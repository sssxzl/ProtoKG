## 3.2 多源协议知识规范化与关联建模

针对第 1 节提出的第一个挑战，本节给出多源异构协议知识的规范化与关联建模方法。该方法的核心思想是：将分散于不同来源、具有不同格式与描述方式的协议知识，统一映射为一种类型化、可溯源、可关联的**知识原子（Knowledge Atom）**，并以每协议封闭配置对知识的合法性进行强约束，最终在知识中枢中形成面向状态协议模糊测试的结构化知识模型。下文依次阐述知识原子的统一表示、类型化取值、认知状态与证据溯源、每协议封闭配置与封闭式校验，以及多源知识的抽取与映射方法。

### 3.2.1 统一知识单元：知识原子

协议知识天然具有结构化特征：方法具有必填头部字段，头部字段具有取值池与语法约束，状态之间由方法触发的转移相互连接，状态码具有特定语义，而漏洞则针对特定的方法与字段。为将这些异构知识统一表示，本文定义知识原子作为知识中枢中的最小知识单元，其形式化表示为六元组：

> （公式 3-1）Atom = ⟨Subject, Aspect, Condition, Value, Epistemic, Evidence⟩

六元组各维度的含义如下：

- **Subject（主体）**：协议知识所描述的对象，如方法（method）、头部字段（header）、状态（state）、状态码（status）、关系（relation）、协议（protocol）与参与者（actor）等。Subject 支持递归嵌套：例如一条状态转移关系可携带 source（源状态）、target（目标状态）与 method（触发方法）三个子主体，从而以结构化方式表达"某状态下由某方法迁移至另一状态"这一动态知识。
- **Aspect（方面）**：主体在某一维度上的属性，如存在性（existence）、语法（syntax）、定义（definition）、取值枚举（value_enum）、安全属性（security_property）、目标状态（target_state）与发生情况（occurrence）等。同一主体可具有多个方面，每个方面对应一条独立知识。
- **Condition（条件）**：知识成立的约束条件。条件采用联合类型表示，涵盖恒真（always）、恒假（never）、未知（unknown）、谓词（predicate）以及逻辑合取、析取与否定等八种情形，用以刻画知识仅在特定条件下成立的情形。
- **Value（取值）**：主体在给定方面下的具体取值，其类型由 3.2.2 节的类型系统约束。
- **Epistemic（认知状态）**：该条知识的认知来源与确定性程度，如规范性必须（must）、规范性未指明（normative_unspecified）、描述性（descriptive）与观测性（observed），并附带权威等级（authority），详见 3.2.3 节。
- **Evidence（证据）**：该条知识的出处与溯源信息，记录来源类型、来源标识、所在文档、定位符（locator）与原文引用（quote），使每条知识均可回溯至其原始出处。

（图 3-2 知识原子六元组结构示意图。插入位置：3.2.1 节末尾。图示内容：一个知识原子及其六个维度，辅以一个状态转移关系的实例——Subject=relation（含 source/target/method 三个嵌套子主体）、Aspect=target_state、Value=具体状态名、Epistemic=must、Evidence=指向 RFC 文档的定位符与原文引用。）

知识原子的身份由内容哈希唯一确定：以（Subject, Aspect, Condition）三元组计算事实标识 fact_id，以（Value, Epistemic）计算声明标识 claim_id，以（来源类型, 来源标识, 定位符）计算证据标识 evidence_id。这一身份机制使得来自不同来源、以不同方式描述的同一知识能够被确定性归并，为 3.2.6 节的多源知识融合提供基础。

### 3.2.2 类型化取值表示

为避免异构知识在取值层面产生歧义，本文为知识原子的 Value 维度定义了一套类型系统，共包含十二种取值类型，如表 3-1 所示。

| 取值类型 | 含义 | 典型协议知识示例 |
| --- | --- | --- |
| scalar | 标量 | 状态码数值 200、端口号 8554 |
| enum | 枚举 | 方法集合 {SETUP, PLAY, TEARDOWN} |
| set | 集合 | 头部字段白名单 |
| sequence | 序列 | 报文中的有序字段序列 |
| range | 区间 | 客户端端口取值范围 |
| pattern | 模式 | 头部字段的正则模式 |
| struct | 结构体 | 由多个子字段构成的复合结构 |
| ref | 引用 | 对另一知识原子的引用 |
| observation | 观测 | 从流量中观测到的实例取值 |
| binary | 二进制 | 原始二进制载荷 |
| union | 联合 | 多种取值类型之并 |
| text | 文本 | 自由文本描述 |

（表 3-1 知识原子的十二种取值类型及说明。插入位置：3.2.2 节。）

取值类型约束了 Value 维度的数据形态。在知识构建与校验过程中，若某知识原子的取值与其声明类型不符，将触发取值类型不匹配错误（ValueTypeMismatchError），从而在源头杜绝类型混乱，保证知识中枢中数据的自洽性。

### 3.2.3 认知状态与证据溯源

不同来源的知识具有不同的确定性程度与可信度。本文以 Epistemic 维度刻画知识的认知状态，共定义四种类型，如表 3-2 所示。

| 认知状态 | 含义 | 典型来源 |
| --- | --- | --- |
| must | 规范性必须遵守的约束 | RFC 规范中的必填字段、强制状态转移 |
| normative_unspecified | 规范性提及但未明确强制 | 规范中可选字段 |
| descriptive | 描述性知识 | 专家标注、漏洞报告、源代码分析 |
| observed | 观测性知识 | 真实流量中观测到的行为 |

（表 3-2 知识原子的四种认知状态及说明。插入位置：3.2.3 节。）

每种认知状态均附带权威等级（authority），用于在 3.2.6 节的多源知识融合中确定知识冲突时的裁定优先级。为满足可追溯性要求，每条知识均携带 Evidence 维度，记录其来源类型（如 RFC、专家知识、真实流量、历史漏洞、源代码）、来源标识、所在文档、定位符（行号、字节偏移、时间戳或字段路径）与原文引用。这一设计使知识中枢中的每一条知识均能回溯至其原始出处，从而保证知识的可信度与可审计性。

### 3.2.4 每协议封闭配置与封闭式校验

为使知识中枢具备协议无关性——即支持新协议时无需修改任何核心代码，本文为每个协议定义一份**封闭配置（Profile）**，其包含三套注册表：

- **主体类型注册表（subject_type_registry）**：登记该协议下所有合法的主体类型；
- **方面注册表（aspect_registry）**：登记该协议下所有合法的方面，并声明每个方面适用的主体类型与取值类型；
- **认知类型注册表（epistemic_type_registry）**：登记该协议下所有合法的认知状态类型。

封闭配置采用**封闭式校验（fail-closed）**策略：知识构建过程中，任何对未注册主体类型、未注册方面或未注册认知类型的引用，均立即抛出硬错误（UnregisteredReferenceError、UnregisteredAspectError、UnregisteredEpistemicError），而非被静默忽略。这一设计将"知识表达的合法性"与"协议实例"解耦：当需要支持一个新协议时，仅需提供该协议的一份 Profile 配置文件，核心代码保持不变。封闭式校验同时能够在知识抽取阶段及时捕获缺漏与不一致，避免错误知识流入下游的种子生成环节。

### 3.2.5 多源知识抽取与映射

在知识原子模型与封闭配置的基础上，本文针对五类异构知识源分别设计了相应的抽取与映射策略，将各类原始知识材料转换为统一的知识原子。五类源及其映射策略如表 3-3 所示。

| 知识源 | 原始形态 | 抽取与映射策略 | 产出知识原子 |
| --- | --- | --- | --- |
| RFC 规范 | 半结构化规范文本 | 分节切片与正则抽取后，将规范条目原生映射 | 方法定义、头部字段、状态转移、状态码语义 |
| 专家知识 | 结构化标注 | 直接映射（无需中间层） | 方法白名单、字段约束、状态转移 |
| 历史漏洞 | 漏洞报告 | 解析触发条件与异常路径 | 漏洞模式、触发序列、边界取值 |
| 真实流量 | 抓包报文 | 按规范身份去重后映射，记录观测次数 | 方法序列、字段分布、状态轨迹 |
| 源代码 | 实现代码 | 静态分析提取定义与位置 | 字段类型、实现细节、定义位置 |

（表 3-3 五类知识源的抽取与映射策略。插入位置：3.2.5 节。）

（图 3-3 五源知识抽取与映射流程示意图。插入位置：3.2.5 节末尾。图示内容：五类知识源各自经对应抽取策略映射为知识原子，汇聚进入知识中枢；不同来源的同一知识经内容哈希归并。）

需要特别指出的是，除上述协议结构知识外，目标服务还存在一类**实例级知识**——即目标服务的资源清单、统一资源定位符结构与部署配置。此类知识不属于协议规范范畴，无法从 RFC 中获取，而蕴含于目标服务的源代码与真实流量之中。以 RTSP 目标服务为例，其可访问的媒体流名称（如 h264ESVideoTest、aacAudioTest 等）由目标服务源码中的注册逻辑定义。本文从源代码中抽取此类实例级知识，作为目标资源清单（target resource inventory）纳入知识中枢。这一设计在后续实验中体现出关键作用：由于变异式模糊测试难以凭空构造新的资源标识符，初始种子的资源覆盖面直接决定了代码覆盖率的可达上限，而完整的目标资源清单能够显著抬升这一上限。

### 3.2.6 知识组织、存储与关联

规范化后的知识原子按来源与协议进行组织与存储：每个来源、每个协议下的知识原子独立落盘为结构化文件，便于检索与增量更新。在存储层面，借助 3.2.1 节的内容哈希身份机制，来自不同来源的同一知识被确定性归并；当同一知识被多个来源以不同方式断言时，依据认知状态的权威等级进行裁定，并记录裁定的依据声明标识，保证融合结果的可追溯性。

在关联层面，本文利用 Subject 的递归嵌套能力与 ref 引用类型，建立消息、字段、约束与状态之间的语义关联：方法通过必填头部字段与字段关联，状态通过方法触发的转移与状态关联，漏洞知识通过目标方法与字段与相应结构知识关联。由此，原本分散、孤立的知识原子被组织为一张以知识原子为节点、以引用与嵌套关系为边的知识图谱，为第 4 章的检索增强与种子生成提供结构化、可导航的知识基础。

（图 3-4 知识中枢三层架构与知识图谱关联示意图。插入位置：3.2 节末尾。图示内容：知识中枢的三层架构——逐源映射层（Layer 2）、每协议封闭配置层（Layer 1）、知识原子层（Layer 0），以及知识原子之间的引用与嵌套关联。）
