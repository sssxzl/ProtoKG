## 一、本次已修复的问题（4 处协议耦合残留）

### 问题 1：`run_seedgen_e2e.py` 漏传 protocol 给 classify 函数 ⭐

- **位置**：`scripts/run_seedgen_e2e.py:79`（`_build_danger_streams` 内 `classify_vuln(v)`）、`:264`（攻击路 `classify_all(vulns)`）
- **表现**：`classify_vuln/classify_all` 上一轮已加 `protocol` 参数，但这两个调用点漏传，走默认 `rtsp` → 换协议时漏洞触发流提取退化 RTSP。
- **修复**：`_build_danger_streams` 加 `protocol` 参数并透传；`:264` 改 `classify_all(vulns, protocol=args.protocol)`。

### 问题 2：`load_resources` 用硬编码 `_CRASH_STREAMS`

- **位置**：`scripts/run_seedgen_e2e.py:32,51`
- **表现**：`load_resources(protocol)` 过滤崩溃流用的是 RTSP 硬编码 `_CRASH_STREAMS`，而 `vuln_pattern` 已把 `crash_streams` 参数化到 profile。换协议时崩溃流过滤失效。
- **修复**：`vuln_pattern.py` 新增公开函数 `crash_streams(protocol)`（从 `_load_vuln_config` 读，缺省回退 RTSP）；`load_resources` 改用它。

### 问题 3：`emit_boundary_fact` 硬编码 protocol="rtsp"

- **位置**：`core/fused/downstream/boundary_probe.py:426`
- **表现**：边界探针回写 `legal_boundary` fact 时，`fact_key.protocol` 恒为 "rtsp"，换协议回写会污染。
- **修复**：`emit_boundary_fact` 加 `protocol: str = "rtsp"` 参数（默认向后兼容），写入 `fact_key.protocol`。

### 问题 4：`_extract_stream_hints` 向后兼容别名无 protocol 且为死代码

- **位置**：`core/fused/vuln_pattern.py:137`
- **表现**：别名无调用点、默认 rtsp，若未来被误用会静默退化 RTSP。
- **修复**：别名加 `protocol` 参数并透传，标注「向后兼容、当前无调用点」。

## 二、建议处理的设计性/轻微问题（未强制修）

### 问题 5：`raw_writers.py` 的路径解析与 `paths.py` 双份

- **位置**：`core/raw_writers.py:292-310`（`_targets_root`/`_load_profile`）
- **表现**：`_targets_root()` 与 `paths.targets_root()` 重复实现（`here.parents[1]/"fused_hub"/"targets"` vs `PROJECT_ROOT/"fused_hub"/"targets"`）；`_load_profile` 与 `paths.target_profile` 并存。功能等价但不统一。
- **影响**：轻微；维护时可能改一处漏一处。
- **建议**：`raw_writers._targets_root` 改复用 `paths.targets_root()`。

### 问题 6：`run_seedgen_e2e.py` 默认输出目录硬编码 rtsp

- **位置**：`scripts/run_seedgen_e2e.py:36`（`DEFAULT_OUT = ROOT/"derived"/"seeds"/"rtsp"`）
- **影响**：不带 `--out` 时换协议会写进 rtsp 目录。
- **建议**：`DEFAULT_OUT` 按 `args.protocol` 动态拼，或去掉默认强制传 `--out`。

### 问题 7：`llm.py` 的 API key 硬编码（安全）

- **位置**：`core/llm.py:48`（`DEEPSEEK_API_KEY = "sk-..."`）
- **影响**：key 随代码走，git 提交/分享会泄露（注释已明确是用户要求，非疏漏）。
- **建议**：改环境变量 `DEEPSEEK_API_KEY`（`DeepSeekClient` 已支持 env > .env > 硬编码的读取链，只需删掉硬编码常量）。

### 问题 8：`chat_json` 的 `response_format=json_object` 与返回类型 `dict|list` 不匹配

- **位置**：`core/llm.py:29`（Protocol 声明 `-> dict | list`）、`:294`（`response_format={"type":"json_object"}`）
- **表现**：`DeepSeekClient.chat_json` 强制 `json_object`，实际只会返回 dict；但 Protocol 声明 `dict|list`。若未来有 prompt 期望数组（list），会被 `json_object` 强制成 object。
- **影响**：当前所有调用方 prompt 都要求返回 JSON object，故无实际影响；属「声明与实际约束不一致」的潜在隐患。
- **建议**：把 Protocol 返回类型收紧为 `dict`，或去掉 `response_format` 让 LLM 自由返回。

### 问题 9：`run_boundary_probe.py` / `source_probe.py` 为 RTSP 专用运行时脚本

- **位置**：`scripts/run_boundary_probe.py`（VM 地址/端口 8560/Session=000022B8/load_vuln_kb(protocol="rtsp")）、`core/fused/source_probe.py`
- **表现**：RTSP 探测/判定逻辑硬编码，换协议失效。
- **影响**：这是「运行时辅助脚本」，RTSP 专用属合理；`source_probe.py` 已加协议耦合注释，`run_boundary_probe.py` 建议同样标注。
