## 二、ABNF 派生字段集（修 C6 —— M1 第一瓶颈）

### 动因

C6（`target_field` 绑到协议已知字段集）是 M1 的**第一瓶颈**（E1 组 32 条 `field_unbound`）。
实测：**LLM 全部给出了字段名**，但字段集缺了它们 ⇒ 真约束被误拒。
SIP 的 `Request-URI`（§8.1.1.1）与 `SIP-Version`（§7.1.1）是 RFC **明确要求**的真头字段
（原文：「applications sending SIP messages MUST include a SIP-Version of "SIP/2.0"」）。

### 实现：`derive_abnf_field_names()`

**双证据**判据（缺一不可）：
- **E2** 该名字是 ABNF **右部引用的** token（被语法**使用**的名字）
- **E3** 该名字在**散文**里被称作 header / field

并排除 RFC 5234 / 5321 的**语法原子**（`ALPHA`/`DIGIT`/`CTL`/`US-ASCII`…）。

★ **不用 ABNF 左部**（定义名）：那些多为语法产物名（`ACKm`/`INVITEm`/`A-d-l`）⇒ 污染且非协议字段。
★ **不扩 `field_sections`**：整章扩会引入 `Vias`/`Clients`/`Servers` 等**章节结构名**。

### ★ 一处**刻意排除**（避免语义错误的规则）

实测把 `Transport` 也加进 sip 字段集可再得 +2 条，但**逐条核对后判定为假阳性**：
SIP RFC 3261 的 §20「Header Fields」共 44 个子节，**并不包含 Transport**
⇒ `Transport` 在 RFC 3261 里是**传输层概念**（§18 Transport 章），不是 HTTP 风格的头字段
⇒ LLM 说「Transport 必须存在」是**语义误解**（原文讲的是「a client must indicate the
transport parameters」）。
⇒ 只采用纯 ABNF 派生（不加 Transport）⇒ **宁可少 2 条，不引入错误规则**。

### 效果

| 协议 | 字段集 | ABNF 派生 | 关键新增 |
|---|---:|---:|---|
| rtsp | 45 → **48** | 7 | Request-URI / RTSP-Version |
| sip | 46 → **54** | 32 | **Request-URI / SIP-Version** |
| smtp | 19 → **20** | 12 | Resent-Reply-To |

## 三、F1 过滤器的**单值 spec_version** 缺口（顺手修）

### 问题（实测发现）

`rfc_config.json` 的 `spec_version` 是**单值**字段，但 smtp 的 kb 里有 **4 个 RFC**
（3207 传输扩展 / 4954 认证 / 5321 传输 / **5322 邮件格式**），
而 SMTP 的**语义约束**（头字段 MUST/SHOULD）出自 **RFC 5322**（邮件格式），不是 5321（传输）
⇒ 原先单值 `"RFC 5321"` 把 4 条 smtp 规则**全部滤掉** ⇒ **smtp 语义规则库恒为 0 条**。

### 修法

`_protocol_spec_versions()` 支持**列表**（`spec_versions` 优先，或 `spec_version` 为列表）；
单值行为**完全不变**（rtsp / sip 不受影响）。
⇒ smtp 配置改为 `spec_versions: ["RFC 5321", "RFC 5322"]`
⇒ **smtp 语义规则库 0 → 4 条**（From / Resent-Date / Reply-To / Resent-Sender）。

## 六、散文 LLM 路线：试点验证 ⇒ **判定不铺开**

### 调研（三类「确定性抽不到」的来源）

| 来源 | 规模 | 结论 |
|---|---|---|
| **ABNF 行** | rtsp 219 / sip 328 / smtp 220 | **100% 可被规则表处理** ⇒ 已作为**字段集来源**用掉（见 §二）|
| **散文句** | 2192 行（三层收窄 + 排除 TOC/标题行后） | 真约束密度低 |
| **ASCII 图** | rtsp 75 / sip 12 / smtp 7 行 | 规模太小，不单独立项 |

### 试点（120 条小样本，1 次 LLM 调用/协议）

- **产出率 3.3%（4/120）** —— 远低于 60% 铺开门槛，也低于 30% 停止门槛。
- 命中的 2 条质量也差：`field='authentication'`（非字段名）、`operand` 是整句话。
- 按 3.3% 外推：覆盖 2192 行需 **19 次调用**，产出约 **73 条候选**，
  经 E1 转换后只剩 **~4 条规则** ⇒ **投入产出比极差**。

### 结论

⇒ **散文 LLM 扩候选句不铺开**；③ 层剩余缺口靠确定性路线
（扩池 + ABNF 字段 + 散文状态机抽取）继续补。
⇒ 保留 `local/LLM使用清单.md` §2 的 L1/L2 标记为待做，供后续重新评估。
