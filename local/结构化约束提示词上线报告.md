## 1. 变更内容

### 1.1 `core/fused/rfc_extractor.py`

- `_PROMPT_CONSTRAINT` **换成本体**：要求 LLM 直接给出 `operator`（10 词受控表）+ `operand`（数组）；
  并**收紧 P 侧引导**（「按你对协议的理解推断」→ 「推断不到留空字符串」）。
- 新增 `CONSTRAINT_PROMPT_VERSION = "rfc-constraint-structured"`
  ⇒ **进 LLM 缓存键**（`sha256(candidate_text + prompt_version + model)`），改提示词必须同步 bump。
- `infer_constraints()`：解析并校验 `operator` / `operand`
  （算子须在 `core.fused.semantic.OPERATORS` 内；有参算子缺 operand ⇒ 整体留空）。
- `extract_constraint_norms()`：`content` 串追加 `operator=` / `operand=`（逗号分隔），
  norm dict 追加 `operator` / `operand` 两个独立字段。

### 1.2 `core/fused/norm.py`

- `_RE_CONSTRAINT_SPLIT` 扩展：切分键增加 `operator` / `operand`。
- 新增 `parse_constraint_operand()`：按逗号切出字符串数组（与 `parse_constraint_content` 同口径）。
- `constraint_norm_to_facts()`：`legal_boundary` fact 的 value 携带 `operator` / `operand`
  ⇒ **下游不必再从中文自由文本反推算子**。

### 1.3 `scripts/exp_semantic_gain.py`

- **删除**实验脚本内的提示词副本与 `monkeypatch` ⇒ 改为直接用 core 的提示词（**单一真源**）。
- `PROMPT_VERSION` 改为从 core 导入（`from core.fused.rfc_extractor import CONSTRAINT_PROMPT_VERSION as PROMPT_VERSION`）。
- 算子获取**改从 norm 层读**（`norm["operator"]` / `norm["operand"]`），
  不再依赖 `llm.last_response` 旁路（该旁路在生产链路里不存在）。
- 字段重命名：`llm_operator` / `llm_operand` → `structured_operator` / `structured_operand`。
- 注释与文档串按**功能**重写（主路径 / 兜底 / 结构化算子），**不含 v1/v2**。

---

## 2. 为什么必须动 core（不能只留实验脚本）

原状态下结构化算子只经由 `llm.last_response` **旁路**取用 —— 该旁路只存在于实验脚本，
生产链路（`build_hub --constraints` → `extract_constraint_norms` → norm → fact）**拿不到算子**。
⇒ 光换提示词会让算子在 norm 层丢失 ⇒ 必须补 norm 通道（本轮 §1.2 所做）。

## 3. 对基线的影响

- 基线种子**不受影响**：基线构建（`tools/qa/ablation/regen_baseline.py`）走
  `build_hub --sources rfc`，**不带 `--constraints`** ⇒ 不走 LLM 约束抽取路径。
- `build_semantic_rules()` 是**零 LLM**（纯规则表）⇒ 语义四库自动重发布的内容不变。
- 实测：`group_E2/*` 产物**逐字节不变**（E2 是零 LLM 路径）；冻结候选集未变（实验只读）。
