## 二、ChatAFL 增强

### 关键发现 1：DeepSeek 模型 reasoning 陷阱
- `deepseek-flash` / `deepseek-v4-pro` 是 reasoning 模型，会把 completion_tokens 全耗在
  `reasoning_content`（思考），导致 `content` 字段为空。
- ChatAFL 的 `chat_with_llm` 只读 `content`，所以增强种子全空（0 字节）。
- **修复**：`llm_proxy.py` 增加 `MODEL_OVERRIDE = "deepseek-chat"`，把请求 model 改写为
  非 reasoning 的 deepseek-chat（作为别名仍可用，返回正常 content）。

### 关键发现 2：afl-fuzz C 代码对 deepseek-chat 的解析 bug
- deepseek-chat 返回的语法模板含 markdown 说明，导致 json-c 断言崩溃。
- ChatAFL 的 `construct_prompt_for_templates` 有 JSON 转义 bug（msg 含换行直接嵌 JSON）。
- kamailio 的 pattern 文件 0 个（extract_message_pattern 解析失败），种子被误判"已有所有类型"跳过增强。
- **最终方案**：放弃 afl-fuzz，改用**手动重建**（`local/chat_afl_enrich.py`），
  忠实复用 ChatAFL 的 prompt 模板、temperature=0.5、max_tokens=2048、C(n,2) 组合逻辑，
  直接用 Python + DeepSeek 走代理复现语法提取 + 增强，绕开 C 代码解析 bug。

### 手动重建脚本 `local/chat_afl_enrich.py` 参数（对齐 chat-llm.c / afl-fuzz.c）
- 语法提取：TEMPLATE_CONSISTENCY_COUNT=5 次 × (templates + remaining) 两次调用
- 增强：MAX_ENRICHMENT_MESSAGE_TYPES=2（每次补 2 个类型，C(n,2) 组合）、
  MAX_ENRICHMENT_CORPUS_SIZE=10、temperature=0.5、max_tokens=2048、ENRICHMENT_RETRIES=5
- 落盘对齐 write_new_seeds（非空 + 与原文不同 + 补 \r\n\r\n）
