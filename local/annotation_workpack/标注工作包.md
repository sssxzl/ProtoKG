# M2 人工标注工作包（117 条待标）

> 生成脚本：`scripts/gen_annotation_workpack.py`（可重复运行，内容确定）

> 标注规范：**`docs/annotation_guide.md`**（判定标准、边界规则、正反例）

> ⚠️ **标注前请完整读一遍指南**，尤其 §2.3 / §3.3 / §4.3 / §5.4 的边界规则。


---


## 一、怎么用这份工作包


### 1.1 标注流程


1. 读 `docs/annotation_guide.md`（判定标准 + 边界规则）。

2. 打开 `待标注模板.json`，逐条填写 4 个判定字段（见 §1.2）。

3. 填完后回填到 `derived/exp_semantic/truth/<协议>.{annotated,holdout}.json`：

   保持条目顺序与 `candidate_id` 不变，把 `pending` 改为 `false`、`annotator` 填你的代号。

4. 校验：`E:/app/Anaconda3/python.exe scripts/annotate_candidates.py validate --annotations <你填的文件> --include <对应的 holdout 文件>`

5. 全部标完后算 κ（需**第二名**独立标注者 B 的文件）：

   `E:/app/Anaconda3/python.exe scripts/calc_cohen_kappa.py --a <A 的文件> --b <B 的文件> --show-disagreements`


### 1.2 每条要填的 4 个字段


- **`has_normative_requirement`** —— 是 / 否（这条候选句本身是否含规范性约束）


- **`modality`** —— MUST / SHOULD / MAY / 无


- **`operator`** —— eq / ne / lt / gt / le / ge / in / present / absent / range / 不可


- **`expected_response_class`** —— success / protocol_error / application_error / silence / null


另有两个可选字段：


- **`uncertain`** —— 拿不准填 `true`（布尔）

- **`uncertain_reason`** —— 拿不准的原因（如「响应类别不可判定」）


### 1.3 三条最容易出错的地方（指南原文摘要）


1. **只看候选句本身**。原文没写规范性动词 ⇒ `has_normative_requirement = 否`。不要凭「这看起来像条约束」来判。

2. **不要从协议常识倒推**。特别是 `expected_response_class`：原文没说违反后会怎样，就填 `null`。

3. **拿不准就标 `uncertain = true`**，不要硬猜。不确定的条目进入仲裁清单，是资产不是负担。
