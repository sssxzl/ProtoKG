# 模型调试诊断报告（LLM 语义规则抽取链路）

## 0. 结论速览

- **链路健康**：DeepSeek 真实调用 `status=200` / 0.92 秒 / 返回合法 JSON；key、网络、客户端、缓存均正常。
- **效果问题不在链路**，在 **LLM 输出契约与下游解析器的口径错配**。
- B-10 实验 M1 负增益（E1 减 C0 = −5.0 个百分点），根因是 **73/120 候选因 `operator_unresolved` 被拒**。

## 1. 链路健康检查

| `.env` | `DEEPSEEK_API_KEY` 已设置（35 字符）、`DEEPSEEK_BASE_URL=https://api.deepseek.com`、`DEEPSEEK_MODEL=deepseek-chat` |

## 2. 调用点

- `core/fused/rfc_extractor.py::infer_transitions(protocol, llm=None)` — 状态机 LLM 抽取，带磁盘缓存（`CACHE_DIR/<协议>.transitions.json`，`block_hash` 失效），无 key 时跳过且不阻断构建。
- `scripts/exp_semantic_gain.py::run_experiment` — C0 / E1 / E2 三组对照，`DeepSeekClient` + `CachedLLM`。
- 候选源：`derived/exp_semantic/candidates_frozen.jsonl`，120 条（rtsp / sip / smtp 各 40）。

## 3. 根因定位

### 3.1 输出契约错配，导致 `operator_unresolved` 73 条（主因）

`rfc-constraint-prompt-v1` 让 LLM 产出的 constraint 结构是：

```
{"field", "constraint", "violation", "expected_code", "expected_behavior"}
```

实测 `llm_cache.jsonl` 里 113 条 constraint **全部没有 `operator` / `operand` 字段**。

而 M1 判定用的 `probe_operator(text)`（`scripts/exp_semantic_gain.py:209`）是用 `PROBE_PATTERNS`
正则从**自由文本**里机械解析 operator 的，这套正则面向 C0 的英文 `legal_boundary`。
把它套到 LLM 的中文自然语言 constraint 上，大量失配。

M7 拒绝原因直方图（E1 组）：

| 原因 | 条数 |
| --- | --- |
| `operator_unresolved` | **73** |
| `non_normative_kind` | 23 |
| `field_unbound` | 6 |
| `optional_modality` | 4 |

结论：这是 **prompt 契约与下游解析器口径不一致**，不是模型能力、不是候选句质量、不是网络或 key 问题。

### 3.2 候选句质量不是主因

- B-13 逻辑句切分已生效：`extract_constraint_candidates` 实测 421 条，非完整句结尾 **12.8%**
  （rtsp 25.0% / sip 8.8% / smtp 10.3%），对比修复前代码注释记载的 91.4% 半句。
- B-10 冻结集 120 条，非完整句结尾 **11.7%**（14 条），实验用的不是半句池。

### 3.3 `known_fields` 里 smtp = 0（独立数据缺陷）

`known_fields` 来自 `known_field_set(protocol)`（`run_experiment` 第 1689 行）：
rtsp 45 / sip 46 / **smtp 0**。smtp 无字段表，规则绑定全部失败，
对应 M1 表现最差：c0=12.5% / e1=2.5% / e2=0%。

### 3.4 已产出的规则质量本身没问题

M3 证据可核对率 100%、M4 显式性纯度 100%、M5 may 误提升 0%。
瓶颈在**产出率**（大量候选被拒），不在规则质量。

### 3.5 M2 硬阻塞（与既有记忆一致）

`derived/exp_semantic/truth/` 共 120 条：已标注 3 条、pending 117 条；标注者仅 A 一人
⇒ Cohen's kappa 无法计算 ⇒ `verdict = 暂不可判定`。需 117 条重标 + 真人标注者 B 到位。

## 4. 可行动修复项（按性价比排序）

1. **prompt v2**：要求 LLM 输出结构化 `operator`（受限词表，与 `PROBE_PATTERNS` /
   `_PARAM_OPERATORS` 对齐）与 `operand`，不再只给自由文本。
   改动 `_PROMPT_CONSTRAINT` 后**必须 bump `PROMPT_VERSION`**（缓存键包含它），否则会读到旧缓存。
2. **补 smtp `known_fields`**：填充 smtp 字段表，消除 0 字段导致的全灭。
3. **扩 operator 归一化**：把 LLM 常用中文算子表述映射到既有 operator 枚举
   （比改 prompt 省调用次数，但要防语义漂移）。
4. **重跑 B-10**：上述任一改动会让 `llm_cache.jsonl` 失效，需约 120 次真实 LLM 调用。
5. **M2 解阻塞**：117 条重标 + 标注者 B，需真人参与，本会话无法完成。
