#### ★ A3 · 正文覆盖台账（评审 05 前半 · P0）

| 项 | 内容 |
|---|---|
| **问题** | 窗口合并有预算（`max_depth=2` / `max_chars=4000`）⇒ ⇒ **超限正文被截断即静默丢失**；且**去重**可能误删「不同语义位置」的重复正文 ⇒ ⇒ 当前**无法回答「正文有没有被漏掉」** |
| **改动点** | ① 在窗口组织层记录「**每个有效正文区间**（行号集合）是否进入过至少一个主窗口」<br>② 单独记账「**被预算截断**的区间」<br>③ 单独记账「**因去重被丢弃**的区间」<br>④ 记账「**零窗口覆盖**的正文行」 |
| **落点** | `core/fused/extraction/rfc_extractor.py`（窗口组织处）＋ `core/fused/extraction/rfc_extractor.py::rfc_quality_report`（出报告） |
| **产物去向** | ★ **不进 fact 空间** ⇒ 写进**构建元数据**（与 `derived/hub/sources.json` 同级的位置，例如 `derived/per_source/<协议>/rfc/coverage.json`）⇒ ⇒ **中枢零影响 / 契约零变化** |
| **对接中枢** | ✔ 不涉及中枢（纯观测） |
| **验收** | ① 对 4 个协议各跑一次 ⇒ 断言「**零覆盖正文行数 = 0**」<br>② 断言「**截断区间数 = 0**」（若非 0 ⇒ 必须有明确标记）<br>③ 断言「元数据里能列出每段的**窗口数**与**覆盖行数**」 |
| **风险** | 低（纯记账，不改抽取行为） |
| **回滚** | 关开关 ⇒ 产物逐字节不变 |

### 批 2 · LLM 补漏升级 + 证据语义验证（评审核心 P0）

---

#### ★ A1 · LLM 补漏粒度：整文 → **窗口级**（评审 01 · P0）

| 项 | 内容 |
|---|---|
| **问题** | 散文语义腿的触发条件是「**该文档一条结构化事实都没抽出**」⇒ ⇒ **混合结构文档**（抽到了一个状态码表，但同篇大量散文规定条件/重试/异常行为）⇒ ⇒ **散文约束全被跳过** ⇒ ⇒ 静默漏抽 |
| **改动点** | ① 触发粒度从「文档」改为「**窗口**」<br>② 窗口命中以下**任一**特征 ⇒ 送 LLM：<br>　 a. 含**规范性关键词**（MUST / MUST NOT / SHALL / SHOULD / MAY / REQUIRED / 禁止 / 不得 / 必须）<br>　 b. 含**条件句式**（if / when / unless / except / in case / 若 / 除非）<br>　 c. 含**异常与错误处理**（error / timeout / retry / failure / 错误 / 超时 / 重试）<br>　 d. 含**跨节引用**（see §X / as defined in §Y / 参见）<br>③ **调用预算与记账**：每批构建记录「**送了几次窗口 / 调了几次 LLM / 产出几条**」⇒ ⇒ **不设硬上限**（D2）但**必须记账** |
| **落点** | `core/fused/extraction/rfc_extractor.py::extract_rfc_norms`（现在的 `_unmatched_files` 收集器 ⇒ 改成「**未覆盖窗口**收集器」）＋ `core/fused/extraction/prose_semantics.py`（新增「按窗口批」入口，保留现有「按文档批」入口） |
| **产物去向** | 复用现有散文语义通道的两种 aspect：<br>· 散文语义 ⇒ **`definition`**（落 `A_structure`）<br>· 散文约束 ⇒ **`legal_boundary`**（落 `C_constraints`）⇒ ⇒ **不新增 aspect** |
| **对接中枢** | ✔ 中枢读端**零改动**（都是已有 aspect 与已有 value 结构） |
| **验收** | ① 造一份**混合结构文档**（同篇含表格 + ABNF + 散文义务「客户端 MUST 在状态 S 收到 M 后执行 A」）⇒ ⇒ 断言该义务**被抽到**（当前必漏）<br>② 对 4 个协议各跑一次 ⇒ 断言「**散文约束条数 > 0**」（当前 rtsp/sip/smtp = 0）<br>③ 断言「**调用次数与产出条数**已记账」 |
| **风险** | ★ **中**（成本显著上升 ⇒ 但 D2 已接受）⇒ ★ **误抽风险**：LLM 可能把「说明性文本」当成规范义务 ⇒ ⇒ 由 A2 的证据语义验证兜底 |
| **回滚** | 关开关 ⇒ 退回「整文零命中」⇒ 产物逐字节不变 |

#### ★ A2 · 证据语义验证：单行 → **跨度 + 语义支持**（评审 04 前半 · P0）

| 项 | 内容 |
|---|---|
| **问题** | 现有反幻觉闸是「**证据行里必须出现实体名**」⇒ ⇒ 但**实体出现在该行 ≠ 该行支持抽取出的结论** ⇒ ⇒ 跨行定义、代词指代、否定词落在别处 ⇒ ⇒ 都会被放行 |
| **改动点** | ① 证据从「**单行**」升级为「**跨度**（起止行）」<br>② 过滤规则升级为**三条同时满足**：<br>　 a. 跨度内**同时出现**主体名 **与** 行为/约束词<br>　 b. **否定词与条件词必须落在跨度内**（否则丢掉极性 ⇒ 只保留正面陈述）<br>　 c. 跨度**不跨越**文档的章节边界（避免把别的章节的句子拼进来）<br>③ 跨度外**再留一行上下文**（供人工核对，不参与判定） |
| **落点** | `core/fused/extraction/prose_semantics.py`（证据构造与过滤处） |
| **产物去向** | 不变（仍是 fact）⇒ ⇒ **证据位置字段更精确**（含起止行）⇒ ⇒ 中枢读端零改动 |
| **对接中枢** | ✔ 不涉及 |
| **验收** | ① 造**反例**（实体名在行内、但结论不由该行支持）⇒ ⇒ 断言**被拒收**<br>② 造**否定/条件跨行**的样本 ⇒ ⇒ 断言**条件被正确保留或正确丢弃**<br>③ 断言「**通过率下降但准确率上升**」（用已抽条目人工过一遍） |
| **风险** | 中（可能**过度过滤**⇒ ⇒ 产出变少）⇒ ⇒ 建议**先只对新通道生效**，旧通道不改 ⇒ ⇒ 便于对比 |
| **回滚** | 关开关 ⇒ 退回单行规则 |

### 批 3 · 文档级治理（评审 02 · P1）

---

#### ★ C1 · 文档登记与规范效力标签（评审 02 · P1）

| 项 | 内容 |
|---|---|
| **问题** | 抽取层直接从 RFC 正文开始 ⇒ ⇒ **不关心**该 RFC 的**状态**（Standards Track / Informational / Experimental）、**Updates / Obsoletes** 关系、**规范性引用**、**勘误** ⇒ ⇒ 「单篇抽取正确」**不等于**「最终知识仍是有效的要求」（例如已被 Obsoletes 的旧版本与现行版本混在一起） |
| **改动点** | ① 在**清洗前**做一次**文档级登记**：从 RFC 头部抽 `编号 / 标题 / 状态 / 日期 / Updates / Obsoletes / 规范性引用`<br>② 抽取时给**每个 claim** 打「**所属文档的效力等级**」标签（`standard` / `informational` / `experimental` / `obsoleted_by_peer`）<br>③ ★ **不做门禁**：**不因为状态是 Informational 或已被 Obsoletes 就拒抽** ⇒ ⇒ 只**标记**，让下游自行过滤 ⇒ ⇒ **避免误伤** |
| **落点** | ① 文档登记：抽取层的**清洗之前**（新增一个轻量步骤，只读 RFC 头部的前 N 行）<br>② 效力标签：claim 的**证据元数据**（不进 aspect） |
| **产物去向** | ★ ① 文档登记 ⇒ 写进 `derived/per_source/<协议>/rfc/documents.json`（**不进 fact 空间**）<br>★ ② 效力标签 ⇒ 作为 claim 的**元数据字段**（**不进 aspect**）⇒ ⇒ **中枢零影响 / 契约零变化** |
| **对接中枢** | ✔ 不涉及中枢（纯元数据）⇒ ⇒ 中枢读端零改动 |
| **验收** | ① 对 4 个协议各跑一次 ⇒ 断言「**文档登记表**里每份文档都有状态字段」<br>② 断言「**每条 claim 都带效力标签**」<br>③ 断言「**fact 总条数不变**」（只加标签不加事实 ⇒ ⇒ 数量必须完全一致） |
| **风险** | 低（纯标记） |
| **回滚** | 关开关 ⇒ 标签不写、登记不产 |

### 批 4 · 规范语义事实模型（评审 03 · P0）★ D1 已定为**方案 ③**

---

#### ★ B1 · 规范语义（主体/强度/极性/条件/例外）挂 `definition`（方案 ③）

| 项 | 内容 |
|---|---|
| **问题** | 现有产出只能表达「**实体是什么**」「**取值范围**」「**状态怎么转**」⇒ ⇒ **表达不了**「主体 + 行为 + 对象 + 规范强度 + 极性 + 生效条件 + 例外」⇒ ⇒ 行为义务与禁止性约束**无载体** |
| **方案 ③ 的具体形态**（D1） | ★ **不扩 `legal_boundary`**、**不新增 aspect** ⇒ ⇒ 规范语义**写成 `definition` 的文本值**，但用**固定的规范化格式**：<br>`[RULE] subject=客户端; action=执行A; object=…; strength=MUST; polarity=必须; condition=处于S且收到M; exception=条件C成立; scope=…`<br>⇒ ⇒ **仍是 text** ⇒ ⇒ **`definition` 的 value_type 不变** ⇒ ⇒ 契约零变化<br>⇒ ⇒ **强度由 `epistemic_type` 承载**（`must` / `normative_unspecified`）⇒ ⇒ 消费端可**按 `epistemic_type` 区分普通定义与规范义务** |
| **落点** | `core/fused/extraction/prose_semantics.py`（产出规范化文本）＋ `core/fused/extraction/norm.py`（`prose_constraint` → `definition` 的映射，当前走 `legal_boundary` ⇒ ⇒ **改挂 `definition`**，或在 `legal_boundary` 不可用时按 D1 改挂） |
| **产物去向** | **`definition`**（落 `A_structure`）⇒ ⇒ **不新增 aspect**、**不改 `legal_boundary` 的 value 结构** |
| **对接中枢** | ✔ 中枢读端零改动（`definition` 已是现有 aspect，value 仍是 text）<br>⇒ ⇒ **消费端若要取结构化字段**，按 `[RULE] ` 前缀 + `key=value;` 解析（**约定写在文档里**） |
| **验收** | ① 造一条「客户端 MUST 在状态 S 收到 M 后执行 A，除非 C 成立」⇒ ⇒ 断言抽出的 `definition` 文本**含 subject/action/strength/polarity/condition/exception 六个要素**<br>② 断言「**`aspect_registry.json` 的 aspect 数量仍 = 21**」<br>③ 断言「**`legal_boundary` 的字段结构未变**」<br>④ 断言「普通定义（无 `[RULE]` 前缀）与规范义务**可区分**」 |
| **风险** | ★ **中**（① `definition` 桶里会**混两种文本** ⇒ ⇒ 消费端需按前缀识别 ⇒ ⇒ 但这是 D1 的已知代价；② 改挂后 `legal_boundary` 的 rfc 侧产出会**变少** ⇒ ⇒ 需检查下游是否依赖） |
| **回滚** | 关开关 ⇒ 退回原映射 |
