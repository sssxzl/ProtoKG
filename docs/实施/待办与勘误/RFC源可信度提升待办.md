## 一、总设计原则

> **新增抽取能力不能以牺牲已有事实的语义正确性为代价。**

⇒ ⇒ 抽取结果明确划分为**三类**，各有明确去向：

| 类别 | 定义 | 去向 |
|---|---|---|
| **已证实事实** | 证据支持**全部**关键语义字段 | ✔ **进入正式知识库**（现有 aspect） |
| **待审候选** | 有一定证据，但关键语义尚未确认 | ★ **不进 fact 空间** ⇒ 写入**候选台账**（元数据）⇒ ⇒ 中枢零影响 |
| **拒收结果** | 无有效证据，或存在明确语义冲突 | ★ 只留**诊断记录**（含拒收原因） |

⇒ ⇒ ★ **规范强度、否定、条件、例外必须原样保留且可核查** ⇒ ⇒ **宁可零产出，不可产出反向语义**（禁止变强制、条件约束变无条件、例外条款被抹除）。

## 二、事实表示契约（**准备阶段冻结**）

### 2.1 规范规则在 `definition` 内的表示

★ `definition` 的 `value_type` 保持 **text**（⇒ aspect 数量与类型面均不变），规则类事实用**带版本的 JSON 文本**承载：

```
[RULE:v1] {"schema_version":1,"kind":"normative_rule",
           "subject":"client","action":"send","object":"message_M",
           "strength":"MUST","polarity":"negative",
           "condition":"before authentication completes",
           "exception":null,"scope":"state_S",
           "evidence":{"file":"rfcXXXX.txt","span":[1234,1236]}}
```

| 字段 | 含义 | 硬要求 |
|---|---|---|
| `strength` | `MUST` / `MUST NOT` / `SHOULD` / `SHOULD NOT` / `MAY` | ★ **必须无损区分**（不依赖 `epistemic_type` 表达） |
| `polarity` | `positive` / `negative` | ★ 否定**不得**被简化掉 |
| `condition` / `exception` / `scope` | 生效条件 / 例外 / 作用域 | ★ **不得**为提高通过率而丢弃 |
| `evidence` | 原文文件 + 行号跨度 | 可回溯 |

⇒ ⇒ **普通定义与规范规则的隔离判据** = 前缀 `[RULE:v1]`（普通定义**无此前缀**）

### 2.2 契约稳定的三条要求

| # | 要求 |
|---|---|
| 1 | **不增加 aspect**，但**明确语义契约可能变化** ⇒ ⇒ 「21 个 aspect 不变」**只是类型面不变**，**不等于兼容性无问题** |
| 2 | **散文约束的最终映射冻结为 `definition`** ⇒ ⇒ **不先落 `legal_boundary` 再迁移** ⇒ ⇒ 消除中间态与重复迁移 |
| 3 | **消费端语义兼容检查**必须列入验收 ⇒ ⇒ 至少覆盖：把规则当普通定义做语义对齐 / 把规则纳入普通定义的比较与消解 / 聚合时误判定义等价于规则 / 消费端读到文本但无法使用结构化字段 |

## 三、抽取引擎的**两级校验**（替代单行证据检查）

### 3.1 A2a · 证据定位检查

| 检查 | 说明 |
|---|---|
| 区间存在且可回溯 | 原文文件与行号跨度必须真实存在 |
| 内容与声明对应 | 证据内容与待验证声明**指向同一件事** |
| 定位方式 | 支持**表格 / 跨行 / 引用关系**等多形态定位 |
| 记录 | 证据跨度的**章节**与上下文 |

### 3.2 A2b · 语义支持检查

| 检查 | 不通过时的处理 |
|---|---|
| 原文是否真正支持**主体 / 动作 / 对象** | 主体或行为无法可靠定位 ⇒ **待审** |
| **规范强度与否定极性**是否一致 | 无法确认 `MUST` / `MUST NOT` ⇒ 标「强度/极性未确认」⇒ **待审** |
| **条件 / 例外 / 作用域**是否被遗漏或篡改 | 否定词作用范围不明确 ⇒ **保留候选，不转换成肯定陈述** |
| 跨章节证据 | 允许多个**独立证据跨度** ⇒ **不简单拼接正文** |
| 全部关键语义被支持 | ⇒ **已证实事实** ⇒ 进入正式知识库 |

⇒ ⇒ ★ **禁止**「因否定/条件未落在跨度内 ⇒ 丢掉极性 ⇒ 保留正面陈述」⇒ ⇒ 证据不足只能**拒收或待审**。

⇒ ⇒ ★ **「主体名与约束词同现」只是定位线索，不足以证明语义成立。**

## 四、覆盖台账：**两本分离**

| 台账 | 回答的问题 | 记录内容 |
|---|---|---|
| **文本覆盖** | 原文是否**到达**了抽取输入？ | 三段映射：<br>**原始输入（行号跨度）** →（清洗 / TOC 隔离，含 `excluded_reason`）→ **清洗后正文** →（窗口归属，含 `truncated_by_budget` / `dropped_by_dedup`）→ **抽取窗口**<br>★ **覆盖率分母 = 原始输入**（否则清洗误删时仍显示 100%） |
| **抽取覆盖** | 哪些知识**尝试抽过**、哪些**仍有候选**？ | 各通道执行情况、产出事实、LLM 触发原因、**拒收原因**、未处理候选 |

⇒ ⇒ ★ **结构化命中 ≠ 知识覆盖完整** ⇒ ⇒ 「某窗口的字段表解析成功」**不能**证明「该窗口里的条件性散文义务已被抽出」⇒ ⇒ 两本台账**不可互相替代**。

## 五、LLM 补漏的触发与去重

### 5.1 触发粒度

| 规则 | 内容 |
|---|---|
| **候选信号** | 规范性关键词 · 条件句式 · 异常/错误处理 · 跨节引用 ⇒ ★ **只是候选信号**，**不是**「存在未抽取知识」的证明 |
| **判定粒度** | ★ **先在段落 / 语义块上判候选**，再组织所需上下文窗口 ⇒ ⇒ **不让边缘词触发整个大窗口** |
| **已知局限** | 不含这些词的规范性散文**仍可能漏抽** ⇒ ⇒ 由「抽取覆盖」台账的**未处理候选**暴露缺口（可见，而非静默） |

### 5.2 去重

| 规则 | 内容 |
|---|---|
| **按证据区间去重** | ★ 以**来源证据区间**为去重键，**不是**窗口 ID ⇒ ⇒ 自底向上合并造成的**重叠窗口**不会重复产出同一事实 |

### 5.3 成本观测（每批构建必须记账）

`LLM 调用次数` · `处理窗口数` · `token` · `耗时` · `候选数` · `确认数` · `拒收数`

⇒ ⇒ ★ **不设硬上限**（已拍板：接受变慢）⇒ ⇒ 但**必须可观测、可调参**。

## 六、缓存与可复现

| 项 | 内容 |
|---|---|
| **缓存键** | 提示版本 ＋ **模型标识** ＋ **推理配置**（温度 / 输出预算）＋ **解析器版本** ＋ **Schema 版本** ＋ **校验器版本** ＋ 输入指纹 |
| **模型快照** | ★ 记录供应商返回的**实际模型版本** ⇒ ⇒ 规避「模型别名指向的底层版本变化」 |
| **两条结论要分开写** | ① **缓存命中时产物可复现**（可保证）<br>② **重新调用同一模型能否再次生成逐字节相同的结果**（**不一定成立**）⇒ ⇒ 文档措辞必须区分，不得把①说成② |

## 七、文档级登记（**只标记，不拦截**）

| 项 | 内容 |
|---|---|
| **登记内容** | 从 RFC 头部抽：编号 / 标题 / **文档自述状态** / 日期 / `Updates` / `Obsoletes` / 规范性引用 |
| ★ **标签语义限定** | ★ 只能标「**该文档自身声明的信息**」⇒ ⇒ **单篇旧 RFC 的头部无法反映后来其他 RFC 对它的更新或废弃**⇒ ⇒ **不得**标「当前生效」 |
| **支持 `unknown`** | 无法从头部判定的 ⇒ 记 `unknown`（**不猜**） |
| **两级信息分开** | ① **文档类别**（如 Standards Track / Informational）<br>② **单条 claim 的规范强度**（`MUST` / `SHOULD` / …）⇒ ⇒ 二者**不可混用** |
| **不门禁** | ★ **不因状态是 Informational 或已被 Obsoletes 就拒抽** ⇒ ⇒ 只**标记**，让下游自行过滤 ⇒ ⇒ 避免误伤 |
| **产物去向** | 文档登记 ⇒ 写 `derived/per_source/<协议>/rfc/documents.json`；效力标签 ⇒ 作为 claim 的**元数据** ⇒ ★ **均不进 fact 空间** ⇒ ⇒ **中枢零影响 / 契约零变化** |

## 八、最小语义回归集（**本轮必须完成**）

> 完整 P/R/F1 评测需要人工标注基准集 ⇒ **另立项**（评测层，不属抽取层）
> ⇒ ⇒ 但**最小语义回归集不能省**（它是 A2b 的验收依据）

| # | 样本类型 | 断言 |
|---|---|---|
| 1 | `MUST NOT` 否定性约束 | **不得**产出正面陈述 |
| 2 | `SHOULD` vs `MAY` | 强度**无损区分** |
| 3 | 条件 / 例外**跨行** | 条件**被保留或被拒收**（不可静默丢失） |
| 4 | 跨章节引用 | 标「跨章证据」或**待审** |
| 5 | 代词指代 | 主体无法定位 ⇒ **待审** |
| 6 | 非规范性示例 | **不产出**规则 |
| 7 | 实体名出现但**不支持结论** | **拒收** |
| 8 | 重叠窗口 / 多通道重复事实 | 按**证据区间**去重 ⇒ 不重复产出 |

⇒ ⇒ 归层：`tests/extraction/`（**抽取层的测试**）⇒ ⇒ 不越界。

## 九、实施批次

| 阶段 | 工作项 | 目标 | 验收重点 |
|---|---|---|---|
| **准备阶段** | ★ **冻结**：规则表示契约 · 散文约束的目标映射 · A2 拒收语义 · 最小回归集 | 冻结事实契约 | ★ 强度 / 极性 / 条件 / 例外**可无损表达** |
| **第一批** | 覆盖台账（文本覆盖 + 抽取覆盖）· 缓存键扩展 | 输入完整性可观测 + 可复现 | 关闭开关时历史产物**逐字节不变**；覆盖缺口**可追踪** |
| **第二批** | LLM 补漏 + 两级校验 ★ **影子模式**（**不正式入库**，只测量） | 测量新抽取效果 | 记录候选 / 误抽 / 拒收 / token / 调用成本 / 重复率 |
| **第三批** | 规则正式发布 ★ **灰度**（逐协议开放） | 把**已验证**规则按约定格式发布 | 定义 / 规则**隔离**；事实 ID 稳定；**下游行为回归** |
| **第四批** | 文档登记与标签 · 集成验收 | 来源可追溯 | 每条新增事实有来源与证据；未核验状态**明确** |

⇒ ⇒ ★ **影子模式**是零风险验证第二批的关键机制：**只产出候选与统计，不进 fact 空间** ⇒ ⇒ 用实测数据决定是否灰度。

⇒ ⇒ **第四批与前面无严格前置依赖**，可并行开发；其**集成验收**放在最后。

## 十、通用验收口径

| # | 项 | 判据 |
|---|---|---|
| 1 | ★ **兼容性** | **开关关闭时，与基线产物逐字节一致**（这是唯一硬性兼容判据） |
| 2 | ★ **开关开启后** | 既有正确事实**不得**发生**未经解释**的回归；新增事实**必须**具备可核验证据；**错误事实不得进入正式产物** |
| 3 | **回归闸** | 护栏本身：新增 **0** / 消失 **0**（★ 这是**回归闸的判据**，**不是事实条数的判据** ⇒ 两件事**分开表述**） |
| 4 | **契约稳定** | aspect 数量 = **21**（不变）＋ **消费端语义兼容检查**通过（见 §2.2） |
| 5 | **正确性** | ★ 不得为了提高通过率**删除否定、条件、例外或规范强度** |
| 6 | **可追溯** | 新增事实能定位原文证据，并能解释其**触发来源**与**验证结果** |
| 7 | **可复现** | 缓存命中、版本指纹、解析配置**可审计**（★ 只承诺「缓存命中可复现」，不承诺「重调同模型逐字节相同」） |
| 8 | **成本观测** | 调用次数 / 窗口数 / token / 耗时 / 候选数 / 确认数 / 拒收数 **齐全** |
| 9 | **回归检查** | 原有正确事实不得无故消失；新增事实不得造成已知下游行为回归 |
| 10 | **失败隔离** | ★ 不确定候选**不得**自动简化后进入正式事实库 |

## 十一、残余风险（**明确未关闭**）

| # | 风险 | 状态 |
|---|---|---|
| 1 | **全链路原子发布 / 失败回滚** | ★ **范围外且未关闭**：抽取层只能保证「闸不通过 ⇒ 不写盘」⇒ ⇒ **不能据此宣称生产发布安全** |
| 2 | **文本→XML/AST 统一文档模型** | 阶段外：当前输入为 TXT |
| 3 | **完整 ABNF 语义**（增量 / 递归 / 重复 / 大小写） | 阶段外 ⇒ 建议：抽到 ABNF 时标注「**语法完整性未知**」（元数据） |
| 4 | **跨节引用解析 / IANA 注册表快照** | 阶段外（依赖外部数据源与网络） |
| 5 | **状态机边的守卫条件 / 动作 / 角色** | 阶段外：`target_state` 现为「目标状态名」文本 ⇒ 扩展会改 value 结构 ⇒ **需单独决策** |
| 6 | **完整 P/R/F1 语义评测** | 另立项（评测层）⇒ ★ 本轮以**最小语义回归集**替代 |
| 7 | **规范时效性** | ★ 本轮只做「文档自述状态」登记 ⇒ **不声称**「当前生效」⇒ ⇒ 时效性仍**未关闭** |

## 十二、待确定的地方

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | 散文约束的**最终映射**冻结为 `definition`（而非先落 `legal_boundary` 再迁移） | ✔ 冻结为 `definition` ⇒ **消除中间态与重复迁移** |
| 2 | 是否引入★ **影子模式**（第二批先不正式入库，只测量） | ✔ 引入 ⇒ 这是**零风险验证**第二批的唯一办法 |
| 3 | **最小语义回归集**（8 类）是否算进本轮 | ✔ **必须算进本轮**（它是 A2b 的验收依据） |
| 4 | 影子模式的**观察期长度**与**灰度门槛**（哪些指标达到才灰度） | 建议：候选→确认率、误抽率、重复率、调用成本四项先**只记账**，跑两轮后再定门槛 |
| 5 | 规则文本里的**条件/例外**用原文片段还是改写 | 建议：**原文片段**（不改写 ⇒ 可核对）⇒ 解析不了就不进正式事实 |
| 6 | `definition` 里规则与普通定义**混装**是否可接受 | 建议：可接受（靠前缀隔离）⇒ 但**必须**在验收里做消费端语义兼容检查 |
| 7 | 是否每批完成后**同步更新《规范源/RFC知识抽取流程.md》** | ✔ 每批完成后同步（它是事实源） |
