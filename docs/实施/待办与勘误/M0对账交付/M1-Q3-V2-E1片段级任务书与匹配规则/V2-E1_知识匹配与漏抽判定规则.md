# V2-E1 · 知识匹配与漏抽判定规则

> ★ 机器侧基线 = **冻结的历史抽取结果**（★ 156 条候选 + 全部 chunk）
> ★ ★ **本轮不重新调用 LLM、不重新生成候选来填补漏抽**

---

## 一、★ 两层匹配

### 1.1 第一层：来源与证据定位（★ 必要条件）

| # | 检查 | ★ 通过标准 |
|---|---|---|
| ① | ★ RFC 文档相同 | ★ `document` 与 `rfc_sha256` 均一致 |
| ② | ★ 原文跨度重叠 | ★ 候选的 `evidence_span` 与人工知识的 `evidence_span` **行区间有交集** |
| ③ | ★ 同一完整规范句 | ★ 落在同一句界内（★ 用生产的 `_logical_line` + `_sentences_in` 判定） |
| ④ | ★ 跨句 / 跨节引用 | ★ 若人工知识声明跨句/跨节 ⇒ ★ 须在**同一文档**内找到引用来源；★ **跨文档引用不视为匹配** |
| ⑤ | ★ 同一知识对象 | ★ 主体 + 动作 + 对象三者**指向同一对象**（★ 可含代词解析后的实体） |

★ ⇒ ★★ **★ 不能仅靠 chunk_id 相同或字符串相似就确认匹配**

### 1.2 第二层：语义命题匹配（★ 决定匹配等级）

| # | 检查 | ★ 说明 |
|---|---|---|
| ① | 知识类型 | ★ 人工 `knowledge_type` vs 候选的抽取类型 |
| ② | 主体 | ★ 规范化后（★ 指代解析 + 大小写 + 同义归一） |
| ③ | 动作 | ★ 词形等价 + 动词同义 |
| ④ | 对象 | ★ 词形等价 + 子串/超集判定 |
| ⑤ | 强度 | ★ **SHALL≡MUST**（RFC 8174）、REQUIRED≡MUST、RECOMMENDED≡SHOULD |
| ⑥ | 极性 | ★ positive / negative（★ **与强度组合判定**：MUST+negative≡MUST NOT） |
| ⑦ | 条件与例外 | ★ 跨句继承须解析；★ 无条件义务 vs 有条件义务**不可等价** |
| ⑧ | 适用范围 | ★ 适用对象/章节范围 |

## 二、★ 匹配结果（五态，★ 互斥）

| 结果 | ★ 定义 | ★ 判定 |
|---|---|---|
| ★ `full_match` | ★ 原文关键知识**完整保留** | ★ 主体/动作/对象/强度/极性/条件**全部**对应且无错 |
| ★ `partial_match` | ★ 存在对应候选，★ 但**关键字段不完整** | ★ 主体/动作/对象/强度/极性/条件中**至少一项缺失或表述不完整**，★ 但命题本身对应 |
| ★ `semantic_mismatch` | ★ 找到相关候选，★ 但**关键语义错误** | ★ 命题对应但主体/动作/对象/强度/极性**有实质错误** |
| ★ `unmatched` | ★ 未发现对应候选 | ★ 在**冻结的完整候选集合**（★ 156 条 + 全部 chunk）中检索无对应 |
| ★ `uncertain` | ★ 证据不足或匹配存在歧义 | ★ 匹配边界不清 / 需人工仲裁 |

★ ⇒ ★★ **★ 同一候选不得因重复匹配而多次计算为成功抽取**

---

## 三、★ 一对多 / 多对一

| 情形 | ★ 处理 |
|---|---|
| ★ **一对多**（★ 一条候选对应多条人工知识） | ★ 候选**不得**被计为多次成功；★ 记 `partial_match`（★ 候选只覆盖部分知识），★ 多个未覆盖知识记 `unmatched` |
| ★ **多对一**（★ 多条候选对应一条人工知识） | ★ 取**最完整**的一条为 `full_match`；★ 其余记 `partial_match`；★ ★ **★ 须记录该知识被多条候选重复覆盖（★ 属冗余抽取）** |
| ★ **匹配争议** | ★ ★ **交人工仲裁**，★ 不得由程序单方裁定 |

## 四、★ ★ 关键：跨 chunk 检索（★ 不得只看当前片段所属 chunk）

★ ★ **★ 片段所在 chunk 没有候选，★ 不一定代表相同知识没在其他 chunk 被抽取**
⇒ ⇒ ★ **★ 必须在【冻结的完整候选集合】中检索语义等价知识**
⇒ ⇒ ★ 检索范围：★ **156 条候选的全部 chunk**（★ 不限当前片段所在 chunk）
⇒ ⇒ ★ 匹配程序输入：★ 人工 `gold_knowledge` ＋ 冻结候选集 ＋ 冻结 chunk 集合

## 五、★ 漏抽判定（★ ★ 三段式，★ 不得简化）

★ **★ 「没有生成候选」≠「漏抽了一条规范知识」** ⇒ ★ 漏抽判定必须走完三段：

```
① 片段内**是否存在**人工认定的目标知识？
   └─ 否 ⇒ ★ **不是漏抽**（★ 记「片段无目标知识」）
   └─ 是 ⇒ ↓
② 该知识在**冻结候选集合**中是否已有对应（★ 按两层匹配规则）？
   └─ 是 ⇒ ★ **不是漏抽**（★ 记 matched / partial / mismatch）
   └─ 否 ⇒ ↓
③ 该知识属于哪一类遗漏？
   ├─ **触发遗漏**：★ 原文段落未进入任何抽取 chunk（★ 覆盖问题）
   ├─ **切块遗漏**：★ 段落进入 chunk 但被切分边界截断
   ├─ **证据定位遗漏**：★ 段落进入 chunk 但证据跨度未覆盖该知识
   └─ **结构化抽取遗漏**：★ 段落进入 chunk 且证据覆盖，★ 但未产出对应候选
```

★ ⇒ ★★ **★ 只有走完 ①②③ 才可记为「漏抽」；★ 且必须标注遗漏阶段**
★ ⇒ ★★ **★ 「片段无目标知识」与「有目标知识但未抽取」必须分开统计**
