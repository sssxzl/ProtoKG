## 二、★ 人工任务：先判断「这个片段里有哪些知识」

★ 允许同一片段包含**零条、一条或多条**独立知识。

### 2.1 ★ 允许的三种「非知识」状态（★ **三者不可互相替代**）

| 状态 | ★ 何时使用 |
|---|---|
| ★ `no_target_knowledge` | ★ 片段中**确实没有**目标类型知识（★ 如纯语法、纯描述、纯目录） |
| ★ `uncertain` | ★ **无法确定**是否含目标知识（★ 上下文不足、引用不清、判读有歧义） |
| ★ `not_applicable` | ★ 片段内容**不适用于**本次评估目标（★ 如明显是版权声明、重复片段） |

★ ⇒ ★ **不得**用 `uncertain` 代替 `no_target_knowledge`（★ 前者是「看不清」，★ 后者是「看清了没有」）
★ ⇒ ★ **不得**用 `not_applicable` 代替 `uncertain`（★ 前者是「不评」，★ 后者是「评不了」）

### 2.2 ★ 每条知识记录 13 项

| # | 项 | ★ 说明 |
|---|---|---|
| 1 | ★ **知识类型** | ★ 六类：★ `normative_rule_candidate` / `protocol_descriptive_semantics` / `protocol_syntax` / `protocol_registry_or_enumeration` / `non_protocol_metadata` / `mixed_or_uncertain` |
| 2 | ★ **原文证据跨度** | ★ 该知识的行号范围（★ 可多行） |
| 3 | ★ **是否为协议规范义务** | ★ 是 / 否 / 不确定 |
| 4 | ★ **规范主体** | ★ **指代须写出解析后的实际承担者**（★ 如「This field」→「CSeq」） |
| 5 | ★ **动作** | ★ 行为动词 |
| 6 | ★ **对象** | ★ 行为对象（★ 跨行须完整） |
| 7 | ★ **规范强度** | ★ MUST / SHALL / SHOULD / MAY / REQUIRED / RECOMMENDED / ★ **`unknown`** |
| 8 | ★ **极性** | ★ positive / negative（★ SHOULD NOT ⇒ strength=SHOULD **且** polarity=negative） |
| 9 | ★ **条件** | ★ 原文中的条件（★ 跨句继承须写明继承自哪句）；★ 无则 `null` |
| 10 | ★ **例外** | ★ 原文中的例外；★ 无则 `null` |
| 11 | ★ **是否需要跨句或跨节证据** | ★ 否 / 跨句 / 跨节 / 引用外部章节 |
| 12 | ★ **证据支持程度** | ★ `supported` / `partially_supported` / `contradicted` / `evidence_insufficient` |
| 13 | ★ **审核理由及不确定性** | ★ 必填（★ 写清依据原文哪一行、★ 为什么这样判、★ 哪里不确定） |

### 2.3 ★ 三条硬规则

| # | 规则 |
|---|---|
| ① | ★ ★ **原文没有明确给出的规范强度，不允许自动写为 MUST** ⇒ ★ 写 `unknown` |
| ② | ★ ★ **SHOULD NOT 等表达要保留强度与极性的正确组合**（★ strength=SHOULD **且** polarity=negative）⇒ ★ **不得**写成 MUST NOT，也不得丢掉 NOT |
| ③ | ★ ★ **陈述式规范要求**（★ 无 BCP14 关键词但有规范效力）**允许且应当被标注**；★ ★ **必须写明其原文依据**（★ 哪一句、★ 哪个主体、★ 哪个条件） |

### 2.4 ★ 跨句 / 跨节义务

★ 记录**直接规范证据**与**补充引用证据**两部分
★ ⇒ ★ ★ **不得**把被引用章节中的**无关内容**当作证明
★ ⇒ ★ ★ **不得**因为「引用章节里没有明确 MUST」就判定该义务不存在

| # | 约定 |
|---|---|

| 6 | ★ 项目方对**不可编辑字段**（★ 片段原文、哈希、章节路径、行号）逐单元格比较，★ 任何差异即中止 |

## 四、★ 仲裁契约（★ 第三方）

| ★ 仲裁范围 | ★ 说明 |
|---|---|
| ★ 知识存在性分歧 | ★ 一方判有、另一方判无 |
| ★ 知识类型分歧 | ★ 六类之间 |
| ★ 规范效力分歧 | ★ 是否构成协议规范义务 |
| ★ 关键语义字段分歧 | ★ 主体 / 动作 / 对象 / 强度 / 极性 / 条件 / 例外 |
| ★ 原文证据支持分歧 | ★ `supported` vs `partially_supported` vs `contradicted` |
| ★ 一对多 / 多对一匹配争议 | ★ 见《知识匹配与漏抽判定规则》 |

★ ★ 仲裁必须记录：★ **匿名审核者 ID**、★ **审核日期**、★ **仲裁理由**
★ ⇒ ★ **无法解决的分歧保留 `unresolved`，★ 不得强制形成确定真值**
