# V2-E1 · 原子知识切分规范

> ★ 目标：★ **人工真值单位 = 可独立判断语义支持的知识命题**，★ 而不只是「某一行文本」

---

## 一、★ 切分原则

### 1.1 ★ 应当切分（★ 多个独立命题）

| 情形 | ★ 例 |
|---|---|
| ★ 同一段落有**多个独立主体** | ★ 「Server MUST … Client SHOULD …」⇒ ★ 两条知识 |
| ★ 同一段落有**多个独立动作** | ★ 「A MUST send B **and** A MUST receive C」⇒ ★ 两条 |
| ★ 同一段落有**互不相干的适用条件** | ★ 「对 X 适用 P；对 Y 适用 Q」⇒ ★ 两条 |

### 1.2 ★ 不得切碎（★ 不可分割的关系）

| 情形 | ★ 处理 |
|---|---|
| ★ 条件 + 义务不可分 | ★ **同一条知识**，★ 条件作为该知识的 `condition` 字段 |
| ★ 例外与主体不可分 | ★ **同一条**，★ 例外作为 `exception` 字段 |
| ★ 跨句的**同一义务** | ★ **一条知识**，★ 证据跨度覆盖多句（★ 记多证据关系） |
| ★ 引用外部章节支撑的义务 | ★ **一条知识**，★ 分别记录直接证据与补充引用证据 |

★ ⇒ ★ ★ **不得为了提高知识数量而把不可分割的条件/例外/主体关系切碎**

---

## 二、★ 真值链（★ 必须可追溯）

```
snippet_id → gold_knowledge_id → evidence_span → (协议 / 文档 / 行号 / 哈希)
```
★ 每条人工知识都能**追溯到原始 RFC 的具体行**
★ ⇒ ★ **★ 禁止**只保留「片段级标签」而丢失知识级粒度

---

## 三、★ 粒度一致性约定

| 约定 | ★ 说明 |
|---|---|
| ★ **一个候选 ≈ 一条知识** | ★ 抽取候选本就应对应一个原子规范命题；★ 若候选本身含多个命题 ⇒ ★ 属**候选粒度问题**，★ 人工应拆为多条并记录 |
| ★ **一个片段 ⇒ 零到多条知识** | ★ 片段是**采样单位**，★ 知识是**真值单位**；★ 二者不得混用 |
| ★ **零知识的片段要显式记录** | ★ 用 `no_target_knowledge` / `uncertain` / `not_applicable` 三态之一（★ 不可互换） |

⇒ ⇒ ★★ **★ 指标分母必须用「知识级」而非「片段级」；★ 片段级只用于漏抽率的分母**
