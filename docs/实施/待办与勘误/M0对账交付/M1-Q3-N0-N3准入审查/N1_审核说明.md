## 一、★ ★ 盲审者要做什么（★ 只做独立语义判断）

### 1.1 ★ `truth_label` 的定义（★ **完全独立于模型状态**）

> ★ **`truth_label` = 「这段原文是否构成该候选所声称的规范义务」的独立语义真值。**
> ★ ★ **不要**考虑「模型认为对不对」「之前判成什么」「应当确认还是拒绝」
> ★ ★ **也不要**去判断 `false_confirmation` / `false_rejection`（★ 那两个由汇总脚本自动生成）

| 取值 | 判定标准 |
|---|---|
| `valid_confirmed` | ★ 原文**确实**构成该候选声称的规范义务，★ 且主体/动作/对象/强度/极性**都被原文支持** |
| `valid_rejection` | ★ 原文**不**构成该规范义务（★ 属描述性知识 / 字段与原文不符 / 原文根本没这条要求） |
| `pending_insufficient_evidence` | ★ 原文证据不足，★ 无法判定 |
| `uncertain_requires_human` | ★ 你本人也无法确定 ⇒ ★ 需仲裁 |

### 1.2 十项标注

| # | 列 | 说明 |
|---|---|---|
| 1-7 | `★ A:subject` / `action` / `object` / `strength` / `polarity` / `condition` / `exception` | ★ 主体（含**指代解析后的实际承担者**）/ 动作 / 对象 / 强度 / 极性 / 条件 / 例外<br>★ `condition` / `exception` 无则填 `null`；★ ★ **`condition` 不得填整条 constraint** |
| 8 | `★ A:evidence_support` | ★ **原文支持程度**：`supported` / `partially_supported` / `contradicted` / `evidence_insufficient` |
| 9 | `★ A:truth_label` | ★ 独立语义真值（★ 见 1.1） |
| 10 | `★ A:review_note` | ★ **独立审核理由**（★ 写清依据的原文行/短语） |

★ ★ **无法判断时**：`evidence_support=evidence_insufficient` ＋ `truth_label=pending_insufficient_evidence` ＋ 备注写明缺什么证据
★ ★ **允许并鼓励 evidence_insufficient**：★ 大量落在此值 ⇒ 说明**候选本身缺少必要字段证据**（★ 而非审核者不努力）

## 二、★ 证据列怎么读

| 列 | 含义 |
|---|---|
| `★ raw_span` / `★ resolved_span` / `★ span_mode` | ★ 按 M1-Q2 契约解析的锚点（★ `absolute` / `relative`） |
| `★ 锚点行原文（★ 合法可为空）` | ★ 锚点行原文（★ **可能为空**，★ 合法） |
| `★ 锚点行是否空白` | ★ 显式标记 |
| ★ `★ 证据句（含 entity 的非空行）` | ★ **±3 内含 entity 的非空行**（★ 锚点空白时的证据载体） |
| `★ RFC 原文上下文（锚点 ±6 行）` | ★ 同版本 RFC 原文（★ 判断用这个） |
| `★ entity / normative_subject / action / object / strength`（LLM 候选） | ★ **模型产出的字段**（★ 待你核对，不是真值） |
| `★ LLM meaning` / `★ LLM constraint` | ★ **生成文本，★ 不是 RFC 原文**（★ 勿当作原文引用） |
| `★ 推导 polarity` | ★ 由 strength 推导（★ 供核对） |
