## 二、★ 检查②：`truth_label` 与模型状态解耦

### 2.1 ★ 定义（★ 已写入 `N1_审核说明.md`）

> ★ **`truth_label` = 「这段原文是否构成该候选所声称的规范义务」的独立语义真值。**
> ★ **不考虑**模型认为对不对 / 之前判成什么 / 应当确认还是拒绝
> ★ **不判断** `false_confirmation` / `false_rejection`

| 取值 | 判定标准 |
|---|---|
| `valid_confirmed` | ★ 原文确实构成该规范义务，★ 且主体/动作/对象/强度/极性**都被原文支持** |
| `valid_rejection` | ★ 原文**不**构成该规范义务（★ 描述性知识 / 字段不符 / 原文无此要求） |
| `pending_insufficient_evidence` | ★ 原文证据不足 |
| `uncertain_requires_human` | ★ 审核者本人也无法确定 ⇒ 需仲裁 |

### 2.2 ★ 模型相对标签的生成时机与方式

★ **盲审阶段**：★ 脚本**不读**模型状态文件 ⇒ ★ **混淆矩阵不计算**
★ **冻结后**：★ 脚本读取隐藏的模型状态 ⇒ ★ **自动派生**

```
模型=confirmed + 人工=valid_rejection/pending ⇒ false_confirmation
模型=confirmed + 人工=valid_confirmed         ⇒ valid_confirmed
模型=rejected  + 人工=valid_confirmed         ⇒ false_rejection
模型=rejected  + 人工=valid_rejection         ⇒ valid_rejection
```

★ ★ **实测验证**：★ 用**未标注的真实空表**运行 ⇒ ★ 混淆矩阵为空、★ 精确率/误确认率/误拒收率**全部 `N/A`**
（★ 模型状态文件路径给错时同样**拒绝输出**）⇒ ⇒ ★ **保护机制确实生效**
