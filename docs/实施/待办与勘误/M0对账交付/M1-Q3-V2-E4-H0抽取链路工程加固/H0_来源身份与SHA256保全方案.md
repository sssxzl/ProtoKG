# H0 · 来源身份与 SHA256 保全方案

> ★ 影子实现：`guard/_out/_n1c_v2/h0/source_contract.py`（★ **不改生产**）

---

## 一、★ 契约

```
source_reference ──normalize──► normalized_document_id ──resolve──► source_file ──hash──► source_sha256
```

★ ★ **原始 `source_reference` 永远保留，★ 不覆盖**

---

## 二、★ 六条硬要求的落实

| # | 要求 | ★ 实现 |
|---|---|---|
| ① | ★ 保留原始 source_reference | ✔ `normalize_document_id()` 返回 `source_reference` 原值 |
| ② | ★ 规范化结果**可复算** | ✔ **纯函数**（★ 不访问文件系统）⇒ ★ 同输入同输出 |
| ③ | ★ **不允许模糊文件名匹配** | ✔ 只做**精确名**查找；★ 同名出现在多协议 ⇒ **ambiguous**（★ **绝不任选一个**） |
| ④ | ★ 找不到 ⇒ 记 unresolved，★ **不假造 SHA256** | ✔ `status=unresolved` 且 `source_sha256=None` |
| ⑤ | ★ **不允许越界路径或任意文件访问** | ✔ `_is_inside()`（★ resolve 后校验必须位于 `kb_root` 内）；★ `..` 越界段被丢弃并记 notes |
| ⑥ | ★ 原始证据与来源文档版本绑定 | ✔ 每次解析同时产出 `source_sha256` |

---

## 三、★ 处理的六类来源

| 情形 | ★ 处理 |
|---|---|
| ★ 普通文档名 `rfc3261.txt` | ✔ 逐协议**精确名**查找 |
| ★ `file:` 前缀 `file:rfc3261.txt#@130` | ✔ 去前缀后同上（★ **这正是此前 `source_sha256=None` 的根因**） |
| ★ 相对路径 / 绝对路径 | ✔ 词法规范化；★ 绝对路径相对化并记 notes |
| ★ 含空格或特殊字符 | ✔ **原样保留**（★ 不做模糊处理） |
| ★ URI 百分号编码 | ✔ `unquote()` 并记 notes |
| ★ 不合法 / 无法定位 | ✔ `unresolved` / `ambiguous`（★ **不假造哈希**） |
