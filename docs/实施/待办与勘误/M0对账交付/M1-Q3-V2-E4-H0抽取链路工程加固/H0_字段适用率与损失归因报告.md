## 二、★ 四类失败**必须分开**（★ 本报告的核心）

| 失败类型 | ★ 判据 | ★ 本报告中的计数 |
|---|---|---|
| ★ **① 字段不存在（Schema 未要求）** | ★ 该字段不在 LLM Schema 中 | ★ `not_requested` |
| ★ **② 字段为空（Schema 要求但未产出）** | ★ 在 Schema 中但本次为空 | ★ `not_requested`（★ 本实现中 LLM 层为空） |
| ★ **③ 字段不适用（该知识类型不需要）** | ★ 派生层无该字段且该类型无需 | ★ `not_applicable` / `intentionally_omitted` |
| ★ **④ 字段抽错（LLM 产出但内容错）** | ★ 有值但语义错误 | ★ ★ **★ 本轮【无法判定】**（★ 缺可信人工真值） |

⇒ ⇒ ★★ **★ 绝不可把①②③④合并为同一个「字段缺失率」**

## 三、★★ 关键结论

### 3.1 「字段完整性低」的两个**独立**来源（★ 必须分开归因）

| 来源 | ★ 证据 | ★ 责任层 |
|---|---|---|
| ★ **① LLM 层本身不总产出结构化字段** | ★ ② 覆盖率：action/object/strength/polarity ≈ 0.19、normative_subject ≈ 0.13、condition ≈ 0.09、exception = 0 | ★ **Prompt / Schema 层** |
| ★ **② 派生层把 LLM 已产出的字段【丢弃】** | ★ ③ 保留率：normative_subject/action/object/strength/polarity/condition/cross_ref_status **全部 = 0**（★ 而 ② > 0） | ★ **派生层输出契约** |

⇒ ⇒ ★★★ **★ ⇒ 提升字段完整性必须同时改【Prompt/Schema 层】与【派生层输出契约】，★ 改一处不够**

### 3.2 ★ ② 覆盖率本身还被**留痕缺失**压低

★ H2 的缓存只剩 **1 条** raw item（★ 被后续批次覆盖）⇒ ★ 拉低了整体 ② 覆盖率
⇒ ⇒ ★★★ **★ ⇒ ② 覆盖率【不是】纯模型能力指标；★ 必须与「留痕完整度」一起读**
