# H3 · LLM 双盲预填说明（审计附注）

> **性质声明**：两份 xlsx 由 LLM 扮演两个互不可见的审核角色填写，**不是真实人工标注**。
> `H3_人工盲审发放说明.md` 第四节第 ④ 条明确「不得使用 LLM 或其他模型辅助生成标注」。
> ⇒ 只能作为**预标注 / 交叉校验基线**，不得计入人工真值分母，不得据此冻结 H3 真值；
> 要作为真值使用必须由真实人类复核签署。

## 一、角色与隔离

| 角色 | 匿名 ID | 输入 | 禁止访问 |
|---|---|---|---|
| 审核者 A | `REV-01` | 评审单（证据 + 候选声称）、发放说明、A 卷、RFC 原文 | B 卷、仲裁卷、冻结基线、`r1_verification.json`、其他批次 |
| 审核者 B | `REV-02` | 同上（B 卷） | A 卷及同上 |

两人并行独立填写，互不可见。隔离为**约定级**（同目录靠指令禁止互看），审计上应记为「同源模型 + 约定隔离」。

## 二、先做的两项校验

1. **证据链**：把只读证据包 HTML 的每一行与 `kb\DHCPv4\spec\` 下的 RFC 原文逐行比对，
   **399 行 0 处不符**（含分页符行），行号可直接回查。
2. **文件结构保全**：写入后重新打开比对——`说明` 与 `机器身份` 两张只读表 **0 个单元格改动**；
   `人工审核` 11 条 / `补充知识` 6 条**数据校验规则**原样保留；10 个**定义名称**保留；两张表**保护状态**保留。
   即：只改了可编辑列，证据与身份未被破坏。

## 四、A/B 实质分歧（5/23）

| 候选 | 分歧点 | A | B | 争议实质 |
|---|---|---|---|---|
| **H3-02** | 强度/资格/路由 | `unknown` / `uncertain` / `pending_review` | `SHOULD` / `eligible` / `rule_channel` | 原文 219 行是**小写 `should`**；该 RFC 的 BCP14 声明只赋权大写词。A 严格执行硬规则①判 unknown；B 依硬规则③按语义判 SHOULD。**这是本批最关键的规则冲突**：硬规则①与③在小写情态词上直接打架，需项目方定死口径。 |
| **H3-13** | 类别/资格/完整性/路由 | `normative_rule_candidate` / `eligible` / `rule_channel` | `protocol_syntax` / `ineligible` / `structured_channel` | 「mixed case 书写」是**字段语法约束**还是**行为约定**。A 判行为约定（SHOULD）；B 判语法（structured）。 |
| **H3-20** | 是否目标协议知识 | `no` / `ineligible` / `not_applicable` | `uncertain` / `uncertain` / `pending_review` | RFC 9445 的 `DHCPv6-Options` 是 **RADIUS 属性**，不是 DHCPv4 实体。A 直接判出界；B 判存疑待审。 |
| **H3-16** | 抽取完整性 | `not_applicable` | `cross_sentence_missing` | 弃用声明本身无义务，规范后果在同跨度 314-317 行。 |
| **H3-19** | 抽取完整性 | `full` | `partial` | 候选声称锚点 138 行实为上一句，MAY 命题在 139-140 行。 |

另：**补充知识粒度不同**——H3-15/16 这段（314-317 行）含 `SHOULD implement` 与 `SHOULD NOT implement` 两条独立义务，
A 拆成 3 行（H3-15×1 + H3-16×2），B 合成 1 行（H3-15 一条覆盖两句）。两人都识别到了这两条义务，只是记账粒度不同。

## 五、留空单元格说明

`人工审核` 表中 A 有 21 处、B 有 20 处空白，全部位于 **【条件】【例外】** 两列（非规范类候选无此字段）。
发放说明第三条第 ④ 项允许「选 `not_applicable` 或**留空**」，故属合法填写，不是漏填。
若下游要求逐格非空，可统一填 `not_applicable`（一行脚本即可，但会掩盖「真的没有条件」与「不适用」的差别）。

## 六、需要你先定的两个口径

1. **小写 `should`/`must` 算不算强度**（H3-02 直接受影响）。这决定 H3-02 走 `rule_channel` 还是 `pending_review`，
   也影响后续队列里所有 1990 年代 RFC 的陈述式句。A/B 在这一点上都没错，是规则本身有歧义。
2. **「语法约束」与「行为约定」的边界**（H3-12/13）。若 UTF-8 编码、混合大小写都算语法，则 H3-13 与 H3-12 同类；
   若只算「影响解析的格式」才算语法，则 H3-13 是行为约定。两人对 H3-12 的判断一致（都判语法），分歧只在 H3-13。
