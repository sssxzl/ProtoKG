## 二、5 字符差额的原因

上一版报「块字符合计 18 674，原文 18 679，差 5」。实测：

```
len("\n".join(blocks)) == len(text) == 18 679   → 差额 0
```

5 是**块之间的换行分隔符个数**（6 块 5 个 `\n`）：`sum(len(block))` 不含分隔符，所以少了 5。原文没有任何缺失，覆盖率 100%。

## 三、切块是否被静默截断

`_split_blocks(text, max_blocks)` 达到 `max_blocks` 就返回。T0-A 取 `max_blocks = len(text)//3500 + 1 = 6`，恰好切满；若取 5，会静默丢掉尾部约 955 字符。

预检已把这条写成硬检查：`recon_chars == chars`，不相等即拒绝出清单。

## 五、缓存完成条件

两批全部成功前，文档不得标 `complete=true`。依据：`_extract_blocks` 尾部比较 `_doc_done` 与 `_doc_expect`，任一批未处理即置该文档失败、不落缓存；对应测试为 `f2_checks_v3` 的「先成功后失败 ⇒ 不得标成功」。
