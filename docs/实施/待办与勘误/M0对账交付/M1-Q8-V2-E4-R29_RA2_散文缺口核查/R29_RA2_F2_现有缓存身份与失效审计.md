# R29 RA-2 F2 现有缓存身份与失效审计

## 一、当前缓存的身份单位

| 问题 | 答案 | 依据 |
|---|---|---|
| 身份单位 | **批次**（一批块拼一个 hash），不是文档、不是 Chunk | `prose_semantics.py:888-891` |
| 同一批次不同 RFC 如何关联 | 同一文件同一 `items` 数组，靠条目里的 `doc` 字段区分 | `_payload["items"]` |
| 单份 RFC 更新是否只失效自己 | **否**：`block_hash` 由整批块拼接，任一文档变动 ⇒ 整批 key 变 | 同上 |
| 输入顺序是否影响身份 | **是**：拼接顺序进 hash | `"|".join(...)` |
| Prompt/模型/Schema/参数变化是否失效 | 是（key 含 prompt_version、prompt_digest、model、温度、max_tokens、parser/schema/verifier 版本） | `cache_key()` |
| 是否记录来源 RFC 与 SHA256 | 否。条目只有 `doc` 文件名，无 sha；文件级 `key_manifest` 只有模型与版本 | `key_manifest()` |
| 完成状态是否整批 | 是，单字段 `complete` | 619 行 |
| 部分失败是否污染已完成结果 | 会写 `complete=False` 的半成品；下次整批不命中，但文件被覆盖 | 1050-1073 |
| 跨 RFC 错误命中风险 | 低（key 含内容），但**无法逐文档复用**，且 `doc` 仅文件名，改名/同名文档存在串源风险 | 条目结构 |

## 二、结论

现有身份是「输入集合的身份」，不是「文档的身份」。这直接导致：

1. 12 份零产出文档的 76 条结果绑在一个 `complete=false` 的批次里，无法按文档启用；
2. 任何一次输入变化都让全部结论作废；
3. 无法回答「某份 RFC 的散文知识是否已抽过」。

这三条正是 F2 要解决的，不是模型质量问题。

## 三、与既有结论的关系

RA-2 已确认 45 条缺口的直接原因是配置关闭（31）与触发条件（14），本轮不重复审计；这里只补「即使触发，缓存也不支持按文档使用」这一层。
