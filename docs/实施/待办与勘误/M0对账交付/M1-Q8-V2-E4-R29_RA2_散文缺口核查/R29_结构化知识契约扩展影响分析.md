# 结构化知识契约扩展影响分析

## 一、可复用

| 项 | 说明 |
|---|---|
| field Norm 路径 | D4 已证明可用（syntax + definition） |
| map_norm_to_facts | 无需改动 |
| Evidence 单段 quote | D4/H2 足够 |
| 隔离 Hub 读回 | 已验证 |

## 二、必须扩展

| 项 | 原因 | 影响面 |
|---|---|---|
| Value.type=grammar | ABNF 无法用 pattern 准确表达 | 中（需确认枚举是否封闭） |
| Subject.type=field/grammar_rule | header 语义错位 | 中（新 id，旧不动） |
| 多段 Evidence | D3 位域需图例+规范句 | 大（涉及 Claim/Evidence 结构） |

## 三、对 21 aspects 的影响

**零影响**（不新增 aspect）。语法用 `syntax` + grammar value，位域用 `legal_boundary`。

## 四、对身份稳定性

- 旧知识：不变（不做迁移）；
- 新知识：新 type ⇒ 新 id，不与旧冲突；
- 风险点：若将来迁移旧知识，FactID 会变，需一次性规划。

## 五、对 Hub 与 Evidence 读取

- Hub 实体表会新增 type 维度，索引代码可能需要按 type 分组；
- 完整 quote 仍在侧车，读取方式不变。

## 六、回归风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| grammar value 未被下游识别 | 中 | 先做只读实验 |
| 多 Evidence 导致 EvidenceID 冲突 | 中 | 先实验 |
| 旧知识误迁移 | 高 | 明确禁止迁移 |

## 七、D3/D4/H1/H2/H3/H5 验证

| Gold | 现方案 | 扩后方案 |
|---|---|---|
| D4 | 已闭环（借 header） | 改 field，id 变 |
| D3 | 无法 | 多段 Evidence + bitfield |
| H1/H2/H3/H5 | 仅 syntax（H2 部分） | grammar value + grammar_rule subject |
