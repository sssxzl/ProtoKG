# T0-A 341 行真实召回与 v4 回归对照

## 一、341 行：召回成功

v6 首次出现该条：

```
legal_boundary  341  [RULE:v1] {"action":"discard any knowledge obtained prior to the start of the TLS handshake","condition":"upon ..."}
```

主体（clients and servers）、MUST、动作（discard）、对象（knowledge obtained prior to handshake）均保留，未出现身份碰撞。

## 二、但整体回归严重

| 指标 | v4 | v6 |
|---|---|---|
| Norm / Fact | 30 | **16** |
| legal_boundary | 16 | 11 |
| definition | 14 | 5 |
| 实体 | 14 | 10 |
| Gold `-30-1` / `-30-2` | 语义有（锚点错） | **两条都无** |
| 341 行 | 缺 | **有** |

## 三、判断

v6 用「多抽承接句」的规则换来了 341，但输出总量腰斩、Gold 两句再次消失。这不是「全面优于 v4」，是有得有失。

可能原因：新增规则让模型在每条上都尝试找衔接关系，输出重心偏移，短小的定义句被压缩掉（definition 14→5 最明显）。

## 四、结论

- `T0_A_normative_341_live_recall_verified` 可登记（有真实证据）；
- **不能**因此认为 v6 优于 v4；
- 下一步要做的是「v4 + 341 单点补丁」而不是继续叠加规则——例如只在 `condition` 字段提示承接关系，不改变抽取广度。
