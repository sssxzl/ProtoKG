# 2131 与 9112 漏抽模式对照

## 一、共同点

1. **ABNF / 语法约束成片漏抽**：2131 的 flags 保留位、9112 的 request-line/field-name/chunked；
2. **独立 SHOULD NOT 漏抽**：2131 的 D2、9112 的 H6；
3. **术语定义漏抽**：2131 的 siaddr、9112 的 message 结构。

## 二、差异

2131 仍抽到较多字段语义（client identifier、ciaddr 等），9112 则连字段定义都少。
9112 的 ABNF 占比更高，可能是漏抽更严重的原因。

## 三、结论

v6 的缺陷不是随机分散，而是**集中在"形式化/结构化的规范表述"上**：表格、ABNF、位域、语法产生式。
这条规律在两种完全不同协议上复现，可信度高于单文档观察。

## 四、下一步建议

不再用 Prompt 加规则的方式补救（v6 已证明会挤掉其他知识），而是：
1. 保留 v6 做语义型知识；
2. 增加确定性通道处理 ABNF/表格（项目已有 ABNF 通道，曾被 D1 移出）；
3. 两者输出统一走既有身份与 Evidence 校验。

这属于架构调整，需单独批。
