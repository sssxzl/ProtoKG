# R29 RA-2 F2 正式合入风险与回滚方案

## 一、补丁范围

| 项 | 内容 |
|---|---|
| 文件 | `core/fused/extraction/prose_semantics.py` 单文件 |
| 行数 | 144 行（新增函数 + 两处调用点 + `_save_cache` 守卫） |
| 契约 | 不改 Norm/Fact/Evidence、不改 aspects、不改 Schema |

## 二、风险

| 编号 | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | 旧批次缓存被新代码误写 | 中 | `_save_cache` 检测 `.prose.d/` 即返回；测试第 6 项验证字节不变 |
| R2 | 部分命中时重复调用 LLM | 中 | 只对 miss 文档发调用；成本随文档数线性增长 |
| R3 | key 计算引入 doc 名，重命名文档即失效 | 低 | 失效是保守方向，不会串源 |
| R4 | 并发写同一文档缓存 | 低 | 当前单进程假设；如需并发再加锁 |
| R5 | 真实缓存语义未被验证 | 高 | 无可消费历史缓存，只能等首次真实运行后做等价性检查 |

## 三、回滚

1. `git apply -R R29_RA2_F2_影子补丁.patch`；
2. 删除 `derived/cache/source_blocks/<proto>.prose.d/`（若已生成）；
3. 旧 `*.prose.json` 未被动过，回滚后行为与 main 完全一致。

## 四、合入前置（建议）

1. 真实运行一次 DHCPv4（需 LLM 预算），产出文档级缓存后，与旧路径做一次等价性对照——目前做不到，这是最大的未知；
2. 确认 `.prose.d/` 目录不影响中枢构建（`derived/cache` 不参与 hub）；
3. 明确并发约束。

## 五、结论

工程机制可合入候选，但「真实缓存等价性」缺口未闭合。建议先作为影子保留，待一次真实运行后再申请合入。
