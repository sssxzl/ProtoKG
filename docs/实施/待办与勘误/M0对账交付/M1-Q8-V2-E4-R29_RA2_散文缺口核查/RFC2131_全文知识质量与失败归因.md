# RFC 2131 全文知识质量与失败归因

## 一、规模

| 项 | 值 |
|---|---|
| 块 / 批 | 33 / 17 |
| Norm | 74 |
| Evidence 定位 | 68/74 |
| Gold 召回 | 2/6（+1 部分） |
| 语义审查 | 仅 Gold 相关若干条，其余 pending |

## 二、失败归因

| 类别 | 数量 | 例 |
|---|---|---|
| 模型漏抽 | 3（D2/D3/D4） | 承接型 SHOULD NOT、保留位 MUST、siaddr 定义 |
| 引用不可定位 | 6 | quote 在原文无唯一匹配 |
| 语义部分覆盖 | 1（D6） | 消息类型错位 |
| 身份碰撞 | 0 | 未见 |
| 定位器缺陷 | 0 | 未见 |

## 三、判读

- 机械问题（定位、身份、留证）在本轮已基本收敛；
- **质量问题的重心回到模型召回**：DHCP 的表格/字段段落里，模型倾向抽"解释句"而漏"约束句"，与 SMTP 相反；
- 这与 RFC 3207 的结论不矛盾：不同文体的召回模式不同，v6 规则对散文型 RFC 较好，对表格/字段型 RFC 较差。

## 四、是否可进入下一份 RFC

可以，但**不能宣称 v6 泛化成立**。建议带着两个已知缺陷（承接句在表格型文档失效、定义类漏抽）进入 9112，观察是否复现。
