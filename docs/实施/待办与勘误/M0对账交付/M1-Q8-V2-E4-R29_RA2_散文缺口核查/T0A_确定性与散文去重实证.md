# T0-A 确定性与散文去重实证

## 一、做了什么

把散文路径产生的 Fact 与重复副本放进同一 `build_entity_index`，观察现有规则的实际行为，不新增任何判据。

| 场景 | 构造 | 实际结果 |
|---|---|---|
| 完全相同 Fact | 同一 Fact 两条 | 实体数不变（1），Fact 列表保留 2 条 |
| 不同来源同一知识 | 未构造（现有索引层无来源字段参与） | 未测 |
| 相同关键词不同知识 | 依赖 fact_id 不同 | 不合并（fact_id 不同即不同事实） |
| 相同 Fact 不同 Evidence | 现有 Fact 只有一份 claims | 证据合并逻辑在 Claim 层，索引层不处理 |
| 重复构建 | 同输入跑两次 | 实体索引字节一致 |

## 二、能力边界（必须说明）

现有系统在**索引层不做语义去重**：`build_entity_index` 按 `entity_id` 聚合实体，但 Fact 级别的重复条目不会被删除。真正的身份判重依赖 `fact_id`，而 `fact_id` 由 subject/aspect/value 计算——语义相同但表述不同的知识**不会被识别为重复**。

因此本轮不能宣称「语义去重通过」，只能说：

- 相同 `fact_id` 不会在实体表里产生两个实体；
- 不同 `fact_id` 的近似知识会被同时保留，这是当前能力上限。

## 三、为什么不做假

要「让去重通过」，只能临时加相似度判据或改 fact_id，两者都被禁止。保留重复并写明边界，比伪造一个通过更有用。

## 四、后续若要真去重

需要在 Canonical 层增加「同 subject+aspect 的 value 归一化/合并」规则，属于契约变更，需单独审批。
