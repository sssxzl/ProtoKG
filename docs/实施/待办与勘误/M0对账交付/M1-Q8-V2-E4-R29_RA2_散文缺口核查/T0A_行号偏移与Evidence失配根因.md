# T0-A 行号偏移与 Evidence 失配根因

## 一、偏移不是常数

v4 的 30 条里，锚点 76/78/80/82 都准，只有 Introduction 两条偏到 22/25（应为 30/33）。所以**不存在全局固定 8 行偏移**，不能给某段统一加 8。

## 二、根本原因不是行号转换

排查了四层：

| 层 | 结论 |
|---|---|
| 冻结原文行号 | `split("\n")`，30 行确为 `This document describes an extension…` |
| 切块 | 块 1 起始行 1，块内文本保留原换行 |
| 请求 | 只给块文本 + `起始行号 N` 头，未做行号重编号 |
| Raw→Norm | `span_line` 直接用模型返回值，无二次转换 |

因此行号偏差来自**模型自己的计数**，不是程序换算错误。

## 三、现有校验为什么放行

只查「该行原文出现 entity」。这两条 entity=`SMTP`，第 22 行确实有 `SMTP`，于是通过。校验强度不足。

## 四、结论

- 不是确定性换算错误 ⇒ 不存在「修正转换」可做；
- 只能在**证据层**解决：要求模型给出原文 quote，由程序在冻结原文里定位，模型行号只作参考。

## 五、未做的

没有给 Introduction 加偏移，也没有针对 Gold 行号硬编码。
