# R29 RA-2 F1 最小真实试验审批申请

## 一、申请内容

批准一次最小的真实散文抽取试验（T0 档），用于同时验证两件事：散文通道能否产出知识、文档级缓存能否按文档落盘并被复用。

| 项 | 值 |
|---|---|
| 文档 | rfc3207（smtp）、rfc4954（smtp） |
| 块 | 7 |
| 预计输入 token | 约 1.8 万 |
| 预计调用次数 | 2（每批 5 块） |
| 输出上限 | 2 000 token/次 |
| 模型 | 与现有缓存一致的 deepseek-flash（profile 未改） |
| Prompt | 不变（prose-semantics-v2） |
| 覆盖 Gold | 3 条（GK-B-smtp-rfc3207 ×2、rfc4954 ×1） |

## 二、为什么是这两份

1. 体积最小（18 679 + 43 493 字符），失败代价最低；
2. 都属「通道关闭」组，能直接检验开关打开后的行为；
3. 覆盖 3 条 Gold，可做一次小规模命中检查；
4. 缓存收益可立即观察（第二次运行应为 0 次调用）。

## 三、停止与回滚

| 项 | 内容 |
|---|---|
| 硬停止 | 单文档失败重试 2 次；累计失败 3 次；token 超预算 120% |
| 产出隔离 | 写入隔离 worktree 的 `derived/cache/source_blocks/smtp.prose.d/`，不进正式 `derived/` |
| 回滚 | 删除该目录即可；旧 `*.prose.json` 不动 |
| 不产生 | 不写正式中枢、不写 Seed、不改 Norm 基线 |

## 四、验收看什么

1. 是否产出 prose_semantics Norm（数量不计入基线）；
2. 缓存是否为「每文档一个文件、complete=true」；
3. 第二次运行是否 0 次调用；
4. 3 条 Gold 是否有命中（只作观察，不作指标）。

## 五、不批准也能接受的结果

如果项目方选择不批，F2 与 F1 都停在影子状态，相关指标维持 unavailable。本申请不附带自动扣费授权，也不预设必须执行。
