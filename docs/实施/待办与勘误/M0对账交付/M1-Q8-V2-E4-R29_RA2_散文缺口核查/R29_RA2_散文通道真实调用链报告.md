# R29 RA-2 散文通道真实调用链报告

## 一、调用链（按源码）

```
rfc_extractor.extract_rfc_norms
  └─ 4157-4161  读 profile 的 rfc.enable_prose_semantics（缺省 False）
  └─ 4162       if _unmatched_files and _known_entities and _enable_prose
        └─ prose_semantics.extract_prose_norms(protocol, _unmatched_files, entities, llm)
              └─ 块选择（block_selection / block_budget）
              └─ _run(...) 共享内核
                    ├─ block_hash = sha256(doc+start+text 拼接)
                    ├─ cache_key(prompt_version, block_hash, temperature, max_tokens, prompt_digest)
                    ├─ _load_cache → complete=false 或 failed_incomplete ⇒ 不命中
                    ├─ 未命中 ⇒ 构造 LLM 客户端；无凭据 ⇒ 整批放弃
                    └─ 产出 norms(kind=prose_semantics)
        └─ 4169-4178  并入协议级 norms
  └─ norm.prose_semantics_norm_to_facts ⇒ aspect definition / legal_boundary
```

Canonical 路径存在且有映射（`norm.py` 的 `prose_semantics` 分支），不是缺映射，是没数据。

## 二、十个问题的答案

| # | 问题 | 答案与依据 |
|---|---|---|
| 1 | 哪些入口会启用 | 只有 `extract_rfc_norms` 的通道 I；另有 `extract_window_norms`（段落级），同样受开关控制（4189/4223） |
| 2 | 默认是否关闭 | 是。`enable_prose_semantics` 缺省 False（4159） |
| 3 | 哪些协议实际启用 | 只有 DHCPv4（`profiles/dhcpv4/rfc_config.json:271 = true`）；smtp、rtsp、sip 未设置 |
| 4 | 缓存如何被发现 | 固定路径 `derived/cache/source_blocks/<协议>.prose.json`，按协议单文件 |
| 5 | 缓存用什么键 | `cache_key(prompt_version, sha256(块拼接), temperature=0.1, max_tokens=16000, prompt_digest)`，键是**批次级**的 |
| 6 | complete=false 如何拒收 | `_load_cache` 第 619 行 `if d.get("complete") is False: return None`，整条报文不命中 |
| 7 | 是否允许部分缓存 | 不允许。且 `failed_incomplete` 状态还有一层双保险拒收（627） |
| 8 | 无 LLM 客户端时如何处理已有缓存 | 命中缓存可以不调 LLM 并产出；未命中则打印 `[通道I] LLM 客户端不可用` 并**整批返回空**（918） |
| 9 | 拒收后是否完全没有候选 | 是。散文通道是该类知识的唯一入口，拒收后无兜底 |
| 10 | 散文输出到 Canonical 是否有真实路径 | 有，`prose_semantics_norm_to_facts` 复用既有 aspect；当前 0 条数据 |

## 三、一个被忽略的前置条件

触发条件不只是「开关 + 无凭据」，还有 `_unmatched_files`：**只处理零产出的文档**。

实测后果：rfc1542、rfc2131 这类「有确定性产出但仍有散文缺口」的文档永远进不了散文通道。R28-C 归为「有缓存未被接受」的 14 条全部落在这里——它们连缓存检查都没走到。

## 四、结论

散文通道当前处于三重受限状态：

1. smtp / rtsp：配置关闭；
2. DHCPv4：仅对零产出文档触发，部分文档因此永不被覆盖；
3. 即便触发，批次级缓存 `complete=false` 且无 LLM 凭据，整批放弃。

这三层是串联的，不是并列的，修任何一层都不足以恢复知识。
