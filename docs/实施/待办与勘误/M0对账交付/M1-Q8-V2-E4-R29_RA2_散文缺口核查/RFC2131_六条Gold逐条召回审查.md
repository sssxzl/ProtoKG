# RFC 2131 六条 Gold 逐条召回审查

## 一、结论先说：本轮无法给出可靠召回率

17 批跑完、74 条 Norm 已合并，但**按行号区间比对 Gold 全部落空**：

| Gold | 行 | 行号区间判定 | 实际观察 |
|---|---|---|---|
| D1 | 498–501 | miss | 相邻有 495、497 两条（client identifier） |
| D2 | 1711–1712 | miss | 未发现附近 span |
| D3 | 587 | miss | 无 580–600 区间条目 |
| D4 | 508–510 | miss | 无 |
| D5 | 1698 | miss | 无 |
| D6 | 1718 | miss | 无 |

## 二、判定不能成立的原因

模型给的 `span_line` 与原文行有 1–3 行漂移（D1 落在 495/497），用"行号是否落在区间"做召回判定会把命中算成未命中。

这正是之前 T0-A 已经解决过的问题：**应当用 quote 定位后的 verified_span 判定，而不是模型 span**。

## 三、因此本轮的正确结论

- Raw 层面：D1 附近确有对应知识（client identifier MUST 唯一），但不能据此宣称命中；
- D2（承接型 SHOULD NOT）：在 17 批 Norm 中未找到 1700–1725 区间条目，需用 quote 复核后判定；
- D3/D5/D6：需 quote 复核。

- 未完成六条 Gold 的逐条语义比对。
