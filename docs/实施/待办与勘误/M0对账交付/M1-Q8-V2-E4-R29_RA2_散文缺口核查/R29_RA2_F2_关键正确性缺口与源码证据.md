# R29 RA-2 F2 关键正确性缺口与源码证据

## 一、四处缺口

### G1 批次失败污染文档级完成状态

| 项 | 内容 |
|---|---|
| 原实现 | `_save_doc_caches(..., complete=(not stats.get("failures")))` 对全部文档一视同仁 |
| 后果 | B 文档失败 ⇒ A 文档被重写为 `complete=false`，已完成的 A 反而失效 |
| 修正 | 引入 `_doc_ok: dict[doc,bool]`，按批次结果逐文档置位；只保存 `doc_ok=True` 且属于本次 miss 集合的文档 |
| 证据 | 测试「A 命中 + B 失败 ⇒ A 缓存字节不变」、」「下次只处理 B」 |

### G2 旧缓存兜底与设计不一致

| 项 | 内容 |
|---|---|
| 原实现 | 文档级全未命中时 `else: cached = _load_cache(protocol, block_hash)` 仍读旧批次文件 |
| 后果 | 旧缓存（含 `complete=false` 之外的情形）可绕过文档级来源与版本约束 |
| 修正 | 删除兜底，文档级路径不再触碰 `*.prose.json`；`_save_cache` 检测 `.prose.d/` 即返回 |
| 证据 | 测试「旧批次缓存（complete=true）不被消费、不被改写」 |

### G3 Parser 版本被 Prompt 版本冒充

| 项 | 内容 |
|---|---|
| 原实现 | `_load_doc_caches(protocol, meta, PROSE_SEMANTICS_PROMPT_VERSION)`，把 prompt 版本当 parser 版本传入 |
| 修正 | 改为 `from cache_key import PARSER_VERSION as _PV`，键内 `parser_version=_PV` |
| 其余身份 | Prompt 版本与内容哈希、模型身份、温度、max_tokens、schema 版本均由 `cache_key()` 显式纳入（见 `cache_key.py:66-95`：`prompt_version/prompt_digest/model/model_snapshot/temperature/max_tokens/parser_version/schema_version/verifier_version`） |
| 证据 | 测试「parser 版本进入键」 |

### G4 原始 RFC 哈希与选块哈希混淆

| 项 | 内容 |
|---|---|
| 原实现 | `doc_sha256` 是 `sha256(doc + 拼接文本)`，既不是原文哈希，也受拼接顺序影响 |
| 修正 | 1) 块构建时记录 `src_sha256 = sha256(文件字节)`；2) 选块指纹 `_block_signature` 用「起始行+长度+块内容哈希」结构化拼接；3) 键 = `doc + src_sha + block_sig + 版本`；4) 来源缺失或冲突（同文档不同 sha）⇒ 拒收且不写缓存 |
| 证据 | 测试「块边界不同 ⇒ 指纹不同」「原始 SHA 变化（块文本相同）⇒ 失效」「来源 SHA 缺失 ⇒ 不命中」 |

## 二、仍然保留的保守设计

1. 不迁移 76 条历史条目，不赋予单文档完成资格；
2. `complete=false` 一律不可读；
3. 来源不可证时不写缓存（写了也读不到，等于制造垃圾）；
4. 文件名仅用于命名，身份由 `key` 决定。

## 三、未解决

真实缓存等价性仍无法验证（无合法可消费的完整缓存），见最终验收文档。
