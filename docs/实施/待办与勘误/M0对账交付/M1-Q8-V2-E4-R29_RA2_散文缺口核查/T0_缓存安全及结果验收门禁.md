# T0 缓存安全及结果验收门禁

## 一、缓存安全（引用既有证据，不重做审计）

| 检查 | 结论 | 证据 |
|---|---|---|
| 外层 doc 正确、内部 item 属于他文档 | 条目按 `item["doc"]` 归入各自文件，不串号 | `f2_checks_v3`「缓存内 items 的 doc 与文件名一致」 |
| 部分块后提前终止 | 不得写 complete=true | 本轮新增「块未跑全 ⇒ 不写缓存」守卫 + `t0_preflight` 的 `partial_blocks_not_complete=True` |
| 来源缺失/冲突 | 不产生有效缓存（粘性） | `f2_checks_v3` B1–B4 |
| 历史 76 条 | 不读、不写、字节不变 | `f2_checks_v2` 第 6 项 |

新增的一处最小修正：`_extract_blocks` 尾部比较 `_doc_done` 与 `_doc_expect`，块数不足即把该文档标为失败、不落缓存。此前「预算中途停止」会让半份文档被标 complete。

## 二、结果采集清单（真实运行时必须落盘）

| 项 | 字段 |
|---|---|
| 每次请求 | model、doc、block 起始行、input/output token、耗时、finish_reason |
| 原始响应 | 全文（脱敏）+ sha256 |
| 解析结果 | 条目数、拒收数、拒收原因 |
| 失败分类 | 请求失败 / JSON 解析失败 / 截断 / 空结果 |
| 缓存 | 每文档 key、doc_sha256、block_sig、complete、status |
| 二次运行 | 命中文件数、真实请求次数（应为 0） |
| Gold | 命中/部分/未命中 + 证据跨度 |
| 隔离 | Norm 数量变化只出现在影子目录 |

## 三、空结果与失败必须分开

| 现象 | 判定 |
|---|---|
| 返回 `{"items": []}` | `success_empty`（可信负结果） |
| JSON 解析失败 | 失败，不写缓存 |
| `finish_reason=length` | 截断，不写 complete |
| 请求异常 | 失败，重试后仍失败则不写 |

不能把截断或解析失败记成 `success_empty`，否则「没抽到」与「没跑成」混为一谈。

## 四、验收门禁

T0 结果须同时满足：

1. 请求次数 ≤ 2，且实际支出 ≤ 批准上限；
2. 每份文档缓存 `complete=true` 且 `doc_sha256` 与文件一致；
3. 二次运行 0 次请求、命中同一 key；
4. 3 条 Gold 有明确的命中/未命中记录，**不要求命中率**；
5. 影子 Norm 与正式基线隔离（正式 `derived/` 未被写入）；
6. 无跨文档串号条目。

任一条不满足，T0 记为 `failed`，不得以「产出了 N 条 Norm」替代。
