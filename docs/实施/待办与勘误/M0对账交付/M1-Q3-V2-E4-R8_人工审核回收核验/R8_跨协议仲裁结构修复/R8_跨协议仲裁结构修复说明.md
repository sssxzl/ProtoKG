## 一、已验证事实

### 1.1 六列 A/B 原始判断的自动回填

原表头标注为「机器预置，不可改」，但机器基线本就不含双方判断。
已从各协议的 A 与 B 原始审核文件按审核 ID 精确回填六列：

| 列 | 来源 |
|---|---|
| A:知识类型 / B:知识类型 | 各协议审核者 A、B 的「人工审核」表 knowledge_kind 列 |
| A:rule_eligibility / B:rule_eligibility | 同上 rule_eligibility 列 |
| A:证据充分性 / B:证据充分性 | 同上 evidence_sufficiency 列 |

57 条全部回填，**空缺 0 条**。回填来源记录在每行的「回填来源」列。

### 1.2 字段错位的修正

原「最终裁定状态」列实际存的是 V2 目标路由值（rule_channel 等），与表头语义不符。

处理：新增「仲裁后 V2 目标路由」列承接原值；原「最终裁定状态」列改为指引文本。
**不推断第三方未作出的裁定**：仲裁者从未填过裁定状态，该列保持空白指引。

57 条中仲裁后路由与知识类型的对应关系**零不一致**，与 V2 的六类到四路由映射完全吻合。

### 1.3 抽取完整性分歧清单

A 与 B 在抽取完整性上分歧 **37 条**（SIP 20、RTSP 4、SMTP 13）。
已生成 `R8_抽取完整性待确认清单.xlsx`，含 A 值、B 值、C 的仲裁后知识类型、
C 理由中是否提及完整性、机械提取的建议值（仅供参照），以及留空的人工确认三列。

仲裁表新增「仲裁后抽取完整性」列，57 条全部留空待人工填写。

### 1.4 原子知识拆分线索

从第三方仲裁理由中提取 **7 处**真实拆分线索：

| 线索 | 协议 | 候选 | 内容 |
|---|---|---|---|
| SC-01 | RTSP | X-rtsp-rfc7826-03 | 同句前半 MUST allow 重复设置属未被覆盖的另一条义务，应另立条目 |
| SC-02 | RTSP | X-rtsp-rfc7826-05 | 458 的枚举行可另立一条，但不能替代本句的应答要求 |
| SC-03 | RTSP | X-rtsp-rfc7826-06 | 5398「Otherwise, a body MUST NOT be returned」是紧邻的另一条义务，须另立 |
| SC-04 | SMTP | X-smtp-rfc3461-03 | 同句含 MAY 与 MUST 两条规范，应拆成两条入规则通道 |
| SC-05 | SMTP | X-smtp-rfc3461-04 | ENVID 与 ORCPT 共享同一 MAY，宜拆两条 |
| SC-06 | SMTP | X-smtp-rfc6531-01 | 可把两个术语拆成两条术语条目，并保留「可能是也可能不是 ASCII 子集成员」的关键限定 |
| SC-07 | SMTP | X-smtp-rfc8098-03 | 491 行的 SHOULD 另立一条；492 行的例外约束的是整组 OWS 建议 |

机械拆分结果不得直接作为 Gold，须人工在补录表中逐条确认命题、跨度、强度、极性与是否纳入。

## 二、限制

1. 抽取完整性的建议值为从仲裁理由中机械提取，**不作裁定**，37 条全部需人工确认。
2. 拆分线索为从散文中按拆分动词筛选，可能仍有遗漏或误判，需人工核。
3. 补录表的「与已有补充知识的关系」需人工判断，避免同一命题重复计入。
