# V2 · RFC1534 陈述式规范义务专项审计

## 一、★ 五个问题的回答

### Q1：没有 RFC2119/BCP14 大写关键词时，原文是否仍可能规定协议行为？
★★ **是。** ★ 典型如 RFC 1534 行 72–75：
```
If a DHCP server that is not configured to support BOOTP clients receives a
BOOTREQUEST message from a BOOTP client, that server silently discards the
BOOTREQUEST message.
```
★ 该句**规定协议参与方的可观测行为**（★ 条件 → 行为），★ 却**无任何大写 BCP14 关键词**

### Q2：主体、动作和触发条件是否足够明确？
| 要素 | 内容 | ★ 明确性 |
|---|---|---|
| ★ 主体 | ★ **that server**（★ 承接前文 ⇒ DHCP server） | ★ 明确（★ 跨句指代） |
| ★ 动作 | ★ **silently discards** | ★ 明确 |
| ★ 触发条件 | ★ **服务器未配置支持 BOOTP 客户端 且 收到来自 BOOTP 客户端的 BOOTREQUEST** | ★ 明确（★ 两个合取项） |

### Q3：是否能区分规范要求与仅描述常见实现行为？
★★ **可以，★ 靠「义务主体 + 行为动词 + 条件从句」三要素**（★ V2 的 S10 判据）
★ ★ **不靠 BCP14 关键词**（★ 关键词只是**充分**条件，★ **不是必要**条件）

### Q4：若原文未明确给出强度，是否应保留 `strength=unknown`？
★★ **应当。** ★ V2 的陈述式规范句路径**明确输出 `strength = unknown`**，
★ ★ **不擅自提升为 MUST**（★ 已由单元测试 `test_strength_must_not_be_promoted_to_must` 断言）

### Q5：V2 如何保证此类真实规范候选不被元数据或描述性规则误排除？
| 措施 | 说明 |
|---|---|
| ★ ① **陈述式规范句判据（S10）** | ★ 条件从句 + 协议行为动词 + 协议参与方主体 ⇒ **适用规则通道** |
| ★ ② **跨句复核** | ★ 条件与主体常跨句 ⇒ ★ 在**完整逻辑行**上再判一次 |
| ★ ③ **跨度合并** | ★ entity 句与强度词句相邻 ⇒ **合并为一段证据**（★ 避免选到章节标题/定义句） |
| ★ ④ **§四 案例实测** | ★ `rfc1534.txt@1#3` 与 `@1#4` ⇒ **均判 `normative_rule_candidate` → `rule_channel`** ✔ |

## 二、★ N1-B 与 N1-C 的 DHCPv4 判断差异（★ 先查同类性与构成，★ 不直接判矛盾）

| 项 | ★ N1-B（开发集 32 条） | ★ N1-C（独立集 50 条） |
|---|---|---|
| ★ DHCPv4 候选数 | 2 条（★ `rfc1534.txt@1#3` / `@1#4`） | 15 条（★ 含 rfc1534/1542/2131/2132/2563/2939/3004） |
| ★ 人工判 valid_confirmed | ★ **2 条** | ★ **0 条** |
| ★ **是否同一规范语义类别** | ★ **是**（★ 都是 RFC1534 的陈述式规范句） | ★ ★ **否**（★ 15 条中仅 2 条是 rfc1534，★ 其余 13 条来自其他 RFC 的**选项/格式定义**） |
| ★ **抽样构成差异** | ★ DHCPv4 占 2/32 = 6% | ★ DHCPv4 占 15/50 = 30% |

⇒ ⇒ ★★★ **★ 结论：★ 差异主要来自【抽样构成差异】而非【同一批样本的人工标注互相矛盾】**
⇒ ⇒ ★★ **★ 仍存在的实质矛盾：★ N1-C 的 15 条 DHCPv4 中**不包含** `@1#3`/`@1#4`**
⇒ ⇒ ★★ ⇒ **★ 因此无法用 N1-C 直接复核 N1-B 的那两条** ⇒ ⇒ ★★ **须专项复核**（★ 建议取 RFC1534 的对应锚点重新盲审）

⇒ ⇒ ★★ **★ 另需注意：★ V2 在 N1-B 上把这两条判为 `normative_rule_candidate`（★ 正确），
★ 而在 N1-C 上，★ 若同类候选出现，★ 应同样进入规则通道**（★ 判据不依赖批次）

## 三、★ 本专项的遗留

| # | 遗留 | ★ 后续 |
|---|---|---|
| ① | ★ RFC1534 的 `@1#3`/`@1#4` 在 N1-C 中**无对应样本** | ★ 专项盲审（★ 需新增样本，★ 属新独立集的一部分） |

| ③ | ★ 跨句指代（★ "that server"）的**主体解析**依赖既有 `coreference` 模块 | ★ V2 只判类型，★ 主体解析仍由字段级校验负责 |
