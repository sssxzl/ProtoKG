## 一、★ 新独立评测集的构造原则（★ 冻结规则）

| # | 要求 | ★ 具体规则 |
|---|---|---|
| 1 | ★ **在执行验证前冻结样本与指标** | ★ 样本清单 + 指标定义 + 脚本哈希**先冻结**，★ 再开始标注 |
| 2 | ★ **覆盖不同协议与 RFC 章节** | ★ 4 个协议 × **≥ 3 个不同章节类型**（★ 规范义务章 / 语法附录 / 登记表 / 元数据区 / 描述性章） |
| 3 | ★ **包含五类目标样本** | ★ A 真实规范义务 ｜★ B 非规范元数据 ｜★ C 结构化语法 ｜★ D 描述性知识 ｜★ E 混合段落 |
| 4 | ★ **防止同源 chunk 近重复泄漏** | ★ ★ **按 `chunk_id`（而非文档/行）去重**；★ **同一 chunk 的全部候选只允许出现在一个集合**；★ ★ **开发集（N1-B 32 + N1-C 50）的 `chunk_id` 全部列入排除集** |
| 5 | ★ **含未生成候选的 RFC 原文段落** | ★ 从 **未被候选生成覆盖**的原文段落抽样，★ **为后续召回率实验提供基础**（★ 本轮只抽样与冻结，★ 不做召回结论） |
| 6 | ★ **独立人类审核 + 分歧仲裁记录** | ★ 与 N1-A/N1-C 同规程：★ A/B 双盲 + 第三方仲裁，★ **匿名审核者 ID + 日期 + 理由**三项齐备 |
| 7 | ★ **不得因结果不好而换样本或改指标** | ★ ★ 若独立评估失败：★ 可据失败案例迭代，★ 但**该批即进入开发过程**，★ 下一次正式泛化评估**须另建测试集**；★ ★ 严禁「调整判据后重算并仍称为首次独立评估」 |

## 二、★ 样本规模与构成（★ 建议，★ 冻结前可调整一次）

| 分层 | ★ 建议条数 | ★ 来源 | ★ 目的 |
|---|---:|---|---|
| ★ A 真实规范义务 | **20** | ★ 人工预筛含强度词或陈述式规范句的段落 | ★ 测「是否被错误排除」 |
| ★ B 非规范元数据 | **12** | ★ 版权/商标/免责/地址章 | ★ 测「是否被错误路由为规则」 |
| ★ C 结构化语法 | **12** | ★ ABNF 产生式/选项布局 | ★ 测「是否被保留在结构化通道」 |
| ★ D 描述性知识 | **12** | ★ 无义务强度的说明性散文 | ★ 测「是否被误判为规则」 |
| ★ E 混合段落 | **14** | ★ 同一段内既有规范句又有描述/登记 | ★ 测「是否按子句/证据跨度分开处理」 |
| ★ **合计** | **70** | —— | —— |

★ ⇒ ★★ **样本量依据**：★ A 层 20 条 ⇒ ★ 误排率的 95% Wilson 区间约 ±20 个百分点（★ 小样本的诚实区间）
★ ⇒ ★★ **建议同时做一次「按 chunk 分层」的重采样抽样（★ cluster bootstrap）**，★ 避免把同 chunk 的多条当作独立样本

## 三、★ 泄漏防控的具体机制

| 机制 | 实现 |
|---|---|
| ★ chunk 级排除 | ★ 构建 `excluded_chunks = {N1-B 的 32 条} ∪ {N1-C 的 50 条}`（★ **82 条的 chunk_id 全集**）⇒ ★ 抽样时**硬排除** |
| ★ 文档级降权 | ★ 同一 RFC 文档在新集中**不超过 6 条**（★ 避免单文档主导） |
| ★ 近重复检测 | ★ 对候选的 `evidence_span` 文本做 **5-gram Jaccard**，★ 与开发集相似度 > 0.6 ⇒ ★ 排除 |
| ★ 锚点邻域排除 | ★ 新样本锚点行 ± 3 行内**不得**与开发集锚点行重合 |

## 四、★ 预注册指标（★ 冻结，★ 不得事后改）

| # | 指标 | ★ 定义 | ★ 阈值（建议） |
|---|---|---|---|
| ★ P1 | ★ **真实规范义务误排率** | ★ A 层中被 V2 排到非规则通道的比例 | ★ **越低越好**；★ 报告 CI |
| ★ P2 | ★ **非目标知识误路由率** | ★ B+C+D 层中被 V2 判 `rule_channel` 的比例 | ★ **= 0 为期望** |
| ★ P3 | ★ **结构化知识保留率** | ★ C 层中进入 `structured_channel` 的比例 | ★ **= 100% 为期望** |
| ★ P4 | ★ **混合段落子句级处理率** | ★ E 层中按证据跨度分开处理的比例 | ★ 报告实测 |
| ★ P5 | ★ **规则通道纯度** | ★ 进入 `rule_channel` 中人工判成立的占比 | ★ 报告实测 |
| ★ P6 | ★ **不确定项占比** | ★ `pending_review` 占比 | ★ 报告实测（★ **不设阈值**） |
| ★ P7 | ★ **人工负担口径** | ★ 待审中「人工判成立但字段不完整」的条数 | ★ 报告实测（★ **不由 pending 数推断**） |
| ★ P8 | ★ **陈述式规范句召回** | ★ A 层中「无 BCP14 关键词」的样本被正确保留的比例 | ★ **★ 关键指标** |

★ ★ **禁用的证明方式**：★ 不得以「pending 减少」「LLM 路由减少」作为性能提升的证据
★ ★ **必报的伴随项**：★ ① P1 误排条数逐条列出 ② 阈值未达时如实报告失败
