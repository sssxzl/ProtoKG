## 一、★ 案例 A：N1-B `rfc3207.txt@468#0`（RFC 3207 · SMTP）

### 1.1 原始上下文（★ 行 459–470）
```
459: This document and translations of it may be copied and furnished to

463: kind, provided that the above copyright notice and this paragraph are

466: the copyright notice or references to the Internet Society or other

```

### 1.2 规范对象定位

| 项 | 结论 |
|---|---|
| ★ 原始章节 | ★ **文档版权声明（Copyright Notice）**，★ 位于 RFC 正文之前 |
| ★ “must be followed” 的**主语** | ★ **the procedures for copyrights defined in the Internet Standards process**（★ 文档级对象） |
| ★ 约束的**行为** | ★ 版权程序须被遵循（★ **约束文档使用者**，★ 非协议参与方） |
| ★ 协议参与方 | ★ **无**（★ server / client / peer 均未出现） |
| ★ 人工真值 | ★ **valid_rejection**（★ 人工判不构成协议规范义务） |

### 1.3 V2 判定
| 项 | 值 |
|---|---|
| ★ source_kind / knowledge_kind | ★ `non_protocol_metadata` |
| ★ rule_eligibility | ★ `ineligible` |
| ★ route | ★ `metadata_channel`（★ **不是丢弃**，★ 保留证据与理由） |
| ★ 命中信号 | ★ S6（元数据章节）**或** S5+S3+¬S4 |
| ★ 证据跨度 | ★ 行 469 起的版权许可句（★ **仅该句**，★ 非整块） |
| ★ V1 单独 | ★ `routed_to_LLM`（★ **误入规则通道**） |
| ★ **V2+V1** | ★ `routed_to_structured`（★ **已修正**） |

## 三、★ 确定性判断的依据（★ 三重，★ 互不依赖）

| # | 依据 | ★ 说明 |
|---|---|---|
| ① | ★ **结构位置** | ★ 该证据落在**文档版权声明章节**（★ S6）⇒ ★ 无论内容如何都非协议行为规范 |
| ② | ★ **文档作用域** | ★ 命中的句子位于「**许可条件 / 免责条款**」语境（★ S5）⇒ ★ 是**对文档使用者的许可约束** |
| ③ | ★ **语义对象** | ★ 主语/宾语为**文档级对象**（★ copyright / notice / document / standards process）且**无协议参与方**（★ S3 ∧ ¬S4） |

⇒ ⇒ ★★ **三条同时成立才判元数据**；★ **任一不成立 ⇒ 不判元数据**（★ 避免误伤）
⇒ ⇒ ★★ **★ 明确未采用的两种朴素做法**：
★ ✗ 「包含 must ⇒ 规范规则」（★ 版权声明也含 must）
★ ✗ 「包含 copyright ⇒ 整块全部删除」（★ 只按证据跨度判定，★ 其余内容不受影响）

## 四、★ 为什么这不是「丢弃」

★ **★ 路由到 `metadata_channel`（★ 保留可追溯记录）**，★ 不是删除：
★ 原始证据跨度（★ 行号 + 原文）**完整保留**；★ 隔离原因**逐条记录**
★ ★ 判据表与单元测试均断言「证据跨度必须非空」

⇒ ⇒ ★★ **★ 「不是规范规则」≠「无价值知识」**：★ 这类知识仍以**元数据**形态被保留，★ 只是**不进规范规则确认通道**
