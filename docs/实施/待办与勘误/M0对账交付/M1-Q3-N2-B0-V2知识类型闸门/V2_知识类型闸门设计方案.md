# V2 · 知识类型闸门设计方案

> ★ 日期：2026-11-16 ｜★ **离线影子，★ 未接入生产** ｜★ **0 次 LLM 调用**

## 一、★ V2 的定位（★ 不取代 V1）

★ **V2 = 判断「候选属于哪一类知识、应该交给哪条处理路径」**
★ **V1 = 判断「证据是否支持该规范义务、是否有明确反证、还是不确定」**
★ ⇒ ★ **V2 输出规范候选资格（rule_eligibility），★ 不输出 confirmed**

### 1.1 ★ 四个维度（★ 必须同时区分）

| # | 维度 | 取值 | ★ 说明 |
|---|---|---|---|
| ① | ★ **source content kind**（来源内容类别） | 六类之一 | ★ **原文这段是什么**（语法？登记？版权？规则？） |
| ② | ★ **knowledge kind**（候选知识类别） | 六类之一 | ★ **这个候选承载的是什么知识** |
| ③ | ★ **rule eligibility**（是否适用规范规则确认通道） | eligible / ineligible / uncertain | ★ **能否进规范规则确认通道** |
| ④ | ★ **evidence sufficiency**（证据是否足够） | 由 V1 提供 | ★ **三态判定（supported/contradicted/uncertain）** |

⇒ ⇒ ★★ **① ≠ ② ≠ ③ ≠ ④**：★ 「不是规范规则」**不等于**「无价值知识」

## 二、★ 六个知识类别与既有通道复用

| V2 类别 | ★ 语义 | ★ **既有 aspect 通道（复用，★ 不新增）** | ★ 路由 |
|---|---|---|---|
| ★ `non_protocol_metadata` | ★ 版权/商标/免责声明/IANA 声明等**文档级元数据** | ★ **无对应 aspect** ⇒ ★ **保留记录但不进规则通道** | `metadata_channel` |
| ★ `protocol_syntax` | ★ ABNF 产生式、消息语法 | ★ `syntax` → A_structure/headers；★ `binary_layout`/`option_layout` → D_construction/layout | `structured_channel` |
| ★ `protocol_registry_or_enumeration` | ★ 状态码表、选项名表、错误码表 | ★ `value_enum_spec` → D_construction/case_rules；★ `value_enum_observed` → E_observation | `structured_channel` |
| ★ `protocol_descriptive_semantics` | ★ 描述性散文（★ 无义务强度） | ★ `definition` → A_structure/by_entity_type；★ `existence` | `descriptive_channel` |
| ★ `normative_rule_candidate` | ★ 具备规范义务形态 | ★ `precondition`/`required_header*`/`response_expectation`/`session_header`/`legal_boundary`/`security_property`/`method_sequence`/`message_instance`/`relation_to_other`/`url_template`/`target_state`/`state_changing`/`vuln_pattern` | `rule_channel`（★ 再交 V1） |
| ★ `mixed_or_uncertain` | ★ 证据不足或形态混合 | —— | `pending_review`（★ 人工） |

⇒ ⇒ ★★ **★ 不新建平行 FactID、★ 不修改既有 21 aspects、★ 不新建 aspect**
⇒ ⇒ ★★ **★ 没有任何「丢弃」出口**：★ 每条都有 route，★ 原始证据与隔离原因全部保留

## 四、★ 禁止项（★ 明确不采用）

| 禁止 | ★ 本设计的替代 |
|---|---|
| ★ **「包含 must ⇒ 规范规则」** | ★ 须同时满足：★ 强度词 **且** 义务主体为**协议参与方** **且** 有行为动词；★ 版权声明含 must ⇒ **判元数据** |
| ★ **「包含 copyright ⇒ 整块全部删除」** | ★ **只按证据跨度（单句/合并句）判定**；★ 其余内容不受影响；★ **保留原始证据与隔离原因** |
| ★ **「无 BCP14 关键词 ⇒ 描述性」** | ★ 新增**陈述式规范句**判据（★ 条件从句 + 协议行为动词 + 协议参与方主体）⇒ **适用规则通道，★ strength = unknown** |
| ★ **强度不得擅自提升** | ★ 陈述式规范句 ⇒ ★ `strength = unknown`，★ **不写 MUST** |

## 五、★ 与 V1 的关系

```
候选 ──► V2：知识类型与来源作用域判定
          ├─ rule_channel ──► V1（冻结）：supported / contradicted / uncertain
          ├─ structured_channel ──► 既有 aspect 通道（★ 非规则通道）
          ├─ metadata_channel ──► 保留记录（★ 非规则通道）
          ├─ descriptive_channel ──► 既有 definition 通道
          └─ pending_review ──► 人工
```
★ ★ **V1 不得修改**（★ 哈希 10/10 一致，★ 已由单元测试断言）
★ ★ **V2 不以分类结果代替字段级语义校验**：★ 下列六类问题**仍不允许发布**：
★ ① 强度与极性不一致（如 SHOULD NOT 被抽成 SHOULD）② 主体缺失 ③ 条件遗漏
★ ④ 对象或跨句指代未解析 ⑤ 证据不足 ⑥ L2 结论存在重大分歧
★ ★ **这六类由 V1 + 字段级校验负责，★ V2 只判「有没有资格进规则通道」**
