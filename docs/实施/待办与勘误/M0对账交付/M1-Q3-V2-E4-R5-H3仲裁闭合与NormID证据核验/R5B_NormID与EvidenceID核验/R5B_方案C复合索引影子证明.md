# R5B 方案 C 复合索引影子证明

> ★ 只读影子实现，★ 未修改生产 norm_id 生成函数，★ 未写入 Evidence / Fact / FactID / Seed

## 一、复合索引构造

```
scheme_c_index = <文档标识> @ <起始行> _ <语义载荷 SHA256 前 8 位>
```

三段分别承担不同职责：文档标识解决跨文档冲突；起始行解决同文档不同位置冲突；语义载荷哈希解决同一跨度内的不同命题冲突。

★ 复合索引不含序号、不含时间戳、不含随机成分，★ 三次运行的输出逐字节一致。

## 四、来源版本绑定

复合索引本身不含来源版本，★ 因为来源版本的变化应产生**新的**索引值而非复用旧值。★ 实现上采用 sidecar 形式：

| 字段 | 来源 |
|---|---|
| `scheme_c_index` | 文档标识、起始行、语义载荷哈希 |
| `source_sha256` | 逐条登记，★ 来源版本变化时可检出 |
| `norm_id` | 旧标识符，★ 保留供兼容读取 |
| `evidence_id` | 现行值，★ 保留供对照 |

★ 来源版本变化时，★ 若语义载荷未变则复合索引不变，★ 但 sidecar 中的 `source_sha256` 记录会变化，★ 由此可检出「同内容、不同文档版本」的情形。

## 五、限制

1. 本证明基于 R3 的 57 条与 H1 的 156 条，★ 未在其他数据集上验证。
2. 复合索引未接入生产路径，★ 其唯一性结论不能直接推断到未来新增数据。
3. 真实 canonical 产物上的引用关系未核对，★ 相关结论保持 unmeasured。

## 六、下一步

若获批，以 sidecar 形式落地，★ 不改动任何生产标识符，★ 旧 norm_id 与 evidence_id 继续可读。
