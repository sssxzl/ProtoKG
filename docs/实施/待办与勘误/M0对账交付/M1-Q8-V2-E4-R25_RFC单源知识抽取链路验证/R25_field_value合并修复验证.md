## 二、五条验收要求的逐条判定

| # | 要求 | 判定 | 依据 |
|---|---|---|---|
| 1 | 原始合法取值不得丢失 | **通过**（真实语料） | 三协议的生产与影子**均为 0 丢失** |
| 2 | 不得错误合并不同字段 | **通过** | 按 norm_id 分组；不同字段 norm_id 不同 |
| 3 | 不得错误覆盖已有证据 | **通过** | 合并只改 content，不动 evidence_summary |
| 4 | 不得产生不必要的重复 Norm | **通过** | 影子补丁保留条数与生产相同 |
| 5 | 不改变现有 Canonical 身份契约 | **通过** | 影子补丁只改 content 字符串，**不触碰** norm_id / evidence_id / fact_id |

**但必须如实报告**：上述「通过」是在**真实语料零触发**的前提下得到的。
R24B 已用**合成输入**证明该分支有真实缺陷（合并结果写在被丢弃的 norm 上），
本轮用同一合成场景复验：

**合成场景（3 条同 norm_id，取值 alpha/beta/gamma）**：
生产：返回 1 条，内部 merged 有 3 值，**输出 content 只有首值** → 缺陷确认；
影子补丁：返回 1 条，**输出 content 含全部 3 值** → 修复有效。

## 三、影子补丁的设计（一处改动）

```python
# 生产（rfc_extractor.py:4114-4127）：合并结果写在**被丢弃**的 norm 上
norm["content"] = (f"{norm['name']} | values: " + SEP.join(_prev))
# 没有 norms.append(norm) → 该条被丢弃，合并结果随之消失

# 影子补丁：回写**已保留的首条**
_first = out[first_index[key]]
_first["content"] = (f"{_first['name']} | values: " + SEP.join(_prev))
```

**改动范围**：抽取层 `rfc_extractor.py` 的 field_value 分支；
**不涉及**：Canonical Schema、21 aspects、FactID、EvidenceID、NormID 契约。
