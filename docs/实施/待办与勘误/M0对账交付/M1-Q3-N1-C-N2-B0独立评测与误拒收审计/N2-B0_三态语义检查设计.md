# N2-B0 · 三态语义检查设计

> ★ 日期：2026-11-16 ｜★ **影子实现，不接入生产**
> ★ 实现：`guard/_out/_n1c/n2b0_tristate.py`（★ **不进 `core/`**，★ 不影响正式行为）

---

## 一、★ 核心原则

> **没有找到支持证据，不等于已经找到反对证据。**

★ 现行 `semantic_support` 只有「支持 / 不支持」两态，★ **「不支持」直接 ⇒ rejected**
⇒ ⇒ ★★ **本设计把它拆成三态，★ 并把「不确定」显式分离出来**

---

## 二、★ 三态定义与判定条件

| 态 | ★ 判定条件（明确） | 处置 |
|---|---|---|
| ★ **`supported`** | ★ 该字段在证据中命中：★ **词序列命中**（含生产同款「去尾 e」词根变体）**或** ★ **子串命中**（形态/词序不同）<br>★ 强度：★ 命中其同义词集（`MUST`→must/shall/required/is required/has to；`SHOULD`→should/recommended/…；`MAY`→may/optional/can/…） | ★ **进入 LLM 链**（★ 与现行行为相同） |
| ★ **`contradicted`** | ★ 存在**明确、可复核的反证**：★ 候选强度与原文的**相反强度/否定结构**同时出现<br>★ `MUST` 的反证：must not / shall not / should not / may not / is not required / is not mandatory<br>★ `SHOULD` 的反证：must not / shall not / must / is required / shall<br>★ `MAY` 的反证：must / shall / must not / shall not / is required | ★ **维持严格拒收（rejected）** |
| ★ **`uncertain`** | ★ 证据为空、该字段无值（合法缺省）、★ 词序列与子串**均未命中**、★ 或强度同义词集未出现 | ★ **保持 pending / 进入既有可控核验路径**；★ **绝不自动 rejected**；★ **绝不自动 confirmed** |

★ ⇒ ★★ **判定顺序**：★ 先查 `contradicted`（★ 任一字段命中即整体 contradicted）
⇒ ⇒ ★ 再看是否**全部 supported** ⇒ ⇒ ★ 否则 `uncertain`

---

## 三、★ 不在改造范围内的情况（★ 绝不当 pending）

★ 本设计**只作用于「纯语义支持检查」层**（★ `semantic_support`）
⇒ ⇒ ★ 以下情况**一律不转换**、**不进入三态**：

| 情况 | 处置 |
|---|---|
| ★ L1 身份契约不成立 | ★ **维持既有拒收** |
| ★ 解析失败 / JSON / Schema / Parser 异常 | ★ **维持既有 pending（保守待审）** |
| ★ 无效来源 / 非 RFC 文本 | ★ **维持既有拒收** |
| ★ 违反既有身份契约的候选 | ★ **维持既有拒收** |

⇒ ⇒ ★★ **不创建任何平行事实体系**；★ **复用现有 `verdict` / `reasons` / `field_verdicts` 字段**

## 四、★ 判定示例（★ 取自本批真实样本）

| 场景 | 现行 | 三态 | 依据 |
|---|---|---|---|
| 动作「silently discards」 vs 原文「silently discards」 | 不支持 | ★ **supported** | ★ 词序列命中 |
| 动作「silently ignore」 vs 原文「silently ignores」 | 不支持（★ 去尾 e 后仍不匹配 ignore≠ignores） | ★ **supported**（★ 三态的 `_morph` 覆盖 -s/-es/-ed/-ing 屈折与双写辅音） | ★ **同一动作的词形变化 ⇒ 不应拒收** |
| 对象「them (SEND, SAML, SOML)」 vs 原文 | 不支持（★ 括号/词序致精确匹配失败） | ★ **uncertain** | ★ 同上 |
| 对象「the procedures for copyrights defined in the Internet Standards process」 | 不支持 | ★ **uncertain** | ★ **候选字段本身是生成的长描述**（★ 属 A 类，★ 应重新抽取） |
| 强度 `MUST` vs 无 2119 关键词的 RFC（★ 如 RFC 1534） | 不支持 | ★ **uncertain** | ★ **无反证 ⇒ 不应拒收**（★ 强度无原文依据 ⇒ **需人工判读**） |

## 六、★ ★ 本设计的已知局限（★ 诚实记录）

1. ★★ **「三态 supported」≠ 放行**：★ supported 只表示「确定性语义检查通过 ⇒ 可进 LLM 链」
2. ★★ **三态比原版更保守但更准确**：★ 原版 41 条「支持」⇒ 三态 **37 supported / 10 uncertain / 3 contradicted**
   ⇒ ⇒ ★ **⇒ 14 条原 rejected 中：★ 1 条仍 rejected（★ 有反证）、★ 8 条转 pending（★ 无反证）、★ 5 条回 LLM 链（★ 词形等价命中）**
   ⇒ ⇒ ★ **★ 人工审核负担【不增反减】**（★ pending 15 → 8）
3. ★★ **`contradicted` 本批 3 条** ⇒ ★ 判据**已有少量实证**，★ 但样本少 ⇒ ★ 需在 N1-C 独立集上校准
4. ★★ **A 类根因（候选字段本身不在原文）无法靠三态修复** ⇒ ★ 需回到**抽取环节**
5. ★★ **合法缺省不构成阻塞**（★ 某字段本就无值 ⇒ ★ 不拉低整体判定）⇒ ★ 与用户要求的「区分合法缺省与遗漏」一致
