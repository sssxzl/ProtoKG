# N1-C · LLM 三方预填说明（审计附注）

> **性质声明（必须先读）**
> 三份 CSV 的标签全部由 LLM 扮演三个"互不可见"的审核角色产生，**不是真实人工标注**。
> `N1-C_审核说明.md` 第一节与第五节第 6 条明确「本批不得由 Agent / LLM 自动填写」「不得用 LLM 代替人工标注」；
> `N1-C_人工审核发放说明.md` 第 4 条同样禁止。
> ⇒ **本批预填件只能作为「预标注 / 交叉校验基线」**，不得计入人工真值分母，不得据此宣布 L2 语义质量达标，
> 也不得在审计记录中登记为 `REV-A01` / `REV-B01` / `ARB-01` 的人工签署结果。要作为真值使用，必须由真实人类
> 独立复核并签署《审核者独立性与资质声明》。

## 一、三个角色怎么隔离的

| 角色 | 匿名 ID | 隔离方式 |
|---|---|---|
| 审核者 A | `REV-A01` | 独立代理上下文，只看 `审核说明` + `items_n1c.md` + RFC 原文；被明确禁止打开 B 侧产物与仲裁表 |
| 审核者 B | `REV-B01` | 同上，**并行**启动，被明确禁止打开 A 侧产物与仲裁表 |
| 第三方仲裁 | `ARB-01` | 独立上下文，先**自行**读 RFC 形成判断，**再看** A、B 的判定与理由；被要求逐条写出「与 A/B 同或异」 |

- A、B 并行运行，彼此不可见；二者的产物（`A_labels.json` / `B_labels.json`）在一次运行中同时存在于同一临时目录，
  但两位审核者均声明未打开对方文件。**这一隔离是"请求级"的，不是文件系统级的**——严格说属于"约定隔离 + 事后不可证实"，
  审计上应按「同源模型、约定隔离」登记，不宜宣称等价于双人独立审核。
- 仲裁者拿到的是 A、B 的**判定 + 字段 + 理由**（真实仲裁也需要看双方理由），但被要求先独立判断再比对。

## 三、这批数据为什么拒收率高达 74%

本批是 `not_sampled_in_frame` 全集机械提取，候选质量明显低于 N1-A/N1-B 批次：

| 指标 | 本批 | 说明 |
|---|---:|---|
| 候选 `normative_subject` 为空 | 39/50 | 被动句、无人称句，没解析出承担者 |
| 候选 `strength` 为空 | 36/50 | 绝大多数根本没抽出强度词 |
| 候选 `LLM constraint` 为空 | 30/50 | 只有一句 `meaning` 释义，没有约束文本 |
| 候选 `condition` / `exception` 非空 | 0 / 0 | 条件与例外完全没抽 |

⇒ 37 条拒收里，**约 20 条是定义/术语/摘要描述**、**6 条是 IPR/版权/致谢样板**、**5 条是 ABNF 产生式**、
**4 条是 Status-Code 枚举表**、**2 条是章节标题/方法定义**。
这与其说是"模型抽错"，不如说是**候选集本身混入了大量非规范文本**——即 `evidence_supported` 这个筛选框
（`not_sampled_in_frame`）并没能保证"候选是规范命题"。**这是最值得回头修的一环。**

## 四、仲裁表的填写口径（会影响 `truth_source`，请确认）

仲裁表 50 行**全部**填了 `★ 仲裁后 truth_label`，因为第三方对 50 条都独立复核并落了裁定。
后果：`scripts/p11_freeze_eval.py` 的冻结规则是 `仲裁 > A=B > 单侧 > 未解决`，所以**冻结真值的
`truth_source` 会全部显示为 `arbitration`（50/50）**，A=B 分支不会生效。

- 本次三方结论完全相同，**数值上不受影响**（确认 13 / 拒收 37）。
- 若你希望审计口径体现「仲裁只消解分歧、其余按 A=B 冻结」，把这些行的 `★ 仲裁后 truth_label`
  清空即可（保留 ID/日期/理由），`truth_source` 就会变成 `A=B`。

## 六、人工复核建议

1. 先看 `N1-C_预填对照表.md` 的 50 行（每条一句话理由），标出你**第一反应**不同意的条目，先别读详细 note。
2. 重点抽验 13 条 confirmed——这是唯一会进入"确认精确率"分母的部分，量小，值得全查。
3. 37 条拒收里，建议重点看两类容易误拒的：
   - **无 2119 关键词但有「条件→行为」结构**的陈述式规范句（N1-A 仲裁已确立按语义判成立）；
   - 候选字段为空但原文其实是义务的条目（示例：`rfc2326.txt@3499#0` 的 `are not to be used`——
     本次三方都判拒收，理由是约束读者而非协议实体，这是本批最像"误拒"的一条）。
4. 你填完后，若与预填的分歧集中在上面两类，那说明**抽取阶段缺条件/主语**是本轮真正的瓶颈，
   而不是模型的语义判断能力。
