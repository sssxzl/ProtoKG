## 二、★ B. V1 是否造成大量无效候选**滞留**？

| 判据 | 阈值 |
|---|---|
| ★ **B1** | ★ M3（无效候选进入 pending + routed_to_LLM）**占无效候选总数的比例** ⇒ ★ **与 V0 对照**，★ 报告增减 |
| ★ **B2 滞留上限** | ★ 若「无效候选进入 routed_to_LLM」**占比 > V0** ⇒ ★ **判不通过**（★ V1 反而把无效候选送进验证链） |
| ★ **B3 滞留代价** | ★ 无效候选进入 pending ⇒ ★ **人工可直接闭环**（★ 依据 M6 的质量分层）；★ 进入 routed_to_LLM ⇒ ★ **需真实 LLM 调用**（★ 成本） |
| ★ B4 | ★ **★ 「rejected 归零」若伴随「无效候选滞留大幅上升」⇒ ★ 判为「★ 把拒收换成滞留 ★」，★ 不算改善** |
