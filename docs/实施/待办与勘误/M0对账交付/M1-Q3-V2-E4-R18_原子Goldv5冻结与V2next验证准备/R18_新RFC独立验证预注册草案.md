## 一、已验证事实

### 1.1 为什么必须用新样本

★ 已接触的 57 条（SIP / RTSP / SMTP）★ 已用于 R14 的首次事后评估、R15 的归因、
★ R16 与 R17 的影子方案比较。★ 按项目既有结论，★ **已接触样本不得再作为独立泛化测试集**。

### 1.2 ★★ 新样本的硬性隔离条件

| # | 条件 | 核验方式 |
|---|---|---|
| 1 | ★ RFC 文档**未参与 R14～R17 的任何调试** | ★ 登记文档编号、版本与 SHA256；★ 逐份核对不在既有 kb 与 rfc_text 中 |
| 2 | ★ **不得复用**已用过的 SIP / RTSP / SMTP 候选窗口 | ★ 新样本的候选 ID 空间与既有 57 条无交集 |
| 3 | ★ 新 Gold **不参与模型选择与调参** | ★ Gold 构建与 V2-next 的任何参数调整**分离进行**；★ Gold 冻结后才允许跑评估 |
| 4 | ★ **事前**预注册投影规则 | ★ **不沿用**事后补充的 R10-P1；★ 在新样本上预注册一条事前规则，★ 以保留事前预注册性质 |
| 5 | ★ 规则先于数据冻结 | ★ V2-next 代码、标签映射、投影规则、匹配规则、分母与排除条件、评估脚本**先**冻结并登记 SHA256 |

### 1.3 样本设计草案

| 项 | 建议 | 理由 |
|---|---|---|
| ★ 主验证：一个跨族新协议 | ★ 例如 FTP（★ 文档结构已知、★ 有历史快照） | ★ 最强的泛化证据；★ 但须以**新的 RFC 版本**与**新的候选窗口**取样 |
| ★ 辅助验证：一个同族新版本 | ★ 新版 SIP 或 SMTP 扩展 RFC | ★ 检验同族内的类型边界；★ **不构成跨族泛化证据** |
| ★ 候选级样本量 | ★ 每协议不少于 30 条 | ★ 小于 20 条时单条错误对准确率的影响超过 5 个百分点 |
| ★ 原子知识样本量 | ★ 不少于 10 条 | ★ 覆盖描述性、规范义务、枚举、元数据四类 |
| ★ 审核方式 | ★ A/B 独立 + 第三方仲裁；★ 审核者须不同于 D、C、F | ★ 延续既有的独立性与资格要求 |
| ★ 报告方式 | ★ 分协议；★ 类别分层的准确率与混淆矩阵；★ 不合并为跨协议通过率 | ★ 与 R14 口径一致 |

### 1.6 ★ 当前方案的一项已知盲区（★ 须在预注册中如实披露）

★ V2-next 的三条边界要求「锚点句自身具备行为义务特征」，
★ 因此在**锚点句与相邻句分担主体与行为动词**的情形下**是空操作**。
★ R18 的区分性合成样本 D-01 专门验证了这一点（★ V2 与 V2-next 均判描述性）。

★ ★ **预注册必须写明这一限制**，★ 否则新样本上的结果会被高估。
