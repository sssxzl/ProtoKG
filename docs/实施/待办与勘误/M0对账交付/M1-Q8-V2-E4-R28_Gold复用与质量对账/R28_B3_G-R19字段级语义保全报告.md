# R28-B3 G-R19 字段级语义保全报告

## 一、结论

| 项 | 结果 |
|---|---|
| 与当前 Norm/Fact/Evidence 建立明确对应 | 0 / 6 |
| 可做字段级比对 | 0 / 6 |
| 标签 | 6 条全部 `outside_current_scope` |
| 原因 | Gold 引用的 RFC 文档不在当前 `kb` 输入内 |

这不是「漏抽」，也不能据此判「字段未保全」。判定字段是否保全需要原文与 Gold 在同一可比范围内，当前不满足。

## 二、逐条身份核对

| gold_id | 协议 | 引用文档 | 在 kb 内 | 标签 |
|---|---|---|---|---|
| RTSP-ATOM-X-rtsp-rfc7826-03-1 | RTSP | rfc7826 | 否（当前 rtsp 只有 rfc2326） | outside_current_scope |
| RTSP-ATOM-X-rtsp-rfc7826-05-1 | RTSP | rfc7826 | 否 | outside_current_scope |
| SMTP-ATOM-X-smtp-rfc3461-03-1 | SMTP | rfc3461 | 否（当前 smtp 只有 3207/4954/5321/5322） | outside_current_scope |
| SMTP-ATOM-X-smtp-rfc3461-04-a | SMTP | rfc3461 | 否 | outside_current_scope |
| SMTP-ATOM-X-smtp-rfc6531-01-a | SMTP | rfc6531 | 否 | outside_current_scope |
| SMTP-ATOM-X-smtp-rfc8098-03-1 | SMTP | rfc8098 | 否 | outside_current_scope |

补充事实：这 6 条记录的 `document` 与 `source_sha256` 字段本身为空，只有 `gold_id` 里的 rfc 编号可解析；即使文档在库内，也无法做到行级对齐。这一点登入 B0 元数据（G-R19 的「最终 Gold 身份」为 verified_partial）。

## 三、字段状态

无一条进入字段比对，因此下列字段一律为 **not_applicable（不可比）**，不是 missing：

| 字段 | 状态 |
|---|---|
| 命题边界 | 不可比 |
| 知识类型 knowledge_kind | 不可比（Gold 记 normative_rule_candidate，但无机器对应物） |
| rule_eligibility | 不可比 |
| normative_subject | 不可比 |
| action / object | 不可比 |
| strength | 不可比（Gold 有 MUST/未记 两类，未与机器比对） |
| polarity | 不可比 |
| condition / exception | 不可比 |
| 原文证据 | 不可比 |

特别声明：没有把 R19 冻结的 `not_applicable` 改写成 `unknown`，也没有用当前机器的缺省值反推 Gold 应为何值。

## 四、这 6 条能否用于 R28-C

不能用于质量指标。它们只能作为「Gold 资产存在但当前输入不可比」的证据，说明历史 Gold 的 RFC 范围与当前三协议基线不一致。

若要使用，需要先决定：是否把 rfc7826 / rfc3461 / rfc6531 / rfc8098 纳入输入。这属于输入范围变更，须按计划第十节提交变更申请，不在本轮处理。

## 五、限制

1. 本轮只核对了文档是否存在，未核对「同一 RFC 的不同版本」。即使把上述 RFC 加进来，也要先确认版本与 Gold 采集时一致。
2. 字段级结论完全缺位，因此本报告不能回答「机器是否保住了 strength/polarity」。
