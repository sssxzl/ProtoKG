# R28 41 与 42 份 RFC 的范围差异说明

## 一、结论

| 项 | 数值 |
|---|---|
| `kb/*/spec/*.txt` 实际文件数 | 42 |
| R25 冻结的参与实验文档数 | 41 |
| 差额 | 1，即 `kb/sip/spec/rfc3261.txt` |

差额不是新增文档、不是重复文件、不是派生文本，而是 **SIP 源文件**，R25 清单里明确标注「否（本轮只做 RFC-only 三协议）」，从未参与三协议构建。

## 二、证据

R25 输入清单 `R25_RFC文档输入与版本清单.csv` 共 43 行（1 行表头 + 42 行文档），其中 rfc3261 一行：

```
3261, ... kb/sip/spec/rfc3261.txt, 647976, d513777f..., 否（本轮只做 RFC-only 三协议）
```

其余 41 行的「本轮参与实验」列为「是」。

分布：DHCPv4 36 份、smtp 4 份（3207/4954/5321/5322）、rtsp 1 份（2326）、sip 1 份（3261）。

## 三、对 R28-B 的影响

1. 本轮 G-B1 中 SIP 的 8 条有效记录与 3 条无目标记录，按 `outside_current_scope` 处理，不计入分母。
2. 41 份的正式输入范围未改动，`kb/` 内容未动。
3. 结论：这项差异不影响 G-R19 与 G-B1 的可比范围判断，也不影响本轮任何统计。未因此扩大成本去重新审计全部输入。

## 四、后续若要把 SIP 纳入

属于输入范围变更，须按固定计划第十节提交变更申请，说明新增文档、版本、对 41 份基线的影响与是否重跑。本轮不做。
