## 二、五项任务的结论

### 任务 A：Evidence 行号化（影子）

- 三通道（ABNF 字段、样例取值、消息清单）改为回传真实行号，Norm 集合不变（262 条，前后 `norm_id` 完全一致）。
- 带数字行号的 Norm 从 171 条（65.3%）提升到 214 条（81.7%）。
- 但只有 149 条（56.9%）落在非空原文，65 条落在空行或分页符，属精度不足。
- source 变化 43 条（smtp 27、rtsp 16），全部是锚点名换行号。
- locator 参与 `compute_evidence_id` 的哈希，因此这 43 条的 EvidenceID 必然变化，需要迁移与双读。

### 任务 B：field_value 合并修复（影子）

- 缺陷确认：合并结果写在马上被丢弃的后续条目上，保留条拿不到。
- 修复方式：记录实际保留条目的引用，合并写回保留条。
- 合成用例 4 项全部通过；真实语料 262 条 content 完全相同，`field_value` 差异 0 条。
- 也就是说，**修复在当前语料上零触发**，只有合成证据。

### 任务 C：零产出归因

- 41 份实验文档中，19 份零产出（全部 DHCPv4）：12 份卡在 LLM 缓存缺 `name` 字段，7 份是确定性抽取覆盖缺口。
- DHCPv4 缓存 76 条、覆盖 28 份文档、0 条含 `name`、22 条 `constraint` 非空；原样进映射器可映射 0 条，补 `name` 后可映射 22 条。
- 修复路径明确，但两条都需要成本（重建缓存要 LLM 调用，读取端补全要改代码）。

### 任务 D：口径复核

| 原口径 | 复核结论 |
|---|---|
| 来源绑定 241/262 | 应为 262/262；21 条 `generated_source` 被误判为未绑定 |
| 82/86 与 86/86 矛盾 | 不矛盾：82 是 facts（74 + 8），86 再加 4 条语义规则 |
| 20/22 = 0.909 | 是产出率，不是准确率；准确率需人工真值，记为 unavailable |

### 任务 E：三协议整链影子回归

| 协议 | Norm | Canonical 映射 | Fact | 中枢构建 | 行级证据 |

## 三、本轮发现的两个环境问题

1. **护栏会改写受版本管理的缓存文件**：`tests/extraction/test_llm_diagnostics.py` 多处调用 `_extract_blocks("rtsp", ...)`，把桩数据写进真实路径 `derived/cache/source_blocks/rtsp.prose.json`；三次运行的 `block_hash` 互不相同，`model` 字段被落成 `deepseek-chat`。护栏的"树静止"只比对源码 mtime，未覆盖 `derived/`，因此没报警。已用 `git checkout --` 恢复，未改用例。
2. **冻结散文缓存是抽取输入的一部分**：`DHCPv4.prose.json` 一旦被裁剪，DHCPv4 从 92 条降到 73 条，零产出从 19 变 24。本轮先恢复缓存再重跑，才复现出与 R25 一致的 92。

## 四、结论

1. 任务 A、B 的影子改动在隔离副本内成立，且不影响 Norm 集合与 content；进生产的前置条件是 EvidenceID 迁移与双读落地。
2. 任务 C 的 19 份零产出已逐条归因，其中 12 份的修复成本最低（读取端补 `name`），且不需要新增 LLM 调用。
3. 任务 D 的三处口径问题均属"分母不同"或"概念混用"，已在文档中给出可复算的拆解。
4. 任务 E 的整链在确定性通道上通过；LLM 通道整轮未执行，因此不能宣称整链在含 LLM 的配置下同样通过。

## 五、限制

1. 无 `DEEPSEEK_API_KEY`，239 条用例 skip，LLM 通道与 LLM 状态机未验证。
2. 行号精度（65 条空行）与 EvidenceID 稳定性互相牵制，未做回退修复。
3. 任务 B 在真实语料上零触发，缺少生产语料的正面证据。
4. 未做种子生成与 GraphRAG 的下游回归。

## 六、下一步

2. 在读取端补 `name` 缺省，把 12 份 LLM 缺口文档转为有产出，并核对新增的 `norm_id` 是否合理。
