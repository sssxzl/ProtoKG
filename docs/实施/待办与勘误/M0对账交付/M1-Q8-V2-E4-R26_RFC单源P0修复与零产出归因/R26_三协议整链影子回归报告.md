# R26 任务 E：三协议整链影子回归报告

## 一、方法

链路：RFC 原文 → Document Parser → Chunk → 确定性抽取 → 分类 → Norm → Canonical 映射 → RFC-only 中枢。

隔离方式：生产基线与影子补丁各用一份独立工作副本（`_ci_work_prod`、`_ci_work_shadow`），副本内含 `core`、`scripts`、`profiles`、`fused_hub`、三协议 `kb` 与冻结的 LLM 散文缓存。影子副本覆盖了含任务 A（行号化）与任务 B（field_value 修复）的 `rfc_extractor.py`。

`llm=None`，未发起任何 LLM 调用；`DEEPSEEK_API_KEY` 已从环境移除。

## 七、与上一轮失败记录的关系

上一轮 `pipeline_regression.json` 记录的是失败结果：三协议 Canonical 映射全部因内联 `python -c` 的引号与续行问题报 `SyntaxError`，中枢构建 rtsp/DHCPv4 退出码 1、smtp 产出 0 文件，并记录了 `derived/hub` 13 变 1、`derived/per_source` 173 变 155 的变化。那份记录对应的是影子 `paths.py` 硬编码真实仓库路径的事故状态。

本轮做了三项修正：内联脚本改为临时文件执行；隔离副本只带三协议 `kb` 与冻结缓存，不再整体复制；工作副本改为"覆盖写 + 只清 derived 运行产物"，避免批量删除触发环境保护。旧失败记录保存在 `guard/_out/_n1c_v2/r26/_recovery/pipeline_regression_失败记录_20261118.json`，作为事故留档。

## 八、限制

1. 本轮 LLM 通道未执行（无 key），prose 通道只用冻结缓存，因此"整链"仅覆盖确定性通道加历史缓存能映射的部分。
2. DHCPv4 的 92 条依赖冻结缓存 `DHCPv4.prose.json`（76 条）。该缓存缺失时 DHCPv4 降为 73 条，其它数字不变。
3. 65 条行号落在空行，属精度问题，未在本轮修复。
4. 未做种子生成与 GraphRAG 的下游回归，本轮链路止于 RFC-only 中枢。
