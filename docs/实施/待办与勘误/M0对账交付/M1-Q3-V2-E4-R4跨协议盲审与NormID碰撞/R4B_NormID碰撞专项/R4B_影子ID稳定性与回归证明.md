# R4B 影子 ID 稳定性与回归证明

## 一、已验证事实

影子实现位于 `guard/_out/_n1c_v2/r4/shadow_norm_id.py`，**不修改生产标识符生成逻辑**，★ 影子 ID 不写入 canonical Fact。

### 1.1 唯一性

| 集合 | 记录数 | 现行 | 方案 A | 方案 B | 方案 C |
|---|---:|---|---|---|---|
| R3 | 57 | 55 唯一 | 57 唯一 | 57 唯一 | 57 唯一 |
| H1 | 156 | 116 唯一 | 156 唯一 | 156 唯一 | 156 唯一 |

### 1.2 稳定性

| 检查 | 结果 |
|---|---|
| 方案 A 重复运行一致 | ✔ R3 与 H1 均成立 |
| 方案 A 候选顺序无关 | ✔ R3 与 H1 均成立 |
| 方案 B 重复运行一致 | ✔ R3 与 H1 均成立 |
| 方案 B 候选顺序无关 | ✔ R3 与 H1 均成立 |

实现要点：三个方案的键均由文档标识、起始行与语义载荷的 SHA256 前 8 位构成，★ 不含序号、不含时间戳、不含随机成分。

### 1.3 语义载荷的区分能力

语义载荷包含 kind、entity、meaning、constraint、action、object、strength、polarity、condition、exception 十项。R3 的 3 条碰撞记录与 H1 的 16 个碰撞组中，★ 组内成员的语义载荷哈希全部不同，★ 说明这些记录确为不同知识命题。

## 二、推论

1. 现行 `kind + entity` 不足以标识一条候选，★ 因为同一实体可以承载多条不同命题。
2. 引入文档与跨度维度即可消除跨文档与同文档的碰撞；★ 引入语义载荷哈希可进一步区分同一跨度内的不同命题。
3. 三个方案都满足可复算要求，★ 不需要随机 UUID。

## 三、限制

1. 影子实现未接入生产路径，★ 其稳定性结论基于冻结的 R3 与 H1 数据，★ 未在其他数据集上验证。
2. 语义载荷依赖字段齐全。★ R3 的 57 条中 constraint 非空 23 条、exception 非空 2 条，★ 字段缺失时载荷哈希的区分能力下降，★ 但因文档与跨度维度仍在，★ 唯一性不受影响。
3. 影子 ID 的生成位置未定：★ 放在 norm 构造处还是 Fact 映射处，★ 影响方案 A 与 B 的实施范围。
