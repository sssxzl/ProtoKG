## 二、方案 A：source-scoped 确定性 Norm ID

组成：`kind + entity + 文档标识 + 起始行 + 语义载荷短哈希`。

| 评估项 | 结论 |
|---|---|
| 是否消除不同知识的碰撞 | ✔ R3 与 H1 碰撞均为 0 |
| 跨文档唯一性 | ✔ 文档标识参与 |
| 同文档唯一性 | ✔ 起始行与语义载荷哈希参与 |
| 同一原文跨度多条规则 | ✔ 语义载荷哈希区分，★ 但**跨度相同且语义载荷相同则仍碰撞**（★ 实际是同一命题的重复） |
| 重复运行确定性 | ✔ 无随机成分 |
| 候选顺序变化影响 | ✔ 无 |
| 对旧缓存与旧记录影响 | ★ 旧记录的 norm_id 不变，★ 新键仅对新抽取生效 |
| 对 Norm 下游引用影响 | ★ 直接改 `norm_id` 会改变 `Evidence.source_id`，★ 连带影响 evidence_id |
| 对 canonical FactID 影响 | ★ **需核对**。★ FactID 是否含 evidence_id 决定影响范围，★ 本轮无 canonical 视图，★ **无法判定** |
| 对中枢与 Seed 影响 | ★ 同上，★ 无法判定 |
| 兼容读取旧 ID | ★ 需保留旧字段或映射表 |
| 回归风险 | 中 |
| 回滚 | 恢复 `prose_semantics.py:1208` 一行 |
| 需历史重建 | ★ 否（★ 旧记录保留原 norm_id） |

## 三、方案 B：新增独立稳定唯一标识，保留旧 norm_id

| 评估项 | 结论 |
|---|---|
| 是否消除不同知识的碰撞 | ✔ norm_uid 唯一性 100% |
| 跨文档与同文档唯一性 | ✔ 文档、跨度、语义载荷三者参与 |
| 同一原文跨度多条规则 | ✔ 语义载荷哈希区分 |
| 重复运行确定性 | ✔ |
| 候选顺序变化影响 | ✔ 无 |
| 对旧缓存与旧记录影响 | ★ **最小**，★ 旧记录无需改写，★ 消费者按需读取 |
| 对 Norm 下游引用影响 | ★ **零**，★ `norm_id` 不变，★ `Evidence.source_id` 不变 |
| 对 canonical FactID 影响 | ★ **零**（★ 只要 FactID 计算不含 norm_uid） |
| 对中枢与 Seed 影响 | ★ **零** |
| 兼容读取旧 ID | ✔ 天然兼容 |
| 回归风险 | 低 |

| 需历史重建 | ★ 否 |

## 五、方案比较与建议

| 维度 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 消除碰撞 | ✔ | ✔ | ✔ |
| 对 canonical FactID 影响 | ★ **无法判定** | ★ 零 | ★ 零 |
| 对中枢与 Seed 影响 | ★ **无法判定** | ★ 零 | ★ 零 |
| 下游引用兼容性 | ★ 需适配 | ★ 天然兼容 | ★ 需消费者配合 |
| 回归风险 | 中 | 低 | 最低 |

**建议**：先实施方案 C 作为**影子 sidecar**，用它为 R3 的 57 条与 H1 的 156 条建立复合索引映射，并据此核对 evidence_id 是否实际重复。确认后再决定是否需要方案 B 把复合索引提升为正式字段。

**明确不做**：不采用随机 UUID，那会牺牲可复算性。不修改 21 aspects、Rule Slot 或 Assertion 身份设计。不直接修改现有 norm_id 生成逻辑。

## 六、限制

1. 三个方案的 canonical FactID 与中枢影响均以「未取得真实 canonical 视图」为前提，★ **不能据此判定影响为零**。
2. 方案 A 对 `Evidence.source_id` 的影响会改变 evidence_id，★ 该链路是否参与 FactID 计算需在生产侧核对。
