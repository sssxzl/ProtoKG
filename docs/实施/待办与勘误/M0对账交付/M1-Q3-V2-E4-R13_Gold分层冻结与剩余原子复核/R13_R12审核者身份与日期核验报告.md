### 1.2 ★ R11 审核者是否为原盲审者 A

**核验结论**：★ 极可能是同一人，★ 或至少共享同一判断来源

**决定性旁证**：

- ★ R11 审核意见称「§4.4 第489行」为 ENVID 属 MAIL 命令参数的出处
- ★ R11 审核意见称 ORCPT 属 RCPT 命令参数（§4.2 第403行）
- ★ 查 R4A 审核者 A 对 3461-05 的理由：★ 明确写有「ORCPT 本属 RCPT 命令参数」
- ★ 查 R4A 审核者 B 对 3461-05 的理由：★ 无「RCPT 命令参数」这句
- ★ ⇒ 该具体判断只出现在审核者 A 的记录里，★ 而 R11 的审核意见使用了它

**推论**：★ R11 复核的候选（★ 3461-04 与 6531-01）★ 正是原盲审者 A 参与判断的候选，
★ 而 R11 的论证使用了审核者 A 记录里的独有表述与行号定位。
★ 因此 R11 的裁定**不满足独立审核要求**。

### 1.3 匿名编号不同即可推定独立

★ 不可。★ 编号相同且论证内容高度重叠，★ ★ 应按不独立处理，★ 须由 C 或 F 确认

★ 编号相同（均为 A）★ 且论证内容高度重叠，★ 两者相互印证，★ 不能按「不同编号即独立」处理。

### 1.4 ★ C 是否已裁定 SC-05/SC-06 的最终边界

**核验结论**：★ 否。★ C 裁定了「宜拆两条」，★ 但未裁定 ORCPT 条是否与候选 3461-05 重复、★ 也未裁定两个术语条目是否同义

★ C 的两条原始裁定原文：
- X-smtp-rfc3461-04：「ENVID 与 ORCPT 共享同一 MAY，宜拆两条；『新生成 envelope-id』
  是本条可执行的关键限定，规范化时须保留。」
- X-smtp-rfc6531-01：「规范化时可把两个术语拆成两条术语条目，并保留『可能是也可能不是
  ASCII 子集成员』这一关键限定。」

★ 二者均**未裁定**：★ ORCPT 条是否与候选 X-smtp-rfc3461-05 重复；★ 两个术语条目是否同义。
★ 这两个问题恰是 R12 排除两条的判断依据，★ **须由 C 或 F 确认**。
