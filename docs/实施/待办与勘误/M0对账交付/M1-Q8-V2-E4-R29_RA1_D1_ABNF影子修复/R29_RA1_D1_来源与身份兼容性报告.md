# R29 RA-1 D1 来源与身份兼容性报告

## 一、来源

| 项 | 值 |
|---|---|
| 来源字段 | `file:<rfc>#@<line>`，与既有 Norm 同格式 |
| 行号基准 | `split("\n")`，与 `documents.json` 及 Gold 一致 |
| 行号一致性 | 10 / 10 Gold 精确命中起始行 |
| 文件 SHA256 | 与 R25 冻结清单一致（121/121，R28-C 已核） |

## 二、身份

| 项 | 现状 |
|---|---|
| NormID | `protocol.syntax_production.<name>`，新命名空间 |
| FactID | 未产生（映射未接线） |
| EvidenceID | 未产生 |
| Claim/Assertion | 未涉及 |
| subject type | 影子未定义，因未映射所以未落地 |

关键结论：**这 156 条 Norm 目前只有 Norm 层身份，没有 Canonical 身份**。它们不进中枢、不影响 Seed，也不改变既有 FactID/EvidenceID。

## 三、与既有身份的关系

| 检查 | 结果 |
|---|---|
| 是否覆盖既有 NormID | 否（kind 段不同） |
| 是否与既有 Fact 冲突 | 否（无 Fact） |
| 是否改变 EvidenceID 规则 | 否 |
| 是否改变 21 aspects | 否 |
| 是否改变 Canonical Schema | 否 |

## 四、正式化时需要解决的三个身份问题

1. **新 kind 的注册位置**：`RFC_KIND_MAP` 需要登记，否则永远 0 Fact。
2. **subject type 的选择**：`header` 语义不成立；若新增 `syntax_rule`，等于新增一类知识身份，需明示。
3. **aspect 的语义**：`syntax` 现用于头字段语法（pattern 值）。语法产生式能否复用同一 aspect，属设计判断，不是工程默认。

## 五、兼容性建议

| 方案 | 身份影响 | 建议 |
|---|---|---|
| 只保留 Norm 层，不进 Canonical | 无 | 可作为「影子知识层」长期存在，但下游用不到 |
| 新增 kind + `syntax_rule` subject | 新增身份类 | 需正式契约变更审批 |
| 塞进 header | 语义错 | 不建议 |

## 六、限制

1. 未验证中枢构建时对未知 kind 的处理路径以外的行为（本轮未构建 hub，因 0 Fact）。
2. 156 条的产生式命名空间没有与历史 Gold 的 candidate_id 做映射，只做了名称级比对。
