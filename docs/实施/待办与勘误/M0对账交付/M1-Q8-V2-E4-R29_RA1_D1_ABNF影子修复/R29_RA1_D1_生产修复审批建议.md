# R29 RA-1 D1 生产修复审批建议

## 一、建议

**不建议按当前形态合入。** 影子在 Norm 层恢复了 10/10 历史 Gold，但没有 Canonical 映射，一旦合入会多出 156 条「只有 Norm、没有 Fact」的知识条目，等于在数据层留半成品。

建议分两步：

1. 先批「契约变更」（新增 kind 与 subject type，或明确复用 header 的语义妥协），再谈合入。
2. 契约定了之后，按本文的补丁与测试重跑一遍，再申请。

## 二、需要项目方决定的三件事

| 编号 | 决定 | 选项 |
|---|---|---|
| Q1 | 语法产生式是否算「知识」 | 算（进 Canonical）/ 不算（只留 Norm 层） |
| Q2 | 若算，用哪种身份 | 新增 `syntax_rule` subject / 复用 header（语义错，不建议） |
| Q3 | 156 条是否全部接收 | 全收 / 只收被 Gold 覆盖的族（NPT、atext、auth-param 等）/ 先人工抽检再定 |

## 三、合入前必须补的工作（若 Q1/Q2 通过）

| 项 | 说明 |
|---|---|
| 映射实现 | `syntax_production_norm_to_facts`，aspect=`syntax`，value=pattern |
| 中枢回归 | 三协议 hub 构建 + 与 main 对比新增桶/行数 |
| 数量解释 | 156 条逐条可解释（本轮已按文档归因，可复用） |
| 质量抽检 | 至少人工看 20 条右部是否完整（本轮只做了 8 类负例） |
| 回滚 | 移除 `_extract_abnf_productions` 与调用块，Norm 数回落 |

## 四、不建议的做法

1. 不要为了「让 Fact 数变多」直接把 kind 塞进 field 映射。
2. 不要在没有中枢回归的情况下合入——中枢的行数与桶分布会变。
3. 不要把 10/10 命中当作验收通过，它只是历史回归。
