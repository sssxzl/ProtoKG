## 一、正向：10 条历史 Gold 回归

| 结果 | 条数 |
|---|---|
| 完整识别（Norm 级） | 10 / 10 |
| 部分识别 | 0 |
| 未识别 | 0 |
| 误拆分 | 0 |
| 误合并 | 0 |
| 与既有知识重复 | 0 |
| 无法兼容映射 | 10（全部，因映射未接线） |

逐条行号一致性：10 / 10（source 的 `#@line` 与 Gold 起始行完全相同）。明细见 `R29_RA1_D1_10条Gold逐条核验表.xlsx`。

注意：这 10 条是已接触过的历史 Gold，只能算历史回归，不能宣称独立泛化准确率。

## 二、反向：8 类负例

| # | 场景 | 判据 | 结果 |
|---|---|---|---|
| 1 | 目录行（点引导） | 不得抽 | PASS |
| 2 | 散文里的等号（"set timeout = 30 seconds"） | 不得抽 | PASS |
| 3 | 跨行续写 | 右部完整保留 | PASS |
| 4 | `;;` 注释续行 | 不并入右部 | PASS |
| 5 | C 代码行（`hash = loadb_mx_tbl ... return(...)`） | 不得抽 | PASS |
| 6 | 与既有 field/method 同名 | 不重复产出 | PASS（三协议 0 重复） |
| 7 | 辅助产生式 | 保留（npt-time 等被引用规则） | PASS |
| 8 | 新建 Norm 是否产出 Fact | 必须为 0（映射未接线） | PASS |

脚本：`scripts/d1_checks.py`，输出 8 个 PASS。

## 三、开发过程中被这三类负例拦下的真实错误

这一段必须记录，否则「8 个 PASS」看起来像是设计出来的：

| 错误 | 现象 | 修正 |
|---|---|---|
| 续行吞掉 `;;` 注释 | `auth-param` 右部混入 7 行说明，被句子判据拒掉，导致 9/10 | 续行遇到 `;;` 即停 |
| 引号内的 `{` `}` 被当代码 | `atext` 定义含 `"{"`，整条被误杀 | 先剥引号字面量再判代码特征 |
| 散文 "MTU = Path MTU Discovery" 被抽 | DHCP 出现伪产生式 | 增加英文句子判据 + 名字必须小写 |

## 四、已知残留风险

| 风险 | 现状 |
|---|---|
| 有注释的合法产生式仍可能被判为「句子」 | 已用「强特征 + 非句子」放行，未穷举 |
| 同一规则名在不同 RFC 重复 | 按 norm_id 去重，只保留首个；这是既有行为，未改 |
| 表格/位图里的 `=` | 未单独造例，靠句子判据兜底 |

## 五、结论

10/10 命中不能作为「D1 修复通过」的依据：命中只证明正则能抓到，映射仍缺位，且契约变更未批。合规的说法是：影子在 Norm 层恢复了这 10 条，Canonical 层恢复数为 0。
