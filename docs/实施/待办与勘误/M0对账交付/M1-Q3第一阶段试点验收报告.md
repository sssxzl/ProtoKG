## 〇、★ 前置检查：M1-Q2 证据引用一致性（★ 发现并修正了真实错配）

### 0.1 你指出的三处疑点 —— 全部成立

| 你的指正 | 核查结果 |
|---|---|
| `raw_span=15` 换算锚点是 **10466**，但验收报告用 **10464** 的文本判断 `action=include` 不受支持 | ✔ **成立且属实**。锚点行 10466 = 「field.  The server **MUST include** a list of the unsupported extensions」⇒ ⇒ **原文明确支持该动作** ⇒ ⇒ **M1-Q2 报告的归因【错了】** |
| `raw_span=27/31/34/36` 的换算锚点与报告展示的证据行存在偏移 | ✔ **成立**：锚点分别是 10478/10482/10485/10487，报告展示的是匹配行 10479/10483/10486/10488（**各差 +1 行**） |
| 416 状态码的章节号在报告与冻结块中不一致 | ✔ **成立**：报告写 `21.4.15 416 Unsupported URI Scheme`，实际冻结块该行是 **`21.4.15 420 Bad Extension`**；`416 Unsupported URI Scheme` 的章节号应为 **21.4.14** ⇒ ⇒ **报告的章节号错配** |

### 0.2 ★ 根因：★ 「锚点」与「匹配行」被混为一谈

M1-Q2 的 `resolve_span_evidence()` 返回的 `resolved_span` 是
**`entity_in_span()` 在 ±3 窗口内首次匹配到的行**，★ **不是**「LLM 指定的位置（锚点）」。
⇒ ⇒ L1/L2 的 quote 因此取的是「entity 首次出现行」
⇒ ⇒ 例：`server`（raw_span=15，锚点 10466）⇒ matched=10464（"did not understand"）
⇒ ⇒ ⇒ ★ **L2 拿到的是错的证据行 ⇒ ⇒ 「server MUST include」这条被【误拒】**

### 0.3 ★ 修正（★ 已实施并加回归测试）

| 概念 | 修正后语义 |
|---|---|
| `resolved_span` | ★ **锚点行**（absolute: `raw_span`；relative: `chunk_start + (raw_span − 1)`） |
| `matched_evidence_lines` | ★ entity 在 ±3 窗口内的匹配行（★ **辅助字段**，不改窗口） |
| `quote_span` | ★ `[min(anchor, matched) .. max(anchor, matched)]` ⇒ **L1/L2 的证据窗口** |

★ **entity 校验窗口本身未变（仍是 ±3）** ⇒ ⇒ 不违反「不允许通过扩大邻近行窗口提高候选通过率」

★ **回归测试**：`tests/extraction/test_span_anchor_alignment.py`（6 个）⇒ ★ **锁死 `server MUST include` 这条真误伤**
（断言 `span_line == 10466`、`span_matched_line == 10464`、L2 的 quote 同时含 `MUST include` 与 `did not understand`）

### 0.4 ★ 关于 `span_mode_counts={}` 的含义（★ 你问的第二点）

| 口径 | 含义 | 数值 |
|---|---|---|
| `span_mode_counts` | ★ **拒收时**的解释模式计数（★ 只有拒收才计数） | `{}` ⇒ ★ **该批 6 条全部通过实体核对，无拒收** |
| 「6 条相对恢复」 | ★ **离线重评**口径（★ 对比 OLD vs NEW 的**差异**） | 6 ⇒ ★ 6 条从「拒收」变为「接受」 |

⇒ ⇒ ★ **两个口径不同**：前者是「拒收分类计数」，后者是「修复前后差异」
⇒ ⇒ ★ **`{}` 不与「6」矛盾** ⇒ ⇒ **前者统计「现在还拒收什么」，后者统计「修复改变了什么」**

### 0.5 「server MUST include 是否实际进入 L2 校验上下文」

| 项 | 修正前 | 修正后 |
|---|---|---|
| L2 的 quote 行 | 10464（matched） | ★ **10464..10466（锚点↔匹配完整窗口）** |
| quote 内容 | "The server did not understand the protocol extension specified in a" | ★ "The server did not understand … Proxy-Require … **The server MUST include a list of the unsupported extensions**" |
| L2 判定 | **rejected**（动作不受支持）⇒ **误拒** | ★ **证据完整 ⇒ 交由 L2 按原文判断** |
