# R29 RA-1 阶段阻断原因统计

## 一、结论

32 条 syntax Gold **没有一条卡在 Chunk 上**。它们全部卡在「抽取器不建模这类结构」，具体分两种：29 条是结构类型本身没有解析器，3 条是同族结构已建模但该子命题未产出。

## 二、关键前提：确定性通道不看 Chunk

| 事实 | 证据 |
|---|---|
| `core/fused/extraction/rfc_extractor.py` 全文没有 `chunk` 字样 | `grep -n chunk` 返回空 |
| 分块只被散文通道使用 | `block_selection.py` / `block_budget.py` 的调用方只有 `prose_semantics.py` |
| 确定性通道按整文件行扫描 | `_extract_rfc_file()` 读取全文 `content_lines` |

因此本轮把 Chunk 状态记为 `not_applicable`，不是「未覆盖」。任务书列出的 `chunk_covered_*` / `chunk_not_covered` / `chunk_created_but_not_selected` 这四类，在确定性路径上不成立；只有散文通道才会出现。

## 三、逐阶段统计（单位：条，分母 32）

| 阶段 | 状态 | 条数 |
|---|---|---|
| 原文可定位 | 是 | 32 |
| Parser 文件级解析 | ok（行可重建） | 32 |
| Parser 段落级覆盖 | unavailable（无分块/段落日志） | 32 |
| Chunk 完整覆盖 | not_applicable | 32 |
| Chunk 部分覆盖 | not_applicable | 32 |
| 未进入抽取窗口 | 0（整文件都在窗口内） | 0 |
| 进入窗口但抽取器不建模该结构 | unsupported_syntax_structure | 29 |
| 进入窗口、结构已建模、该子命题无候选 | extractor_invoked_no_candidate | 3 |
| Raw 有候选但未到 Norm | 0 | 0 |
| 无法确认 | 0 | 0 |

## 四、29 条 unsupported 的构成

| 形态 | 条数 | 说明 |
|---|---|---|
| ABNF 语法产生式 | 10 | `npt-range`、`npt-time`、`atext`、`specials`、`auth-param` 等；现有 ABNF 通道只解头字段与方法，不解通用产生式 |
| 散文形式的结构描述 | 19 | 「按八位组顺序传输」「按图中编号顺序」这类规则，无 ABNF、无表格、无位图 |

ABNF 产生式确认未被误当字段：机器 Norm 中不存在 `atext`/`npt-*`/`specials`/`auth-param` 任何同名条目。

## 五、3 条 invoked_no_candidate 的构成

| gold_id | 形态 | 同文档已产出的同族条目 |
|---|---|---|
| rfc1542:200-208 | 位图 + 表格（报头字段编号） | `binary_layout` 已产出该报头布局 |
| rfc2132:628-635 | 选项子字段表 | `option_layout.netbios_over_tcp/ip_datagram_distribution_server` |
| rfc2132:847-854 | 选项子字段表 | `option_layout.perform_router_discovery` 系列 |

这三条说明：布局条目抽到了，但「子字段排列规则」这层命题没抽到。

## 六、分布

| 文档 | 缺口条数 |
|---|---|
| DHCPv4 rfc2132 | 10 |
| rtsp rfc2326 | 9 |
| smtp rfc5322 | 6 |
| smtp rfc4954 | 3 |
| DHCPv4 rfc1542 | 2 |
| smtp rfc5321 | 2 |

6 份文档中 4 份有同族结构产出，说明抽取器在这些文档上**确实执行过**，不是「没跑」。

## 七、不能下的结论

1. 不能说「Parser 有缺陷」——文件级解析全部正常，段落级无日志，标 unavailable。
2. 不能说「Chunk 覆盖不足」——确定性路径没有 Chunk 概念。
3. 不能说「函数执行了但没识别」——29 条是结构类型没有对应解析器，不是识别失败。
