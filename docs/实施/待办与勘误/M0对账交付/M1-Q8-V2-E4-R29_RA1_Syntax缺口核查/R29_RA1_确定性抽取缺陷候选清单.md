# R29 RA-1 确定性抽取缺陷候选清单

只登记本轮有证据的候选缺陷，按影响面排序。每条给出证据、影响条数、修复形态、风险。本轮不实施。

## D1 ABNF 语法产生式不被建模（10 条）

| 项 | 内容 |
|---|---|
| 证据 | 10 条跨度形如 `npt-range = ( npt-time "-" [ npt-time ] ) / ...`、`atext = ALPHA / DIGIT / ...`、`auth-param = "AUTH=" xtext`；机器 Norm 中无任何同名条目 |
| 代码事实 | `_extract_abnf_fields()` 只把「看起来像头字段名」的 ABNF 行转成字段；`_extract_abnf_methods()` 只抽方法。通用产生式既不是字段也不是方法，被跳过 |
| 影响 | RTSP 7 条（NPT 时间族）、SMTP 3 条（xtext/atext/specials） |
| 修复形态 | 新增「语法产生式」知识类型：name=产生式名，content=右侧 ABNF，kind=`syntax_production`；不做语义解释 |
| 风险 | 会让 Norm 数从 262 上升；需要确认 kind 与 aspect 映射不破坏 21 aspects（必须落在既有 aspect 内） |
| 建议 | 先做影子验证，观察新增条数；不改变既有条目 |

## D2 结构「规则」以散文表达，无解析器（19 条）

| 项 | 内容 |
|---|---|
| 证据 | 跨度是纯散文，例如 rfc1542:193「传输顺序按八位组」、rfc2132:189「所有选项以 tag 八位组开始」 |
| 影响 | DHCPv4 12 条、RTSP 2 条、SMTP 5 条 |
| 判据 | 这些句子含 MUST/SHOULD 或陈述性规则，属「规范规则 + 结构说明」的混合，确定性通道无法用 ABNF/表格解析 |
| 修复形态 | 归入散文通道（RA-2），不建议在确定性通道写正则硬抽 |
| 风险 | 用正则抽英文句子会引入大量误抽；不宜作为确定性修复 |
| 建议 | 不做确定性修复；登记为散文通道需求 |

## D3 选项/报头子字段布局规则未产出（3 条）

| 项 | 内容 |
|---|---|
| 证据 | 同文档已有 `option_layout.netbios_over_tcp...`、`binary_layout`（rfc1542 报头），但子字段顺序这条命题没有条目 |
| 影响 | DHCPv4 3 条 |
| 修复形态 | 在 option_layout/binary_layout 中增加「子字段序列」字段（若 schema 允许），或新增一个只描述顺序的 kind |
| 风险 | 触碰 Canonical 结构的可能性最高，须先做契约评估 |
| 建议 | 优先级低于 D1；先确认能否用现有字段承载 |

## 二、按影响排序

| 排序 | 缺陷 | 条数 | 改动面 | 是否触碰契约 |
|---|---|---|---|---|
| 1 | D1 ABNF 产生式 | 10 | 抽取器新增一种 kind | 需确认 aspect 映射 |
| 2 | D2 散文规则 | 19 | 属散文通道 | 否（但需 LLM） |
| 3 | D3 子字段顺序 | 3 | 布局类扩展 | 可能触碰 |

## 三、不建议的做法

1. 不要为这 32 条写特例正则——会把一次核查变成 32 个补丁。
2. 不要把 D2 硬塞进确定性通道——英文句子正则抽取的历史教训（R14 误拒）已说明代价。
3. 不要在 D1 未定 kind/aspect 之前改代码——会连带影响 21 aspects 与 Canonical 契约。
