# R15 输入字段与 Gold 契约一致性检查

> ★ 检查 V2 判据的输入是否充分、★ Gold 的类型契约是否与判据一致

---

## 一、已验证事实

### 1.1 输入字段充分性

| 项 | 值 |
|---|---:|
| 57 条中机器 meaning 为空 | 0 条 |
| 57 条中机器 constraint 为空 | 34 条 |
| 两者均空 | 0 条 |

★ **D 类（输入适配问题）不是本批错误的主因**：★ 全部 57 条都有 meaning，
★ 判据的输入可用。

### 1.2 Gold 侧的类型分布

| Gold 类型 | 条数 |
|---|---:|
| non_protocol_metadata | 8 |
| normative_rule_candidate | 26 |
| protocol_descriptive_semantics | 11 |
| protocol_registry_or_enumeration | 2 |
| protocol_syntax | 10 |

★ Gold 侧 `mixed_or_uncertain` 为 0 条，★ 即人工认为「不确定」的样本，
★ 机器侧未能产出对应的不确定判定。

### 1.3 契约一致性

| 契约点 | V2 判据 | Gold | 是否一致 |
|---|---|---|---|
| ★ 规范义务的判定依据 | ★ 要求 BCP14 强度词，★ 否则 strength=unknown | ★ 允许无强度词的行为义务句（★ 12 条） | **不一致** |
| ★ strength=unknown 的含义 | ★ 归入 `mixed_or_uncertain`（★ 不确定类型） | ★ 强度待定但类型仍可为规范义务 | **不一致** |
| ★ 路由由类型派生 | ★ 是 | ★ 是 | 一致 |
| ★ 描述性 / 元数据 / 语法的排除 | ★ 有明确判据 | ★ 同 | 一致 |

★ **核心不一致点**：`strength=unknown` 在 V2 中被当作「类型不确定」，
★ 而在人工 Gold 的契约里它只是「强度待定」。★ 这是一条可精确表述的契约分歧，
★ 不需要判断谁对谁错。

### 1.4 原文证据充分性

★ 全部 39 条含错误候选的原文证据均已取回并逐条附在《R15_57条候选分类错误归因.xlsx》
★ 的「RFC 原文证据」列，★ 未出现证据缺失导致无法归因的情形。
★ **G 类（原文证据不足）不成立。**

## 二、推论

1. ★ 契约不一致集中在**一处**：★ `strength=unknown` 的语义。
2. ★ 若该处对齐，★ 类型与路由两项指标同时改善；★ 资格维度需单独评估。

## 三、限制

1. ★ 本检查基于已接触的 57 条。
2. ★ 未对 Gold 的类型判定本身做独立复核，★ 只检查其与判据的契约关系。
