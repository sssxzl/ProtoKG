# R15 V2 分类判据的最小兼容改进方案

> ★ **本文件只提出方案，★ 不修改冻结 V2 判据**
> ★ R14 首次评估结果保持冻结，★ 未重算

## 一、已验证事实

### 1.1 问题的精确表述

★ R14 中 15 条机器预测为 `mixed_or_uncertain`，★ 全部同一判据理由：
★ 「陈述式规范句（★ 条件从句 + 协议行为动词 + 协议参与方主体，★ 但无 BCP14 强度词）
★ ⇒ 适用规范规则通道，★ strength = unknown（★ 不擅自提升为 MUST）」。

★ **判据内部存在一处自相矛盾**：★ 它已判定「适用规范规则通道」（★ 即认定为规范义务），
★ 却因强度未知而归入「类型不确定」。

★ 这不是强度词的识别失败，★ 而是 **`strength=unknown` 的语义被复用为类型判定**。

### 1.2 三类样本的区分（★ 决定方案可行性的关键）

| 样本类 | 条数 | 现状 | 方案的影响 |
|---|---:|---|---|
| ★ 原文含 BCP14，★ Gold 为规范义务 | 12 | 判 mixed | ★ **应修复**（★ 判据漏识别 BCP14） |
| ★ 原文无 BCP14，★ Gold 为规范义务 | 0 | 判 mixed | ★ **需契约澄清**，★ 升级会引入反向误判 |
| ★ Gold 非规范义务类 | 3 | 判 mixed | ★ 判 mixed 合理，★ 不算错误 |

★ **因此「把 strength=unknown 一律升级为规范义务」是错的**：★ 它会修好
★ 0 条，★ 但把 3 条本来正确的判断改错。

### 1.3 反向误判的量化

★ 57 条 Gold 中属描述性、元数据、语法、枚举四类的共 **31 条**。
★ 若采用「一律升级」，★ 这些样本中原本被判 mixed 的部分会被错误升级。

## 二、候选方案

### 方案一：★ 修正 BCP14 关键词识别（★ 最小、★ 最可证）

| 项 | 内容 |
|---|---|
| ★ 1. 原始判据为什么出错 | ★ 判据在部分上下文中未命中 BCP14 关键词，★ 使本应识别为规范义务的候选落入 strength=unknown |
| ★ 2. 拟修改的规则或函数 | ★ `v2_knowledge_gate.classify_candidate` 中的 BCP14 匹配逻辑（★ **只改识别，不改类型契约**） |
| ★ 3. 影响的知识类型 | ★ 仅 `normative_rule_candidate` |
| ★ 4. 预计修复 | ★ 12 条（★ 原文确含 BCP14 的） |
| ★ 5. 可能新增误判 | ★ 极低：★ 只在原文真有 BCP14 时才改变 |
| ★ 6. 对资格与路由的连带 | ★ 类型修复后路由随之修复；★ 资格由 eligible 改为 uncertain 或反之 |
| ★ 7. 是否改变身份、Schema 或契约 | **否** |
| ★ 8. 回归风险与回滚 | ★ 低；★ 回滚即恢复 V2 判据文件（★ SHA256 `81566fb71905e313…`） |
| ★ 9. 是否需新协议独立验证 | ★ **需要**：★ 修复后的判据须在未参与归因的样本上验证 |

★ **这是本方案中证据最强的一项**：★ 它只修「没看到关键词」，★ 不动「关键词缺失如何归类」的契约。

### 方案二：★ 分离「强度未知」与「类型不确定」（★ 需契约变更）

| 项 | 内容 |
|---|---|
| ★ 1. 原始判据为什么出错 | ★ `strength=unknown` 同时承担「强度待定」与「类型不确定」两个含义，★ 二者在本批样本上恰好冲突 |
| ★ 2. 拟修改的规则或函数 | ★ ★ **不改 V2 判据本身**，★ 而是修改 Gold 与 V2 之间的契约：★ 约定 `strength=unknown` 不再触发 `mixed_or_uncertain` |
| ★ 3. 影响的知识类型 | ★ `normative_rule_candidate` 与 `mixed_or_uncertain` 之间的边界 |
| ★ 4. 预计修复 | ★ 0 条（★ 原文无 BCP14 但为行为义务的） |
| ★ 5. 可能新增误判 | ★ **较高**：★ 无 BCP14 的描述性陈述句会被误升为规范义务；★ 本批中有 3 条现判 mixed 的样本属此类 |
| ★ 6. 对资格与路由的连带 | ★ 资格由 uncertain 变为 eligible；★ 路由由 pending_review 变为 rule_channel |
| ★ 7. 是否改变身份、Schema 或契约 | **是**（★ 改契约） |
| ★ 8. 回归风险与回滚 | ★ 中；★ 需要新的判据版本 |
| ★ 9. 是否需新协议独立验证 | ★ **必须**：★ 这是定义级变更 |

### 方案三：★ 引入第三态「强度未定的规范义务」（★ 结构最干净）

| 项 | 内容 |
|---|---|
| ★ 1. 原始判据为什么出错 | ★ 六类体系里「类型」与「强度」耦合，★ 缺一个中间态 |
| ★ 2. 拟修改的规则或函数 | ★ V2 判据新增 `normative_rule_candidate_strength_unknown`，★ 路由仍为 `rule_channel` 但资格另设 `eligible_strength_unknown` |
| ★ 3. 影响的知识类型 | ★ 新增一类；★ `mixed_or_uncertain` 保留给真正无法判定的情形 |
| ★ 4. 预计修复 | ★ 0 条 |
| ★ 5. 可能新增误判 | ★ 中；★ 需要独立的判定边界，★ 但不与描述性陈述混淆 |
| ★ 6. 对资格与路由的连带 | ★ 资格枚举需新增取值；★ 路由不变 |
| ★ 7. 是否改变身份、Schema 或契约 | **是**（★ 改标签集合与 Schema） |
| ★ 8. 回归风险与回滚 | ★ 中高；★ 需新版本判据 |
| ★ 9. 是否需新协议独立验证 | ★ **必须** |

### 2.2 推荐路径
