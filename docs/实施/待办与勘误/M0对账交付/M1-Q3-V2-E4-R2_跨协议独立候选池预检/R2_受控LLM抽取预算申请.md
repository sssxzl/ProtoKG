# R2 受控 LLM 抽取预算申请

## 一、申请摘要

本轮不执行任何 LLM 调用。以下为获得授权后的一次性受控抽取方案。

| 项 | 计划值 | 上限 |
|---|---:|---:|
| RFC 文档 | 8 | 9 |
| 原文块 | 16 | 18 |
| 实际 LLM 请求（含重试） | 约 16 | 18 |
| 输入加输出 token 合计 | 预计 40000 | 120000 |
| 费用（USD，deepseek-flash 闲时价） | 预计 0.03 | 0.05 |

上限取自用户授权：最多 9 份文档、18 次请求、120000 token、0.05 USD。任一上限先达到即停止。

## 二、冻结项

| 项 | 值 | 来源 |
|---|---|---|
| 模型 | deepseek-flash (DeepSeek-V4.1-Flash-1017) | 与 V2-E4 试点一致 |
| Prompt | `core/fused/extraction/prose_semantics.py::_PROMPT` | 不新建 |
| Schema | 生产 prose_semantics schema | 不新建 |
| temperature | 0.1 | 与生产一致 |
| max_tokens | 4000 | 与 V2-E4 试点一致（生产默认 16000，此处下调以满足 token 上限，差异已记录） |
| 批大小 | 5 块/批（生产 `_BATCH_BLOCKS`） | 18 块约 4 批 |
| 抽取器代码版本 | 见提交哈希 | 不修改生产路径 |

## 三、块抽样规则

1. 每份文档按段落切分，取连续散文段，段落边界由空行与标题行判定。
2. 每段按 BCP14 强度词密度降序排列，但抽样时不只取高密度段：每份文档取 2 段，其中 1 段为密度最高的段，另 1 段从密度中位以下的段中抽取，以覆盖描述性知识与非协议元数据。
3. 每段长度上限 3500 字符，对齐生产 `_MAX_BLOCK_CHARS`。
4. 跳过所有与开发集、历史抽取窗口、队列 B 片段有行区间重叠的段。
5. 跳过与既有候选证据 5-gram Jaccard 大于 0.6 的段。
6. 随机种子固定为 20261116；输入按（协议，文档名，起始行）稳定排序。

## 四、来源身份完整性验证

每次抽取前校验：文档 source_sha256 与登记值一致；块起始行与行号映射一致；块文本 SHA256 与登记值一致。任一不符则跳过该块并记录原因，不做模糊匹配。

## 五、日志与产物隔离

1. 事件日志采用追加式记录，区分实际请求、缓存命中、离线重放三类。
2. 缓存目录重定向到 `guard/_out/_n1c_v2/r2/pilot_cache/`，不写入 `derived/cache/`。
3. 原始 LLM 输出与派生字段分开保存：原始输出写入 `H3_raw_llm.jsonl`，派生结果写入 `H3_candidates.jsonl`。
4. 不写入 canonical Fact 空间、知识中枢与 Seed。

## 六、失败与预算处理

| 情形 | 处理 |
|---|---|
| 单批 JSON 解析失败 | 记录 error_stage 与原始响应哈希，该批记为无产出，不重试超过生产策略上限 |
| 请求超时 | 记录 attempt 与错误类型，计入重试次数 |
| 缓存命中 | 记为 cache_hit，不计入实际请求数与费用 |
| 达到任一上限 | 立即停止，产出已完成部分与未执行清单 |

## 七、限制

1. 预计 token 与费用基于 V2-E4 试点的实测均值（24 块、48644 token、4 次请求），新文档的段落长度分布可能不同。
2. 预算获批不代表产出质量保证。产出仍需独立人工审核。
3. H2 与 H3 的历史 token 与调用事件不可独立复算，保持 unavailable，不在本方案中追补。

## 八、下一步

获得授权后按本方案执行一次，随后生成盲审包。V2 判据在冻结 V2 之后不因本批结果调整。
