# R2 候选抽样与冻结规则

## 一、抽样单位

抽样单位为原文块（连续散文段），不是候选。候选由抽取产生，不参与挑选，避免用模型预测结果选择样本。

## 二、抽样框

1. 仅限 C 类来源，即库内未参与任何开发与历史独立集合的文档。当前为空，须按 `R2_新增RFC版本和哈希清单.json` 引入新文档后确定。
2. 每份文档取 2 段，共 16 段，对应 8 份文档。
3. 每文档最多 6 条的限制在 A、B 双队列合并计算，跨协议共用该上限。

## 三、分层

队列 B 按章节类型分层，章节类型由冻结的结构规则与标题映射判定，不依赖人工真值：

| 章节类型 | 目标条数 | 说明 |
|---|---:|---|
| 协议操作与行为规范 | 6 | 目标类型 |
| 消息格式与 ABNF | 3 | 目标类型 |
| 状态、响应与错误处理 | 3 | 目标类型 |
| 定义、注册与参数说明 | 3 | 目标类型 |
| 附录、元数据及其他 | 2 | 非目标类型，用于检验类型闸门 |

队列 A 按知识类型分层，依据同章节点在初次分类后的分布确定，不依据 V2 的最终判定。

## 四、协议覆盖

| 协议 | 目标条数 | 说明 |
|---|---:|---|
| SIP | 4 | 库内 RFC 3261 已被开发集使用，须用新增文档 |
| RTSP | 4 | 库内 RFC 2326 已被开发集使用，须用 RFC 7826 系列 |
| SMTP | 4 | 库内 4 份已被开发集使用，须用新增文档 |
| DHCPv4 | 不新增 | H3 的 23 条已覆盖该协议的独立 RFC 内部差异 |

实际分配须按 RFC Editor 的可取得文档数调整；若某协议无法凑足 4 条，按实报告并标注独立性等级降级。

## 五、排除规则

按顺序执行，每条排除记录原因：

1. 精确 chunk_id 排除：与 N1-B、N1-C、V2 六轮调优、队列 A、队列 B、H2、H3 的 chunk 重叠。
2. 行区间重叠排除：与任何历史抽取窗口的行区间重叠。
3. 证据跨度重叠排除：与任何已登记候选的 source_span 重叠。
4. 近重复排除：5-gram Jaccard 大于 0.6。
5. 跨 RFC 同一命题重述：由人工在审核阶段确认，登记到台账。

## 六、冻结

1. 抽样规则、随机种子、配置哈希先冻结，再执行抽样。
2. 抽样结果按（队列，协议，文档，起始行）稳定排序，输出逐行 SHA256。
3. 同一输入、配置与种子多次运行必须产生逐字节一致的清单，由 `tests/extraction/test_r2_sampler.py` 断言。
4. 冻结后不改样本；抽样结果不因产出质量重新抽取。

## 七、限制

1. 章节类型分层依赖标题映射规则，对格式异常的 RFC 可能误判，须在容量报告中列出。
2. 每文档 2 段是按 16 段总量与 8 份文档推导，实际文档数变化时须重算。
3. 本规则不覆盖队列 A。队列 A 的样本量为现有候选中符合独立性条件的部分。
