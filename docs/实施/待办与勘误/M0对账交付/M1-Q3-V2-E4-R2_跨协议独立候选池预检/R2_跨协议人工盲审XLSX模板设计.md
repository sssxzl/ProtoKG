# R2 跨协议人工盲审 XLSX 模板设计

## 一、总体结构

按协议建立独立工作簿，不把不同协议来源混成没有协议标签的记录。每个协议一份工作簿，含三个文件：

- `<协议>_审核者A_盲审模板.xlsx`
- `<协议>_审核者B_盲审模板.xlsx`
- `<协议>_第三方仲裁模板.xlsx`

## 二、工作表划分

沿用 V2-E4-R1 的四表结构：

| 工作表 | 内容 | 可编辑性 |
|---|---|---|
| 说明 | 审核须知、四条硬规则、枚举说明 | 保护 |
| 机器身份 | 中性候选编号、协议、RFC 文档与哈希、证据跨度、原文、候选命题、候选声称的结构化字段 | 保护 |
| 人工审核 | 每候选一行的审核项，含数据验证下拉 | 仅审核列 |
| 补充知识 | 一候选含多个独立命题时新增行 | 可编辑 |

仲裁工作簿含说明表与仲裁记录表，仲裁记录表预置 A、B 两列原始判断、具体分歧、最终裁定、原文证据、日期、理由、unresolved 标志，不预填任何结论。

## 三、字段与格式要求

1. 候选编号使用中性编号（如 SIP-01），不暴露候选类型或规则资格判定。
2. 行号、跨度、候选编号、哈希全部为文本单元格，禁用 Excel 的日期转换与科学计数法转换。
3. 不可编辑的身份与证据字段实施工作表保护，同时用外部机器基线做逐单元格比较，两条校验独立。
4. 人工填写字段使用数据验证下拉，枚举含 unknown、uncertain、not_applicable、unresolved。
5. 原文中的引号、特殊 Unicode 字符、换行与公式样式字符串按文本写入并设 quotePrefix。

## 四、审核项

与 V2-E4-R1 相同的 16 个审核项：原文是否支持候选命题、是否属目标协议知识、source_content_kind、knowledge_kind、rule_eligibility、evidence_sufficiency、规范义务主体与动作与对象、规范强度、极性、条件与例外、抽取完整性、证据充分性、人工认为正确的目标路由、审核理由。

不适用的规范字段不强制填写。

## 五、生成与校验

1. 用 openpyxl 生成，沿用 `guard/_out/_n1c_v2/r1/gen_xlsx.py` 的实现。
2. 生成后重新打开，逐单元格与机器基线比较，差异数为 0 方可发放。
3. 记录每个文件的 SHA256。
4. A、B 两份模板的机器基线须逐单元格一致。

## 六、限制

1. 本轮不生成实际模板，待来源与候选冻结后再生成。
2. 模板不代替原始数据完整性校验，导入结果时仍须做不可编辑字段逐单元格比较。
