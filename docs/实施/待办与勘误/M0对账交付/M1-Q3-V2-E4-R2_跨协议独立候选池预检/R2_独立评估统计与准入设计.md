# R2 独立评估统计与准入设计

## 一、已验证事实

当前各队列的可比较范围：

| 队列 | 样本量 | 来源 | 与队列 B 可比 |
|---|---:|---|---|
| 队列 A | 1 条候选 | H3 之外 | 不适用 |
| 队列 B | 54 片段，121 条 valid_gold | 11 份文档 | H1 可比，H2 与 H3 不可比 |
| H3 | 23 条候选 | 9 份 DHCPv4 文档 | 与队列 B 不可比 |

H3 的独立性已核验：与 N1-B、N1-C、V2 调优来源的文档重叠为 0，与开发集证据的 5-gram 近重复为 0。

## 二、评测报告的分层要求

正式评估须分别报告，不得合并为单一百分比：

1. DHCPv4 内部独立 RFC 结果（H3 的 23 条，盲审后）
2. SIP 独立候选结果（待新增来源）
3. RTSP 独立候选结果（待新增来源）
4. SMTP 独立候选结果（待新增来源）
5. 合并后的跨协议描述性结果（须同时给出各协议的来源 RFC 数、候选数、有效 Gold 数与不确定性）

## 三、准入判据的拟定

| 判据 | 阈值 | 说明 |
|---|---|---|
| 各协议须有独立来源 RFC | 至少 1 份，来源独立 | 库内 6 份均不可用 |
| 队列 A 有效样本量 | 不少于 30 条候选 | 当前 1 条，差距最大 |
| 规则通道纯度 | 不低于历史水平 | 以人工真值为准 |
| 真实规范义务误排 | 逐条列出，阈值待定 | 须先有足够的独立候选 |
| 结论粒度 | 按协议分别陈述 | 不得汇总为单一百分比 |

## 四、限制

1. 队列 A 样本量不足是当前准入的主要障碍。新增来源并完成抽取后须重算。
2. 即使新增来源完成抽取，盲审尚未进行，Gold 数量未知，判据阈值无法最终确定。
3. 跨协议泛化结论的前提是每个协议都有独立来源与足够的 Gold 数。本轮预检结论为该前提尚未成立。

## 五、下一步

1. 若获批引入新文档并执行受控抽取，按 `R2_候选抽样与冻结规则.md` 冻结样本。
2. 抽取完成后按 `R2_跨协议人工盲审XLSX模板设计.md` 生成盲审包。
3. 盲审与仲裁完成后冻结 Gold，按本设计的分层口径出具独立评估报告。
