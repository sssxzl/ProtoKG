### 2.1 ★★ 缺失原因定位（★ §四 要求的准确答案）

| 候选解释 | ★ 成立？ |
|---|---|
| ★ 「模型没识别出主体」 | ★ **部分成立**：★ 阶段1 的 `normative_subject` 产出率仅 **46.88%** |
| ★ 「Schema 没要求该字段」 | ★ **不成立**：★ ★ **原始 Schema 【确实产出】`normative_subject` / `action` / `object` / `condition`** |
| ★ **「派生层未把结构化字段保留进 norm 输出」** | ★ ★ **成立**（★ ★ 【阶段衔接 / 输出契约】问题，★ **而非 LLM 能力问题**） |
| ★ 「被 max_tokens 截断」 | ★ **不成立**：★ 输出 max 15,202/32 条平均 475，★ **0 块触及 4,000 上限**；★ 本轮重试 0 / 失败 0 |

⇒ ⇒ ★★★ **★ 结论：★ 字段缺失有两个独立来源**
★ ★★ **① LLM 层本身不总是产出结构化字段（★ action/object/strength 62.5%、normative_subject 46.9%）**
★ ★★ **② 派生层把 LLM 已产出的结构化字段【丢弃】了（★ norm 里没有）**
★ ⇒ ★★ **★ 因此：★ 要提升字段完整性，★ 既要提高阶段1 产出率（★ Prompt/Schema 层），★ 也要修阶段2 的输出契约（★ 派生层保留字段）**
