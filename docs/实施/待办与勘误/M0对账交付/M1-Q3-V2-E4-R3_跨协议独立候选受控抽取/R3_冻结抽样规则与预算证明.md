# R3 冻结抽样规则与预算证明

## 一、已验证事实

抽样在 LLM 调用前完成并冻结，产物为 `R3_冻结原文块及抽样台账.xlsx` 与 `guard/_out/_n1c_v2/r3/r3_blocks.json`。

### 1.1 抽样规则

| 规则 | 值 |
|---|---|
| 随机种子 | 20261117 |
| 每份文档块数 | 2 |
| 块长度上限 | 3500 字符，对齐生产 `_MAX_BLOCK_CHARS` |
| 块 1 | BCP14 关键词密度最高的合格段 |
| 块 2 | 密度不高于该文档候选块中位数的合格段；同密度时取与块 1 行距最远者 |
| 输入排序 | 按（协议，文档，起始行）稳定排序 |

BCP14 密度只作抽样辅助特征，不用于判定知识类型。抽样未使用 V2 预测标签、模型置信度或已知错误案例。

### 1.2 冻结结果

块数 16（上限 18），RFC 8 份（上限 9），协议分布 smtp 8 / sip 6 / rtsp 2。

### 1.3 预算证明

| 项 | 上限 | 计划 | 实际 |
|---|---:|---:|---:|
| RFC 文档 | 9 | 8 | 8 |
| 原文块 | 18 | 16 | 16 |
| 实际 LLM 请求 | 18 | 4 批 | **8** |
| token 合计 | 120000 | 上界 44800 | **33432** |
| 费用 USD | 0.05 | 上界 0.013920 | **0.01632105** |

调用前的预算检查逻辑：每次请求前用保守上界（批输入 7200 token、输出 4000 token）计算投影值，任一上限将越界则停止该批并记录 `block_failure` 事件。无法可靠判断时停止而非先调用再统计。本轮 8 个批次全部通过预算检查，无因预算停止。

### 1.4 请求数与块数独立

按文档切批（每文档 2 块），因此 8 份文档产生 8 个批次，每批 1 次请求，合计 8 次请求处理 16 个块。请求数与块数在事件文件中分别统计。

## 二、推论

1. 批量化把请求数从按块计的 16 次降到 8 次，仍沿用生产 `_BATCH_BLOCKS=5` 的切批语义与缓存键契约。
2. 实际 token 与费用低于上界，因每批只含 2 块而未达批大小上限。
3. 块 2 的密度普遍为 0，来自封面、目录、注册表或格式定义段落，可覆盖非规范元数据与描述性知识。

## 三、限制

1. 实际抽取的 8 个批次每批 2 块，未触发生产的 5 块批上限。若后续按 5 块批执行，块数与请求数的比例会变化。
2. 抽样段的切分规则（空行与标题行为界）为本轮自实现，未复用生产切块函数，因此段边界可能与生产不同。
3. 块 2 的中位数规则在合格段少于 2 个时不适用，本轮 8 份文档每份合格段均不少于 5 个。

## 四、下一步

按 `R3_回归测试与审批边界证明.md` 的边界执行人工盲审，不因本轮产出结果调整 V2 判据。
