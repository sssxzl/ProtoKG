## 二、★ 两层匹配（★ 已冻结）

### 2.1 第一层：来源与证据定位
| # | 检查 | ★ 通过标准 |
|---|---|---|
| ① | RFC 文档相同 | ★ `document` 与 `rfc_sha256` 均一致 |
| ② | 原文跨度重叠 | ★ 行区间有交集 |
| ③ | 同一完整规范句 | ★ 用生产的 `_logical_line` + `_sentences_in` 判定 |
| ④ | 跨句/跨节引用 | ★ 同文档内可定位引用来源；★ 跨文档不视为匹配 |
| ⑤ | 同一知识对象 | ★ 主体+动作+对象指向同一对象（★ 代词已解析） |

★ ⇒ ★★ **不得仅凭同一 chunk / 文本相似 / 相同规范关键词判为成功抽取**

### 2.2 第二层：语义命题匹配
★ 知识类型 ｜主体 ｜动作 ｜对象 ｜强度（★ SHALL≡MUST、REQUIRED≡MUST、RECOMMENDED≡SHOULD）｜
★ 极性（★ MUST+negative ≡ MUST NOT）｜条件与例外 ｜适用范围

## 三、★ 五态结果（★ 互斥）

| 结果 | ★ 定义 |
|---|---|
| ★ `full_match` | ★ 关键知识**完整保留** |
| ★ `partial_match` | ★ 有对应候选，★ 但关键字段不完整 |
| ★ `semantic_mismatch` | ★ 有相关候选，★ 但关键语义错误 |
| ★ `unmatched` | ★ **在 H1（+H2 单列）中未发现对应候选** |
| ★ `uncertain` | ★ 证据不足或匹配有歧义 |

★ ⇒ ★★ **同一候选不得因重复匹配而多次计为成功抽取**
★ ⇒ ★★ **一对多/多对一须记录人工仲裁**

## 五、★ 漏抽判定三段式（★ 冻结）

```
① 片段内是否**存在**人工认定的目标知识？  否 ⇒ ★ 不是漏抽
② 该知识在 H1 中是否已有对应（两层匹配）？  是 ⇒ ★ 不是漏抽
③ 否则 ⇒ ★ 标注遗漏阶段：
   ★ 触发遗漏 / 切块遗漏 / 证据定位遗漏 / 结构化抽取遗漏
```
★ ⇒ ★★ **★ 「没有生成候选」≠「漏抽了一条规范知识」**
