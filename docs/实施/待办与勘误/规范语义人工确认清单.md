## 二、第二轮指出的 **12 项断言缺口** → 已补强为「真过机制」

| 编号 | 原缺口 | 现在**真过**的机制 |
|---|---|---|
| **03** | 条件/例外是手工填入 payload，没验证真实跨行抽取 | ★ `extract_condition` / `extract_exception`（**跨行抽取器**）⇒ 抽出的结果进 payload |
| **04** | `cross_ref_status="resolved"` 是手工指定的；证据只有引用句却要 CONFIRMED | ★ `extract_cross_ref` + `locate_section_ref`（**真实定位器**）⇒ 未定位 ⇒ `unresolved`；★ 且**只有引用句**时 L1 **不得 CONFIRMED**（新增「证据充分性」判定） |
| **05** | 只测到 L1 待审，没测**正式发布流程**是否确实隔离 | ★ **发布闸** `publish_gate`（真实发布路径的隔离判定）⇒ 代词主体 ⇒ 隔离；★ 且**成功解析主体后可以进入** |
| **06** | 测的是手工 payload + L1，不是真实抽取入口 | ★ 让示例文本进**候选信号判定** + **确定性语义支持** ⇒ 判「不支持」⇒ 发布闸隔离 |
| **07** | Stub LLM 预先返回「不支持」，未证明验证器**能识别**不受支持的结论 | ★ **确定性语义支持检查**（`l2_deterministic_check`，不依赖 LLM）自己识别出「原文不支持发送 ACK」⇒ L2 的**真通路** |
| **08** | 只测声明级去重，没测事实级归并后证据是否完整保留 | ★ `resolve_claims`（**中枢真实消解**）⇒ 两条 claim 都在（`basis ∪ superseded`） |
| **10** | 创建两个独立 Fact 查 ID 相同，**没真正执行多证据归并** | ★ `resolve_claims` 真归并 ⇒ 两条 claim 都在 + 两条证据都在 |
| **12** | 检查两个 FactID 不同，**尚未真正调用事实归并流程** | ★ 两者放进同一 fact 的 claims ⇒ 过 `resolve_claims` ⇒ 判**冲突**而非误合并、两条都保留 |
| **13** | 测到冲突检测函数，**未验证真实中枢归并后两条 claim 都被保留** | ★ `resolve_claims` ⇒ 两条 claim 都在；★ 措辞改为「**潜在**冲突检查」 |
| **14** | 检查了不同来源/相同 value/无冲突，**未测试合并后两条证据仍存在** | ★ `resolve_claims` ⇒ 两条 claim 都在 + 两条证据分别挂在各自 claim 上 |
| **16** | 构造了两个 RFC 来源，**没有验证真实发布时两条 claim 都保留** | ★ `resolve_claims`（真实归并）⇒ 两条 claim 都在；★ 措辞明确「是否真冲突另行判断」 |
| **17** | if/else 两个分支**执行相同断言**，实际没检验「未确认时不强制合并」 | ★ `normalize_condition`（**带开关**）⇒ 两条路径分别断言：**未确认 ⇒ 不合并**；★ **开关打开且命中同义表 ⇒ 允许合并**（本测试**不阻止**将来改进） |

⇒ ⇒ ★ 为支撑上述补强，**新增了确定性机制**（全部无 LLM ⇒ 可复现、可离线测）：
`core/fused/extraction/normative_extract.py`
· `extract_condition` / `extract_exception` / `extract_cross_ref` / `locate_section_ref`
· `normalize_condition`（★ 归一化开关，默认**关闭** ⇒ 不强制合并）
· `semantic_support`（★ 确定性语义支持检查）

⇒ ⇒ ★ 并扩展了校验层：
· L1 新增「**证据充分性**」（只有引用/元话语 ⇒ 待审，不得 CONFIRMED）
· L1 新增「**主体可解析性**」「**强度未知**」「**跨节引用未定位**」
· L2 新增「**确定性语义支持前置**」（不依赖 LLM 自证）
· 新增「**发布闸**」`publish_gate`（真实发布路径的隔离判定）
