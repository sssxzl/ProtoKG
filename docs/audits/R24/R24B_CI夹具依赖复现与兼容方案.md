## 二、★ 兼容方案：★ ★ 夹具入库 + 单一来源（★ 不关闭任何测试）

### 2.1 原则

- ★ **不**通过关闭测试、跳过错误或降低阈值消除报错
- ★ 夹具从隔离实验区迁到**版本控制内的固定位置**
- ★ 测试的 sys.path 指向新位置；★ 旧路径保留兼容期回退

### 2.2 具体步骤

### ① 选定入库位置

★ **内容**：★ 建议 `tests/_fixtures/`（★ 明确是测试夹具，★ 不是生产代码）

★ **理由**：★ 与 `tests/` 同域；★ 不会被误当作生产模块


### ② 迁移夹具文件

★ **内容**：★ 把 guard/_out/_n1c_v2/{h0,h2a,e1,_n1c} 下的实际 import 模块迁到 tests/_fixtures/ 对应子目录

★ **注意**：★ 迁移时**保留原文件的字节内容**（★ SHA256 登记）；★ 这些是抽取链路的实现模块，★ 属于源码而非数据


### ③ 改测试的路径插入

★ **内容**：★ 改为先插 tests/_fixtures/<子目录>，★ 再插旧路径作兼容回退

★ **理由**：★ 新克隆走新路径；★ 老工作区仍能跑


### ④ 登记与护栏

★ **内容**：★ 在 tests 内加一条断言：★ 所有被测试 import 的夹具必须存在于版本控制内


### ⑤ 重采基线

★ **内容**：★ 在**能拿到夹具的环境**重采 CI 基线（★ ubuntu 与 windows 各一份）

★ **注意**：★ 当前 CI 基线（★ ubuntu 70 / windows 67）是在**缺夹具**的环境下采集的，★ 本身就不完整；★ 重采后 29 个 errors 应归零



### 2.3 预期效果

- ★ ★ 29 个收集期 ERROR：★ 归零
- ★ ★ 12 个 failed 新增：★ 需在重采基线后重新评估（★ 大概率随之归零，★ 因为它们同样源于 import 失败）
- ★ ★ 已知本地五项失败：★ 不受影响（★ 本地有夹具）

### 2.4 风险

- ★ 迁移夹具会改动 7 个测试文件与新增 N 个夹具文件 ⇒ 需走审批
- ★ 重采基线会改变 CI 基线文件 ⇒ 需走审批
- ★ 夹具若含运行产物（★ 而非纯模块）⇒ 须先甄别，★ 数据类产物不入库
