# R24 来源实例身份最小兼容设计

> ★ **sidecar / 兼容索引方案** ｜★ 生产 norm_id / evidence_id / fact_id **保持不变**
> ★ 0 次 LLM 调用

---

## 一、设计目标与约束

| 约束 | 内容 |
|---|---|
| ★ 文件来源保留 | ★ RFC 文档身份、★ 版本（SHA256）、★ 原文跨度 |
| ★ 非文件来源保留 | ★ 生成器类型、★ 生成器版本、★ 输入身份、★ 确定性输出身份 |
| ★ **不伪造 source_sha256** | ★ 非文件来源的 `source_sha256` **必须为空**，★ 不得填占位哈希 |
| ★ 同片段多知识不折叠 | ★ 来源实例键含**候选身份**（kind.name），★ 同片段不同候选键不同 |
| ★ 生成器重复运行稳定 | ★ 同一生成器、★ 同一输入、★ 同一输出 ⇒ 键相同 ⇒ 显式折叠 |
| ★ 不同来源同 norm_id 不静默覆盖 | ★ 键不同 ⇒ 保留为两条来源实例；★ **并产出冲突清单** |
| ★ 同一语义 Fact 可在 L4 关联 | ★ 跨源关联由 **L4 契约**处理，★ 不在 L2/L3 提前吞掉 |

## 二、来源实例键的构造

```
source_instance_key =
  来源类别 | 文档或生成器 | SHA256前16位或NO_SHA | 章节 | 原文跨度 | 候选身份
```

| 来源类别 | 判定 | SHA256 | 章节 | 跨度 | 候选身份 |
|---|---|---|---|---|---|
| ★ `file_source` | ★ `file:<x>.txt` 且 x 在 kb 中存在 | ★ 实际计算 | ★ `#<sec>` | ★ `#@<line>` | ★ kind.name |
| ★ `generated_source` | ★ `file:<x>` 但 x 不是 .txt 文件 | ★ **空**（★ 不伪造） | ★ `#<sec>` | ★ `#@<line>` | ★ kind.name |
| ★ `unresolved_source` | ★ 无 `file:` 段或无法解析 | ★ 空 | ★ 空 | ★ 空 | ★ kind.name |

★ ★ **「生成器类型」与「生成器版本」当前无法从 norm 中取得**
（★ `rfc_extractor.py:4021` 只写了 `file:llm@state-machine`，★ 无版本号）；
★ ⇒ ★ 本方案**将其标记为待补字段**，★ **不由 Agent 猜测**。
★ 建议生产侧在 `source` 中补充形如 `file:llm@state-machine@v<version>#<input>` 的结构。

## 三、★ 关键限制：★ 旧 EvidenceID 无法区分两条来源实例

### 3.1 实测

| 场景 | ★ norm_id 相同 | ★ source_instance_key 相同 | ★ 旧 EvidenceID 相同 | ★ 判定 |
|---|---|---|---|---|
| S-01 文件来源与非文件来源同名 | 是 | 否 | **是** | ★ **关联歧义** |
| S-02 不同非文件生成器同名 | 是 | 否 | **是** | ★ **关联歧义** |
| S-03 同一生成器重复输出 | 是 | 是 | 是 | ★ 合法折叠 |
| S-04 一个 RFC 跨章节多条知识 | 是 | 否 | **是** | ★ **关联歧义** |
| S-05 不同 RFC 相同语义 | 是 | 否 | **是** | ★ **关联歧义** |
| S-06 不同 RFC 同名异义 | 是 | 否 | **是** | ★ **关联歧义** |
| S-07 field_value 多值合并 | 是 | 否 | **是** | ★ **关联歧义**（★ 但须按合并语义处理） |
| S-08 规范性与观测性冲突 | 是 | 否 | **是** | ★ **关联歧义** |
| S-09 旧 EvidenceID 关联歧义 | 是 | 否 | **是** | ★ **关联歧义** |
| S-10 来源身份不可解析 | 是 | 是 | 是 | ★ 合法折叠（★ 但应标 unresolved） |

★ **8 / 10 场景存在旧 EvidenceID 关联歧义。**

### 3.2 ★★ 结论：★ 仅加 sidecar 不足以解决关联问题

★ `compute_evidence_id`（★ `canonical.py:142-146`）= hash(source_type + source_id + locator)，
★ ★ 而 `source_id` 来自 norm_id、★ `locator` 恒 None（★ `norm.py:37`）。

★ ⇒ ★ **两条同 norm_id 的来源实例必然产生同一 EvidenceID。**
★ ⇒ ★ **sidecar 只能提供「哪两条」的信息，★ 不能让下游区分它们。**

★ ★ **必须同时提供显式冲突暴露与阻断机制**：
1. ★ 影子层产出**冲突清单**（★ 同 norm_id 多来源实例）；
2. ★ 冲突记录的 Evidence 关联标记为 **ambiguous**，★ **阻断自动归并**；
3. ★ 阻断须在 L4 生效（★ 不能让两条来源的证据被合到同一 claim 而不可区分）。

## 四、★ 兼容索引（sidecar）结构

| 字段 | 含义 |
|---|---|
| ★ `norm_id` | ★ 保持不变（★ 生产身份） |
| ★ `source_instance_key` | ★ 新增（★ 来源实例身份） |
| ★ `source_class` | ★ file_source / generated_source / unresolved_source |
| ★ `normalized_document_id` | ★ 仅文件来源有值 |
| ★ `source_sha256` | ★ 仅文件来源有值；★ 非文件来源为空 |
| ★ `generator` / `generator_version` | ★ 非文件来源的生成器身份与版本（★ 当前待补） |
| ★ `input_identity` | ★ 生成器输入身份（★ 当前待补） |
| ★ `section` / `source_span` | ★ 章节与原文跨度 |
| ★ `candidate_identity` | ★ kind.name |
| ★ `evidence_ambiguity` | ★ 该 norm_id 是否有多个来源实例（★ bool） |
| ★ `conflict_group` | ★ 冲突组 ID（★ 同 norm_id 的实例共享） |

★ ★ **sidecar 是**兼容索引**：★ **不替换** norm_id；★ **不参与** 生产去重（★ 除非后续单独审批）。
