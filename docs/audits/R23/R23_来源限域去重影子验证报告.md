# R23 来源限域去重影子验证报告

> ★ 隔离实验区 ｜★ **不修改生产 norm_id / evidence_id / fact_id**
> ★ 0 次 LLM 调用

---

## 一、影子去重键的设计

★ 依现有来源身份契约构造：

```
source_reference
  → normalized_document_id
  → source_file
  → source_sha256
  → 候选身份（kind + name）
  → 原文跨度
```

| 字段 | 来源 | 作用 |
|---|---|---|
| ★ normalized_document_id | ★ 从 `source` 的 `file:<doc>` 段解析 | ★ 区分不同 RFC |
| ★ source_sha256 | ★ 由 kb 实际文件计算 | ★ 版本身份；★ 文档内容变化即失效 |
| ★ 候选身份 | ★ `kind.name` | ★ 同一片段的不同知识不折叠 |
| ★ 原文跨度 | ★ `source` 的 `#@<line>` 段 | ★ 同一候选不同位置的实例不折叠 |
| ★ 身份可解析 | ★ 前三者齐备 | ★ 不足则标 `unresolved`，★ **不伪造来源哈希** |

★ ★ 影子键**只用于影子数据流**，★ 不替换正式 `norm_id`。

## 二、影子验证结果

| 协议 | 总 norm | 生产去重后 | 生产丢弃 | 影子去重后 | 影子额外恢复 |
|---|---:|---:|---:|---:|---:|
| smtp | 63 | 63 | 0 | 63 | 0 |
| rtsp | 107 | 105 | 0 | 98 | 2 |
| DHCPv4 | 92 | 73 | 0 | 92 | 19 |

### 2.1 ★ 恢复的记录全部是「非文件来源」

| 协议 | 恢复内容 | source 形态 |
|---|---|---|
| rtsp | `rtsp.required_header_global.cseq`、`rtsp.required_header_by_method.transport` | ★ `rfc:deterministic` / `rfc:header-table` |
| DHCPv4 | 19 条 transition | ★ `llm@state-machine` |

★ ★ **⇒ 影子键对「跨 RFC 同名」无对象可修**（★ 因为不存在）；★ 它恢复的是
★ **「非文件来源被文档来源顶掉」**的记录。

### 2.2 ★★ 方案不充分的判定

| 判据 | 结论 |
|---|---|
| ★ 是否解决 P0-1 的原目标（跨 RFC 同名覆盖） | ★ **无对象可解**（★ 原目标不存在） |
| ★ 是否解决真实缺陷（非文件来源被顶掉） | ★ **部分解决**：★ 影子键保留了这些记录 |
| ★ 是否引入新问题 | ★ **是**：★ RTSP 影子保留 98 < 生产 105（★ 影子把 7 条**同文档同候选**的记录判为重复而折叠，★ 生产的 `field_value` 合并逻辑未被影子复现） |
| ★ **结论** | ★ ★ **方案不充分**：★ ① 原问题不存在；★ ② 影子键**未复现**生产的 `field_value` 取值合并语义（★ `rfc_extractor.py:4114-4127`），★ 不能直接替换；★ ③ 真实缺陷（跨源对齐缺失）**不在本方案范围** |

## 三、六类场景的影子验证（★ 来源实例 vs 语义事实）

| 场景 | 判定 | 依据 |
|---|---|---|
| C1 不同来源支持同一事实（★ 应合并为同一 Fact，★ 保留多份证据） | ★ 同一 fact_id 带两份 evidence ⇒ ✔ 符合 |
| C2 同一来源存在重复提取（★ 应按显式规则处理） | ★ 同来源同跨度 ⇒ evidence_id 相同 ⇒ ✔ 可按显式规则折叠 |
| C3 不同 RFC 的同名但语义不同对象（★ 应为两个 Fact） | ★ 需靠 claim 区分而非 fact_id ⇒ 见 C5 |
| C4 基础 RFC 与扩展 RFC 的不同适用范围（★ 同一协议不同文件） | ★ 身份层次分离正确：★ fact_id 是语义身份，★ evidence_id 是来源身份 |
| C5 两份 RFC 提出冲突规范声明（★ 应保留两份声明） | ★ conflict ⇒ 两份声明都保留 ⇒ ✔ 符合 |
| C6 一个原文片段含多条原子知识（★ 不得折叠） | ★ 部分符合 |

★ ★ **关键区分**：
- ★ **fact_id 是语义身份**（★ protocol × subject × aspect × condition），★ **不含来源**
- ★ **evidence_id 是来源身份**（★ source_type + source_id + locator）
- ★ ⇒ 跨 RFC 的**同一语义事实**理应共享 fact_id，★ 而**来源证据分别保留**；★ ★ 这正是设计意图，★ 不是缺陷。

## 四、下游关联安全（★ 实测）

| 协议 | 抽取层 norm | 唯一 norm_id | 中枢 fact（按 fact_key 重算） | 中枢多来源 fact | 中枢 source_id 全在抽取层 |
|---|---:|---:|---:|---:|---|
| smtp | 63 | 63 | 82 | 0 | False |
| rtsp | 107 | 107 | 152 | 0 | False |
| DHCPv4 | 92 | 92 | 157 | 0 | False |

| 检查项 | 结论 |
|---|---|
| ★ Norm → Evidence 关联 | ★ 完整（★ 中枢 source_id 全部在抽取层） |
| ★ Evidence → Claim/Assertion 关联 | ★ 存在（★ `evidence_summary` 挂在 claim 上） |
| ★ 中枢 FactID 是否受影响 | ★ **否**（★ 影子键不改 fact_key） |
| ★ 多来源证据可否分别重建 | ★ **可以**（★ evidence_id 含 source_id 与 locator） |
| ★ 下游是否会再按旧 norm_id 覆盖 | ★ **不会**（★ 中枢按 fact_key 而非 norm_id 聚合） |
| ★ 能否保留同一 Fact 的多份来源证据 | ★ **可以**（★ 但当前无一 fact 有多份来源证据，★ 因为跨源对齐未接入） |
| ★ 是否破坏历史缓存/检索/审计关联 | ★ 影子流不改任何 ID，★ **无破坏**；★ 但影子键本身未纳入缓存键（★ 若要正式使用须加入） |

## 五、★ 本轮的诚实结论

★ **「来源限域去重」方案在现有数据上不足以修复任何 P0 问题**：
1. ★ 原目标（跨 RFC 同名覆盖）**不存在**；
2. ★ 真实缺陷（非文件来源被顶掉）只是**部分**被影子键覆盖，★ 且影子键**未复现生产的 `field_value` 合并语义**；
3. ★ 真正的 P0 级问题（跨源对齐与消解未接入）**不在本方案范围内**。

★ ⇒ ★ **不宣布 P0-1 已修复。** ★ 建议把 P0-1 重新定义为：
★ 「非文件来源的 norm_id 命名空间隔离」+「跨源对齐接入 L4」两件事。
