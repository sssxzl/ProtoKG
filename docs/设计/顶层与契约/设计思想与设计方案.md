## 摘要

本系统面向**协议模糊测试的初始种子生成**这一核心任务：为基于变异的协议模糊测试器提供一套高质量的**初始种子集**，作为其变异与状态探索的起点。初始种子的质量直接决定模糊测试的成效——它既要**合法完整**（能跑通协议、到达深层状态），又要**有针对性**（覆盖协议边界、触发潜在缺陷）。传统做法——人工编写种子（成本高、不可跨协议迁移）、仅从真实流量捕获（覆盖面窄）、随机生成（缺乏协议语义）——都难以同时满足这两点。

为此，本系统提出一条「**知识对齐 → 种子生成**」的两阶段主线。
> ★ **「对齐层」是本项目的核心创新**：它把五种形态与证据强度迥异的源知识
> 收敛到同一套事实空间，并**保留「谁说的、谁赢了、为什么」**（消解留痕 + 证据链）。第一阶段，将分散在五类**异构知识源**（协议规范、实现源码、抓包流量、历史漏洞、专家知识）中的协议知识**对齐**到同一套「知识原子」坐标系——以「主体、侧面、条件、值、认识论类型、证据」六要素统一表达，使不同来源、不同格式、不同粒度的知识得以融合、冲突消解并全程溯源，形成一张**结构化、可溯源的知识图谱**。第二阶段，基于对齐后的知识图谱，**分层生成**从「守正」到「出奇」的初始种子集。

### 三个核心问题

整条链路围绕三个问题展开，**后文的每一层、每一个设计模式，都是对其中某一个的应答**：

| #       | 核心问题                                  | 主要应答处                                                           | 产出                             |
| ------- | ------------------------------------- | --------------------------------------------------------------- | ------------------------------ |
| **问题一** | **如何将异构知识源提取的知识对齐**                   | 中枢层（§2.2）· 知识原子化（§5.1）· 溯源（§5.2）· 权威分级与冲突消解（§5.3）· 档案与源分离（§5.4） | 一张**结构化、可溯源**的知识图谱             |
| **问题二** | **如何做一个通用的框架，对网络协议的多种知识源都能处理**        | 抽取层（§2.1）· 确定性前置与理解分离（§5.8）· 投影式消费（§5.6）· 确定性（§5.5）             | 与**协议无关**的知识坐标系 + 可换源、可换协议的主程序 |
| **问题三** | **如何利用已提取的知识，结合 RAG 与 LLM 生成目标的初始种子** | 消费与生成层（§2.3）· 图增强检索 GraphRAG（§5.9）· 分层生成（§5.7）· 多道校验闸门（§5.10）   | 合法完整且有针对性的**初始种子集**            |

整条链路以三条设计原则贯穿始终：**可信（Trustworthy）、可控（Controllable）、可扩展（Extensible）**——分别保证知识的可溯源与可复现、运行的可归因与可对比、体系的可扩展与可解耦。

## 一、整体设计思想与核心理念

### 1.1 要解决的核心问题

系统要回答三个问题：

1. **如何将异构知识源提取的知识对齐**：协议规范、实现源码、抓包流量、历史漏洞、专家笔记——五类来源的形态、粒度、证据强度各不相同，如何让它们**落到同一套坐标系**上，同时保留「谁说的、谁赢了、为什么」；
2. **如何做一个通用的框架，对网络协议的多种知识源都能处理**：框架不能写死某一个协议或某一类来源——**协议无关**是主程序的硬要求，换协议、换来源都只换数据不换机制；
3. **如何利用已经提取的知识，结合 RAG 与 LLM 生成目标的初始种子**：把知识变成**合法完整**（能跑通协议、到达深层状态）又**有针对性**（覆盖协议边界、触发潜在缺陷）的初始种子集。

> ★ 三问之间不是并列的三件事，而是**一条链**：**问题二**保证「知识能持续抽出来」，
> **问题一**保证「抽出来的知识能用且能用得放心」，**问题三**保证「知识能变成种子」。
> ⇒ ⇒ 任何一环缺失，前一环的投入都会在最后一环失效。

### 1.2 核心设计理念

**理念一：知识优先（Knowledge-First）**

不直接「从文本跳到种子」，而是先完成一次明确的「知识抽取与结构化」中间步骤。这个中间层的存在，使得上游来源的可替换性与下游消费的可验证性得以解耦——知识成为两端之间的稳定契约。

**理念二：溯源优先（Provenance-First）**

每一条知识都作为「带证据的声明」存储，而非孤立的结论。任何知识都可以被追问「来自哪个来源、依据是什么」。这是「知识可信」能够被**证明**而非仅仅被宣称的前提，也是问题三里「用 RAG 检索时不把幻觉当知识」的基础。

**理念三：可信、可控、可扩展三原则**

- **可信**：通过溯源与确定性，保证结果可证明、可复现；
- **可控**：通过多源分级与**源/协议档案分离**（档案只承载协议结构声明），保证每次运行**可归因、可对比**（能干净地关掉某个源，说清结果里哪些来自它）；
- **可扩展**：通过知识原子化与投影式消费，保证知识可拼装、消费端可解耦。

三条原则还共同承担一项关键作用——**降低 LLM 幻觉对系统的影响**。可信通过「确定性前置 + 受控词表 + 多道校验」缩小幻觉的作用面，并拦截形式层面的幻觉；可控通过「多源分级 + 可归因」把幻觉变成一个可溯源、可度量的变量；可扩展通过「知识原子化」把幻觉的影响限制在单个知识原子内，避免扩散。需要说明的是，这套机制拦截的是「形式幻觉」（格式、词表、字段绑定等可校验错误）；而「语义幻觉」（格式正确但理解错误）无法靠规则拦截——它只能靠**独立校验**（L2 逐字段核验）与人工标注评测兜底。

### 1.3 关键设计选择

**选择一：按来源的可结构性，分别采用「确定性切分 + 定点精读」「语义检索」「直接映射」三种读法**（见 5.8）

协议规范是高度结构化的（章节树、语法定义、状态表、规范性措辞），适合用确定性规则精确切分，再让语言模型对切好的片段做「定点精读」；协议实现源码是非结构化的，状态机等逻辑散布在任意位置，靠语义检索定位；历史漏洞与专家笔记本身已是结构化记录，直接映射即可。**判据**是**「来源本身能不能精确切」与「需不需要精确溯源」**——能精确切的就规则切，切不了的才检索，已结构化的就直搬。

**选择二：知识组织采用「实体—关系」图**（见 5.9）

知识被组织成显式的「实体—关系」图谱。原因有二：其一，图能保留明确的证据链与来源标注，这是可信原则的载体；其二，图支持按关系做多跳导航，能自动拼齐「生成某个消息所需的完整上下文」。

**选择三：单源与多源可切换**（见 5.3、5.4）

系统支持在同一套机制下，自由切换「仅使用规范」与「融合全部来源」两种形态。这不是功能冗余，而是**问题二（通用框架）的直接体现**——唯有能干净地关闭某些来源，才能说清「结果里哪些知识来自哪个源」。

**选择四：守正与出奇分层生成**（见 5.7）

种子生成不追求「一把梭」，而是从「守正」（保证合法完整、能跑通协议）到「出奇」（注入危险、触发缺陷）分层递进。两者缺一不可：没有守正种子，模糊测试器连协议都跑不通；没有出奇种子，跑通了也戳不到缺陷。

## 二、模型层级与职责划分

模型自下而上分为**五层**，每层职责清晰、互不越界；层间**单向依赖**（详见 §4）。

| 层级 | 名称 | 主要职责 | 主要应答 | 覆盖的问题 |
|---|---|---|---|---|
| 第 1 层 | **知识抽取层**（§2.1） | 把五类异构来源读成结构化知识 | 确定性前置 + 定点精读（§5.8） | **问题二** |
| 第 2 层 | **知识中枢层**（§2.2） | 把异构知识**对齐**到同一套事实空间 | 知识原子化 + 溯源 + 权威分级（§5.1~§5.4） | **问题一** |
| 第 3 层 | **知识整理层**（§2.3） | 把对齐后的知识**组织成可取用的视图** | 图增强检索 + 投影式消费（§5.9、§5.6） | **问题三** |
| 第 4 层 | **种子生成层**（§2.4） | 在检索到的知识上**组装初始种子** | 分层生成（§5.7） | **问题三** |
| 第 5 层 | **种子校验层**（§2.5） | 在交付前做最后一道契约校验 | 多道校验闸门（§5.10） | 贯穿三问 |

> ★ 另有一条**仓库级**的**护栏机制**（§4.1 第 6 层）不属于模型的五层：
> 它守护的是「每次改动是否可信」，而非「种子是否合法」。


### 2.1 知识抽取层

**职责**：把异构的原始知识源，转化为结构化、带溯源的知识。（详见 5.8、5.2）

按**来源类型**分为五条相互独立的知识来源（各自的**结构化通道**数量不同：规范源现为
A~J 共 10 条结构化通道，另加 LLM 补漏通道），各自采用最适合该来源的读法：

- **规范抽取通道**：处理协议规范文档。采用「确定性切分 + 定点精读」——先用规则切出候选片段（不消耗语言模型、完全可复现），再让语言模型对片段做结构化理解。此通道产出协议的结构、状态机、语义约束等知识。
- **源码抽取通道**：处理协议实现源码。采用「语义检索」——将源码切块并向量化，用协议无关的通用查询检索与状态机、事件处理、错误处理相关的代码块。此通道补充「实现侧」的知识。
- **流量抽取通道**：处理抓包流量。解析真实报文，产出「实测观测」性质的知识。
- **漏洞抽取通道**：处理历史漏洞素材。将已知漏洞的结构化记录映射为知识，产出「漏洞模式」性质的知识，供攻击性种子生成使用。
- **专家知识抽取通道**：处理专家笔记素材。将专家标注的薄弱点、关键字段、设计缺陷、隐式约束等映射为知识，产出「专家经验」性质的知识。

五条通道最终归结为**三种读法分工**：对高度结构化的规范文档用「确定性切分 + 定点精读」（定位精准、可溯源、零额外成本）；对非结构化的实现源码用「语义检索」（无法精确切、只能靠语义定位）；对已经是结构化记录的历史漏洞与专家笔记用「直接映射」（无需理解、直接搬运）。这一分工的依据是「来源本身的可结构性」——能精确切的就规则切，切不了的才检索，已结构化的就直搬。

**边界**：抽取层只负责「把知识取出来并结构化」，不负责判断知识的优劣，也不负责知识如何被使用。

★ **问题二（通用框架）在此落地**：主程序**不含任何协议分支** ⇒ 协议差异只体现在
「档案（`profiles/<协议>/`）」与「知识源内容」两处 ⇒ ⇒ 换一个协议、换一个来源，
**只换数据、不换机制**。

### 2.2 知识中枢层（**对齐层**）

**职责**：统一承载、融合、溯源所有来源的结构化知识，是全系统的核心。（详见 5.1、5.3、5.4、5.5）

知识中枢内部承担四项子职责：

- **知识原子化**：把知识拆成最小、可独立溯源、可自由组合的原子单元。每个原子由「主体、侧面、条件、值、认识论类型、证据」六个要素构成。
- **多维分桶**：知识按「侧面」（维度）归类存储。当前注册 **21 个 aspect**
  （真源：`core/fused/hub/registry/aspect_registry.json`），覆盖从「协议有哪些消息类型」
  「消息长什么样」「消息按什么顺序出现」「各元素出现频次如何」「协议处于什么状态、如何转移」
  「字段取值边界是什么」，到**状态机（`target_state`）、方法序列（`method_sequence`）、
  安全属性（`security_property`）、合法边界（`legal_boundary`）、漏洞模式（`vuln_pattern`）**
  等维度（★ 完整清单以 `core/fused/hub/registry/aspect_registry.json` 的 21 个为准；
  ★ **「来源纯净度」不是知识维度**，而是**图路径纯度闸**，见 §2.3）。
  ★ 维度清单**只增不改**：新增知识形态走「投影式消费」（§5.6），不改既有 aspect。
- **多源融合与权威分级**：同一知识原子可能被多个来源以不同方式陈述，中枢需在保留各自声明的条件下，按「认识论优先级」做冲突消解；同时支持按来源集合开关，实现单源/多源切换。
- **溯源与确定性**：每条知识附带来源与证据链；知识的存取顺序是显式、确定的，保证「同一输入 → 同一输出」。

**边界**：知识中枢只负责「知识如何被可信地组织与融合」，不负责「知识如何被翻译成种子」。

### 2.3 知识整理层

**职责**：把知识中枢里已对齐的知识，**组织成生成可直接取用的视图**。（详见 5.6、5.9）

内部包含三个协作步骤：

- **知识组装**：按目标把相关维度知识装配成一份完整可用的知识视图。
- **子图检索**：当有明确目标时，在知识图谱上做多跳子图检索，只取与目标相关的知识，避免无关噪声；★ 这就是本项目的 **RAG** 形态（§5.9）。
- **投影式消费**：把新出现的知识形态，投影成下游已经认识的既有形态，使下游无需改动即可消费新知识。

★ 另含**图路径纯度闸**（`graph_query.check_path_purity`）：只保留**整条知识路径都干净**的
上下文，避免把跨源污染的知识喂给生成端。

**边界**：本层只负责「知识如何被组织与取用」，**不生成任何报文**；产出的视图交给种子生成层。

### 2.4 种子生成层

**职责**：在知识整理层给出的视图上，**组装初始种子**。（详见 5.7、5.10）

- **分层生成**：按「守正到出奇」的分层策略，生成结构覆盖、通用危险、漏洞边界、黄金路径等多类种子，并在基准种子之上追加序列级变异。
- ★ **与 LLM 的分工**：**检索（召回上下文）由知识整理层负责，组装（写报文）由本层的 LLM 负责** ⇒ ⇒ LLM 只在**有证据的知识**上组装，不凭空编造协议行为。

**边界**：本层只负责「把知识变成种子」，**不做放行判定**；产出仍需经过种子校验层。

### 2.5 种子校验层

**职责**：在种子交付外部之前，做最后一道契约校验。（详见 5.5、5.10）

- **语料准入校验**：对产出种子做**多道契约检查**——合法端点、**来源纯度**、数量契约、字段绑定等，逐道把关，任何一道不符即不予放行。
- **可复现校验**：同一输入必须得到同一输出（§5.5），否则不予放行。

**边界**：种子校验层是「守门人」，只做判定，不参与生成。

> ★ **与护栏的区别**：种子校验层判的是「**这批种子合不合格**」；
> 护栏（§4.1 第 6 层）判的是「**这次改动能不能信**」⇒ ⇒ 两者互不替代。


## 三、模块关联、协作方式与数据流向

### 3.1 端到端数据流主线

整条数据流是单向的「原料 → 成品」流水线：

```
外部知识源 → 知识抽取层 → 知识中枢层 → 知识整理层 → 种子生成层 → 种子校验层 → 模糊测试器
```

数据在相邻层之间以**「结构化知识」而非「原始文本」**的形式交接。这是知识优先理念的直接体现：抽取层交付结构化知识，中枢层交付**对齐后**的知识，知识整理层交付**可取用的视图**，种子生成层交付种子，种子校验层交付「**通过校验的种子**」。

### 3.2 各模块协作方式

- **抽取层 → 中枢层**：五类来源各自产出带来源标注的结构化知识，汇入中枢。中枢不关心知识「怎么抽出来的」，只关心「是否带可信的溯源」。
- **中枢层 → 知识整理层**：整理层向中枢「按需取知识」——无明确目标时取全量视图，有明确目标时做子图检索。整理层对中枢是只读的，不反向改写知识。
- **知识整理层 → 种子生成层**：整理层交付**检索到的、有证据的上下文**，生成层在其上组装种子。
- **种子生成层 → 种子校验层**：生成层产出种子，校验层做独立判定。校验层与生成层解耦，任何生成策略的变更都不影响校验口径。
- **种子校验层 → 外部**：通过校验的种子交付模糊测试器。校验层是系统与外部世界的明确边界。


这种「单向流动 + 稳定契约」的协作方式，使得每一层都可以被独立替换或演进，而不牵动其他层。

## 四、分层结构与依赖关系

### 4.1 分层结构

系统自下而上（按依赖方向）分为**六层**（★ 与 `core/fused/` 的目录分层一致）：

| 层级    | 名称      | 职责               | 对应代码 |
| ----- | ------- | ---------------- | --- |
| 第 1 层 | 知识抽取层   | 异构来源 → 结构化知识     | `core/fused/extraction/`（各源） |
| 第 2 层 | 知识中枢层   | 知识的原子化、对齐、融合、溯源 | `core/fused/hub/` |
| 第 3 层 | 知识整理层   | 实体—关系图、社区、子图检索、投影 | `core/fused/graph/` |
| 第 4 层 | 种子生成层   | 分层生成合法与攻击性种子     | `core/fused/downstream/` |
| 第 5 层 | 种子校验层   | 契约校验与合规性审查        | `core/fused/downstream/`（校验） |
| 第 6 层 | 护栏与质量   | 回归护栏（新增失败为零 / 消失为零） | `guard/` |

★ 另有一条**横切**的语义层（`core/fused/semantic/`）与知识类型定义（`core/kinds/`）。

### 4.2 依赖方向与调用层级

**依赖方向是单向向下的**：上层依赖下层提供的知识或产物，下层绝不依赖上层。

- 第 2 层是全局核心，第 1 层向其「注入」知识，第 3、4 层从其「读取」知识，形成以中枢为中心的辐射结构。
- 第 5 层横跨在输出末端，对第 4 层的产物做独立判定，不参与上游生产。

这种「核心居中、单向依赖」的分层，带来两个直接好处：其一，核心层（知识中枢）保持稳定，来源扩展与消费策略演进都在边缘发生；其二，每一层的可测试性独立——下层可以用固定输入验证，上层可以用桩替身隔离下层。

## 五、关键设计模式与抽象

### 5.1 知识原子化

**抽象**：将知识拆分为「主体、侧面、条件、值、认识论类型、证据」六要素的最小单元。

**作用**：知识不再是不可分割的「一段话」，而是可加减、可去重、可投影的积木。它是图增强检索（§5.9）的底层载体，也是可扩展原则的基础——新增知识类型只是新增一类原子，不必改动既有结构。

**应用位置**：知识中枢层（§2.2），是消费与生成层（§2.3）及图增强检索（§5.9）的底层载体。

### 5.2 溯源（Provenance）

**抽象**：每条知识都是「带证据的声明」，证据链与知识本身同生共死。

**作用**：支撑可信原则的核心机制。它把「这条知识可信」从一句口号变成可验证的事实——**任何结论都能顺着证据链回溯到原文**，这是「来源纯度闸」与「可归因的运行」得以成立的前提。溯源也是「单源与多源可切换」得以成立的前提：只有知道每条知识来自哪个源，才能干净地关闭某个源。

**应用位置**：贯穿全链路——抽取层（§2.1）产出带溯源的知识，中枢层（§2.2）承载与校验溯源。

### 5.3 多源权威分级与冲突消解

**抽象**：系统融合**五类外部来源**——**规范、源码、流量、漏洞、专家知识**。
★ 原设计中的「跨实验复用的**协议骨架**」已**消解并物理移除**（2026-11-10）⇒
协议结构改由**档案**声明（§5.4），不再作为「第六类来源」参与权威分级。
异构来源的知识先**对齐**到同一套知识原子坐标系（见 5.1），同一知识原子可能被多个来源以
不同方式陈述，各来源按「认识论优先级」（实测观测 > 规范声明 > 描述性推断）排序，冲突时高优先级者胜出。

**作用**：支撑可控原则。它让系统既能「融合多源以获得更全的知识」，又能「在需要时回到单一来源」，且不因来源矛盾而失稳。

**应用位置**：知识中枢层（§2.2），直接支撑 §1.3 选择三「单源与多源可切换」。

### 5.4 档案与源分离（★ 原「骨架与源分离」已改写）

**抽象**：把「**协议结构声明**」与「每次从源抽取的**动态知识**」分离存储。
· 协议结构声明 ⇒ 落在**档案** `profiles/<协议>/profile.json`（★ 只承载结构声明，如必填头）
· 动态知识 ⇒ 来自五个源的自动抽取
★ 原设计的「跨实验复用的**协议骨架**」已**消解并物理移除**（2026-11-10）：
`profiles/*/skeleton.json` 与物化逻辑**全部删除** ⇒ 「骨架常驻保证极限单源链路不断」
的说法**不再成立**。

**作用**：支撑可控原则。分离后，能精确地「抽掉某一来源」，把变量隔离干净，从而**可归因**
「某来源到底贡献了什么」；而**协议结构本身**由档案**独立可控**
（纯源档下不声明即为空）⇒ ⇒ ★ **切换/关闭来源只动知识，不动协议结构**。

**应用位置**：档案在**项目侧**（`profiles/<协议>/`，★ 不随知识库更换）；抽取结果进
知识中枢层（§2.2）；是 §1.3 选择三所依赖的**可归因隔离**基础。

### 5.5 确定性与幂等

**抽象**：知识的存取顺序显式化，同输入必得同输出；流程可重复执行且结果一致。

**作用**：支撑可信原则。确定性使基线可以重标定、回归可以逐条比对、实验可以复现。没有确定性，一切「新增为零、消失为零」的验收都无从谈起。

**应用位置**：知识中枢层（§2.2），并由种子校验层（§2.5）的可复现校验负责把关。

### 5.6 投影式消费

**抽象**：新增知识形态时，不修改下游，而是把新知识「投影」成下游已认识的既有形态。

**作用**：支撑可扩展原则，是「适配器」思想的应用。它把知识层与消费层解耦，使知识体系的演进不再「牵一发而动全身」。

**应用位置**：知识整理层（§2.3）。

### 5.7 分层生成（守正与出奇）

**抽象**：种子生成按「守正 → 出奇」的梯度分层，从保证合法完整，到注入危险触发缺陷，逐层递进。

**作用**：直接服务于核心目标的两面性——模糊测试既要「跑得通」又要「戳得到」。分层还使「哪一层贡献了最多有效种子」成为可度量的归因口径，支撑实验结论的科学性。

**应用位置**：种子生成层（§2.4），对应 §1.3 选择四「守正与出奇分层生成」。

### 5.8 确定性前置与理解分离

**抽象**：把「定位与切分」（确定性、零成本、可复现）与「理解与结构化」（需要语言模型、有成本）两个阶段分离。

**作用**：支撑可信与可控。确定性前置保证定位精准、可溯源、零额外成本；语言模型只在被切好的片段上做定点理解，既控制了成本，又使理解结果天然可归因到具体片段。

**应用位置**：知识抽取层的规范抽取通道（§2.1），对应 §1.3 选择一。

### 5.9 图增强检索（GraphRAG）—— ★ 问题三中「RAG」的具体形态

**抽象**：将知识组织为「实体—关系」图，检索方式是图上多跳子图导航，而非向量相似度匹配。图的节点是协议实体（状态、方法、字段），边是两类关系（「某方法必含某字段」「某状态经某方法转移」）；检索时从目标实体出发做有限跳的广度扩展，取出与目标相关的子图。

**作用**：这是「知识如何被高效取用」的核心范式，也是「结构化知识图谱」定位的直接体现。
★ 与向量 RAG 的差别：向量 RAG 靠**语义相似度**召回片段，GraphRAG 靠**图上的关系路径**召回
「生成某个消息所需的完整上下文」（如「某状态经某方法转移」所需的状态、字段、取值）⇒ ⇒
在本任务里，**关系完整性比语义相似度更重要**——少一个必需字段，种子就不合法。相比整包喂入，子图检索更聚焦、更省、且能做多跳推理；相比向量检索，它保留了证据链，与溯源理念一脉相承。它还支撑了「先整包喂入验证可行性、再子图检索优化」的两步消费策略——前者回答「知识能否指导生成」，后者回答「如何更准更省地生成」。

**应用位置**：知识整理层（§2.3）的子图检索，依赖知识中枢层（§2.2）组织出的图结构；
其结果供种子生成层（§2.4）组装时使用。
★ 与 LLM 的分工：**检索（召回上下文）由图负责，生成（组装报文）由 LLM 负责** ⇒ ⇒
LLM 不再凭空编造协议行为，而是**在检索到的、有证据的知识上**组装种子。

### 5.10 多道校验闸门

**抽象**：知识要转成可执行的规则或种子，必须逐道通过「校验闸门」——算子是否可解析、字段是否绑定到已知字段、期望行为是否落在受控词表内、主语是否为空等。任何一道不通过，产物只作「知识候选」留存，不进入生成链路。

**作用**：它是「可信」原则在转换环节的落地。通过显式、多道的校验而非一次性生成，把「转换失败」从「静默丢弃或污染」变成「可追溯、可计数的降级」，使每一条真正进入生成链路的规则都经过了验证。

**应用位置**：种子生成层的转换环节（§2.4），并由种子校验层（§2.5）的准入校验共同把关。

## 六、总结

本系统的设计可以归结为一句话：**以「知识优先、溯源优先」为理念，以「可信、可控、可扩展」为准绳，构建一条「抽取 → 中枢 → 消费 → 生成 → 闸门」的单向知识流水线。**

按三个核心问题收束：

- **问题一（对齐）** ⇒ 用**知识中枢**解决——知识原子化承载信息，溯源承载证据，
  多源分级承载可归因，确定性承载可复现 ⇒ 异构来源的知识落到同一套坐标系，
  且**每条都说得清自己从哪来**；
- **问题二（通用框架）** ⇒ 用**确定性前置与理解分离 + 档案与源分离**解决——主程序不含
  协议分支，换协议、换来源只换数据不换机制；
- **问题三（用 RAG + LLM 出种子）** ⇒ 用**图增强检索 + 分层生成 + 多道闸门**解决——
  检索负责召回完整上下文（GraphRAG），LLM 负责在有证据的知识上组装，
  分层生成做到「守正保底、出奇触发」，闸门守住最后一道契约。

整条设计的深层一致性在于：**每一个局部设计，都是「可信、可控、可扩展」三原则在某一环节的具体投影**。理解了这三条原则，就理解了整个系统的设计逻辑。
