# Fused Canonical Serialization v2 Spec

> 状态：Draft（随 `core/fused/hub/canonical.py` 同步）
> 来源：fused_knowledge_hub_design.md 第三部分 Subject / Aspect 等结构

## 1. 规范（10 条）

```
1. dict 键按字典序升序
2. 字符串 UTF-8 编码
3. 数字：整型原样; 浮点用 repr()
4. null / None: 默认不输出该键 (避免空值歧义)
   ——若某字段语义上允许 null 且必须存在, 用 "__NULL_SENTINEL__"
5. bool 序列化为 true / false (小写)
6. 递归处理嵌套 Subject (含 relation qualifiers)
7. 联合类型 (Condition / Locator) 按 type 字段排序
8. 输出 UTF-8 字节序列
9. 无尾随空白
10. 严格模式: 任何非规范输入 → canonical 内部处理, 上层负责 fail-closed 校验
```

## 2. 特殊情况

- **None 默认不输出**：dataclass 经 `asdict` 转 dict 后由 `_normalize` 递归过滤 `None`（dict / list / tuple 递归）。
  （注：`dataclasses.asdict` 本身**保留** None，实际过滤发生在 `_normalize`）
  Sentinel 仅在「字段必须存在但可空」时显式写 `__NULL_SENTINEL__`（模块私有常量 `_NULL_SENTINEL`，定义于 `core/fused/hub/canonical.py:20`）。
- **嵌套 Subject**：通过 `_normalize` 的递归完成。
  Relation Subject 的 qualifiers 里嵌套 Subject 会被一并序列化。
- **联合类型**：本规范**不要求**特殊处理 —— asdict 已统一拆为 dict，
  字典序即可保证「type 字段在前」与其他字段一致。

## 3. ID 计算

```python
fact_id     = "f2_" + sha256(canonical_serialize(fact_key)).hexdigest()[:16]
claim_id    = "c2_" + sha256(
                  canonical_serialize(value) + epistemic_type.encode("utf-8")).hexdigest()[:16]
evidence_id = "e2_" + sha256(
                  source_type.encode("utf-8")
                  + source_id.encode("utf-8")
                  + canonical_serialize(locator)).hexdigest()[:16]
```

> 实现见 `core/fused/hub/canonical.py:128-142`。`f2_` / `c2_` / `e2_` 是 v1 退役后保留的
> v2 前缀（与历史 `f1_` / `c1_` / `e1_` 产物隔离）。哈希输入的拼接顺序与上表一致：
> fact 按 canonical 序列化的 fact_key；claim 按 canonical 序列化的 value 再接
> epistemic_type；evidence 按 source_type + source_id 再接 canonical 序列化的 locator。

设计真源: fused_knowledge_hub_design.md 设计哲学 P7（确定性、可复现）与第四部分「防矛盾机制」

## 4. 实现: `core/fused/hub/canonical.py`

- `canonical_serialize(obj) -> bytes`: 走 `_normalize` 后 `json.dumps(sort_keys=True, ensure_ascii=False)`
- `compute_fact_id(fact_key)`, `compute_claim_id(claim)`, `compute_evidence_id(evidence)`
- 模块加载时跑 `_self_tests()`（6 用例，见 `core/fused/hub/canonical.py:27-74`；调用点 `core/fused/hub/canonical.py:150`）：
  1. 确定性
  2. 键排序
  3. 嵌套递归
  4. 不等时不同
  5. 等时同
  6. 空字段不输出

## 5. 反例（错误用法）

- 把 dataclass 直接传给 `json.dumps`（漏了 `asdict` + `_normalize` 转换）
- 用 `pickle`（二进制, 不可读, 平台相关）
- 自定义 key 排序逻辑（应当只让 `_normalize` 决定）
- 把 `str` 与 `bytes` 混用（必须 UTF-8 字符串, 二进制数据用 `binary` Value 类型）（`binary` 为 Layer 0 定义的 12 种 ValueType 之一，见 `fused_knowledge_hub_design.md` §Value 表）
