# 种子校验层设计（seedcheck）

> ★ **定位**：协议模糊测试流水线的**第六层** —— 只负责**检查生成种子的质量**。
> ★ **与代码审查分开**：`guard/` 是**代码审查**（查代码/契约/文档）；
>   `seedcheck/` 是**产物审查**（查种子）⇒ 两者互不依赖。
> ★ 目录：`E:\科研\想法idea\ProtoKG\seedcheck\`（与 `core/` `scripts/` `guard/` **顶层并列**）。

---

## 一、三条核心原则

### ① 校验 ≠ 过滤

**只有 V1（格式必假）阻断**；V2~V4（协议越界）**只打标**。

> ★ **为什么**：被阻断的种子**可能正是能触发漏洞的输入**。
> 「缺必填头」「Session 错」「URI 不存在」这类**协议违反**，恰恰是 fuzzing 最有价值的面
> （服务器可能报错、可能崩溃）⇒ ⇒ 丢弃它等于**主动扔掉潜在漏洞触发面**。

⇒ ⇒ 三类种子：

| 类别 | 例子 | 服务器反应 | 价值 | 处置 |
|---|---|---|---|---|
| **格式非法** | 缺 CRLF、方法行不合法 | **必然拒** | 零 | 🔴 **阻断**（丢弃） |
| **协议越界** | 缺必填头、Session 错、状态机顺序错 | 可能拒/报错/崩溃 | ★★ 高 | 🟢 **打标保留** |
| **合规** | 一切符合规范 | 正常处理 | 低 | 🟢 保留（保底覆盖） |

### ② 判据只来自中枢

校验器自己**一条硬编码都不该有** ⇒ 协议知识一变，校验口径自动跟着变。

| 要校验的 | 判据来源（中枢维度） |
|---|---|
| 必填头齐不齐 | `required_header_by_method` / `required_header_global` |
| 方法存不存在 | `existence`（method 主体） |
| 前置链对不对 | `precondition` |
| 第 N 次起带什么头 | `session_header` |
| 取值填得对不对 | `value_enum_spec`（规范域）/ `value_enum_observed`（实测候选） |
| URI 资源是不是协议声明的 | `profile.resources_file` |
| 资源在不在目标环境 | 环境清单（`playable_resources_file`） |
| 状态机顺序合法 | `target_state` |

### ③ 可追溯

每条违规都带 `evidence`（判据来源）⇒ 否则使用者无法判断该不该修。

## 二、六层检查

| 层 | 检查 | 判据来源 | 协议化 | 处置 |
|---|---|---|---|---|
| **V1** | 非空 / 可切块 / 首行 ≥2 空格 / 头行有冒号 / 以空行结尾 | 规则（5 条最小集） | ❌ | 🔴 **阻断** |
| **V2** | 必填头齐 / 方法存在 / 资源在清单 / 前置链有序 / 会话语义 / **取值合法（★已降级为统计）** | 中枢 6 维度 | ✔ | 🟢 打标 |
| **V3** | 资源 ∈ 目标环境可播集 | 环境清单 | ✔ | 🟢 打标 |
| **V4** | 哪些方法**未被状态机覆盖** | `target_state` | ✔ | ⚪ **只统计**（知识完备度信号，不是违规） |
| **V5** | 内容重复率 / 序列重复率 / 首方法集中度 / 相邻全等率 / 层覆盖 | **本次运行统计** | ❌ | 🟡 **告警**（阈值） |
| **V6** | 报文序列在协议语义上是否合理 | **LLM** | ✔ | ⚪ **只报告** |

### V1 为什么「协议无关」

V1 只判「**任何**协议都不接受的形式」⇒ 对 RTSP / SIP / HTTP 全成立 ⇒ **零误差**。
协议特有格式（URI scheme、方法名是否合法…）**不在 V1 判** ⇒ 交给 V2（用中枢知识判）。

⇒ ★ **目标协议是已知的**：`manifest.json` 里有 `protocol` 字段 ⇒ 不存在「不确定」。

## 三、关键判据的两个修正（2026-11-11 实测踩到）

| 判据 | 初版 | 修正后 | 原因 |
|---|---|---|---|
| URI 形态 | 「URI 含模板占位符名 `{stream}`」 | **资源段 ∈ `resources_file`** | 占位符**已被替换**成实际资源名 ⇒ 占位符名不会出现在 URI 里 |
| 取值合法 | 「值 ∈ `value_enum_spec`」 | **同构变体不算违规**（数字归一后比对） | 规范域抽到的是**示例值**（`client_port=46902-46903`）⇒ 种子用 `50000-50001`（**同样合法**）⇒ 直接判会产生大量误报 |
| 方法不在状态机里 | 报违规 | **只统计** | `DESCRIBE` 等合法方法本就不在 A.1/A.2 表里 ⇒ 用它们不违反协议 |

⇒ ⇒ 误报从 **138 + 108 + 38** 降到 **0**（保留 20 条**真违规**）。

```
seedcheck/_out/<协议>/<时间戳>/
├─ seed_preflight.json   ← 结构化：groups / per_seed(tags) / metrics / violations
```

| 分级 | 含义 |
|---|---|
| `compliant` | 合规 |
| `edge_case` | 协议越界（★ 高价值面） |

## 五、运行方式

```bash
# 基本（协议从 manifest 读；语料默认取最新一次）
python seedcheck/run.py --protocol rtsp --seed-dir derived/seeds/rtsp/<ts>

# 指定目标环境（V3 才有判据）
python seedcheck/run.py --protocol rtsp --seed-dir <dir> --target-env rq2-live555

# 加 LLM 语义审查（只出报告，不阻断；配置与 build_hub 同构）
python seedcheck/run.py --protocol rtsp --seed-dir <dir> --llm \
       --model deepseek-chat --base-url https://api.deepseek.com
```

| 参数 | 说明 |
|---|---|
| `--seed-dir` | 语料目录 |
| `--protocol` | 默认从 manifest 读 |
| `--target-env` | 环境名（不指定 ⇒ V3 跳过） |
| `--model/--base-url/--api-key` | **与 `build_hub.py` 完全同构**（默认读 `LLM_*`） |
| `--llm` | 是否跑 V6（默认关） |

**退出码**：V1 有违规 ⇒ 1；否则 0。

## 三·补 · V2「取值合法性」已**降级为统计**（2026-11-11 实测 sip 触发）

★ **现象**：sip 的 22 条种子**全部**被判「越界」，违规 114 条，全部是
  ``value_outside_domain``（``Call-ID`` / ``Via`` 这类**会话级头**）。

★ **根因**：中枢的 ``value_enum_spec`` 抽到的是**规范文本里出现过的示例值集合**，
  **不是「封闭取值域」**：
  · sip 的 ``Call-ID`` 域 = ``843817637684230@998sdasdh09`` 等 **3 个实例值**
  · rtsp 的 ``Range`` 域 = ``npt=0-`` 等 **12 个示例**
⇒ 而**实例型值**（会话 id / branch / tag / 端口 / 时间戳）**每次会话都不同**
⇒ ⇒ 用「值 ∈ 域」的成员判定**必然误报**。

★ 且中枢**缺「头模式」知识**（实测：rtsp 的 ``syntax`` **0 条**；sip 的 **45 条全是头名**）
⇒ ⇒ 无法用「模式匹配」替代成员判定。

★ **处置**：``value_outside_domain`` **只统计、不判违规**
  ⇒ 写进 ``metrics.value_domain_mismatch``（含按头分布）
  ⇒ 不再污染「合规 / 越界」分级。

★ **要恢复这项判定**，中枢需补其一：
  ① **封闭取值域声明**（与「示例值」区分开）
  ② **头的语法模式**（ABNF/BNF 片段）⇒ 见 `值形态与比较语义.md`
