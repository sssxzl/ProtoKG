# RFC 知识抽取的完整处理流程（规范源）

> ★ **定位**：规范源（`spec` / RFC 文本）的**知识抽取**段设计说明
> ⇒ 即「一份 RFC 纯文本 ⇒ 一批带位置、带证据、带统一标识的事实」的全过程
> ★ **协议无关**：本文描述的是**方法**，不绑定任何具体协议

---

## 〇、总览：8 步主线 + 4 组旁挂能力

```
① 文档清洗 + TOC 隔离
      ↓ 内容行列表（每行带原始行号）
② 标题识别（章节号 + 标题文本 + 命中模式）
      ↓  标题序列
③ 章节树（按章节号层级归属）
      ↓  章节节点
④ 块解析（自底向上合并，受预算约束）
      ↓  「窗口」列表（窗口 = 一节正文 + 其子节正文）
⑤ 类型判定（三层判据：形态 → 标题形态 → 散文句式）
      ↓  窗口被标成某类「候选类型」
⑥ 结构化通道抽取（10 条通道并行，各管一种形态）
      ↓  中间表示（norm：文本 + 位置）
⑦ LLM 通道（只补规则补不到的）—— ★ 两个入口 + 通道 J（段落粒度）
      ↓  中间表示（norm：文本 + 位置 + 规范声明字段）
⑧ 质量闸（fail-closed）→ 映射为事实（统一标识 + 证据强度 + 证据位置）
```

★ **旁挂的四组能力**（★ 不改主线，但决定「产物可不可信 / 可不可追溯」）

| 组 | 章节 | 落点 | 产物去向 |
|---|---|---|---|
| **规范规则契约** | §十 | Rule Slot 进身份 · Assertion 进声明值 · 三级校验 | **进 fact 空间**（`definition`） |
| **覆盖台账** | §九 | 两本台账 + 两项覆盖率 | ★ **元数据**（不进 fact 空间） |
| **文档登记** | §十一 | 文档自述状态 / Updates / Obsoletes | ★ **元数据**（不进 fact 空间） |
| **缓存版本化** | §十二 | 缓存键含模型/推理/解析器/Schema/校验器版本 | 缓存文件（**入库**） |

⇒ ⇒ ★ **主线不变、旁挂增强** ⇒ ⇒ 新增能力**默认关闭** ⇒ ⇒ 关闭时产物**逐字节不变**。

## 一、文档清洗 + TOC 隔离

### 做什么
- 去掉**页眉页脚**（每页重复出现的机构名、页码、RFC 编号行）
- 识别并**隔离目录块（TOC）**
- 丢掉**首个标题之前**的内容（封面 / 摘要 / 版权段）
- 修正行号偏移

### ★ 关键纪律：清洗与 TOC 隔离必须**共用一条路径**

> 历史上存在**两条清洗路径**：一条给「规范抽取」用，另一条给「约束候选抽取」用
> ⇒ ⇒ 出现「一边隔离了目录、一边没隔离」的**判据分裂**
> ⇒ ⇒ 目录里的方法名被当成真知识抽出来 ⇒ ⇒ **TOC 污染**。
>
> ⇒ ⇒ **处置**：把清洗抽成**两个共享入口函数**，**所有**通道都必须走它们
> ⇒ ⇒ 这条纪律的普适表述：**「同一份文档的预处理，只能有一条实现」**。

### 产出
内容行列表，每行携带**原始行号**
⇒ ⇒ 行号一路带到事实的证据里 ⇒ ⇒ **任何一条知识都能回溯到原文哪一行**。

---

## 二、标题识别

### 做什么
把正文里的「章节标题行」挑出来，拆成**章节号** + **标题文本**。

### 难点与对策

| 难点                                  | 对策                                                       |
| ----------------------------------- | -------------------------------------------------------- |
| 标题排版**因文档而异**（顶格 / 带编号 / 全大写 / 带括号） | **宽松的多模式匹配**（编号式 / 全大写式 / 缩进式 / 纯标题式），并**记录命中的模式**供后续判定用 |
| 正文里**长句也以数字开头**                     | 要求「编号 + 短标题 + 后接空行」等**组合特征**，不单看编号                       |
| 有些标题**无编号**（纯文字标题）                  | 单独一档模式，但**不参与章节号推导**                                     |


### 产出
标题序列（章节号 + 标题 + 行号 + 命中模式）

---

## 三、章节树

### 做什么
按**章节号的层级**（`4` → `4.2` → `4.2.1`）把标题序列组织成树。

### 为什么需要
- 后续「窗口」要按**语义完整**的章节范围切，而不是按固定行数切
- 章节号是**跨文档比较**的唯一可靠锚点
  ⇒ ⇒ 但多份规范**章节号会重号** ⇒ ⇒ 因此还需要「**按文档限定**的章节配置」

---

## 四、块解析（自底向上合并 + 预算）★

### 做什么
把章节树**自底向上**合并成「**窗口**」：
> 一个窗口 = 某节的正文 + （受预算约束的）其子节正文

### 为什么是「自底向上」
> 规范里**关键信息常在子节里**（如「某字段的取值范围」写在字段说明的小节中）
> ⇒ ⇒ 从叶子往上走 ⇒ 每个窗口**自带完整的局部上下文**
> ⇒ ⇒ 判据不必依赖全局记忆。

### ★ 预算（上下文膨胀防护）

| 预算项 | 默认 | 防的是什么 |
|---|---:|---|
| 向上合并层数上限 | **2** | 父节正文被**每个**子节反复携带 ⇒ 窗口体积爆炸 |
| 单窗口字符上限 | **4000** | 超长章节把上下文撑爆 |
| 重复正文去重 | 开 | 同一段文字多处重复 ⇒ 浪费预算 + 导致重复抽取 |
| 环检测 | 开 | 章节树异常成环 ⇒ 无限合并 |

⇒ ★ **设计要点**：预算**不是性能优化，而是正确性保障**
⇒ ⇒ 窗口太大 ⇒ LLM 通道的成本与输出漂移都会失控。

## 五、类型判定（三层判据）

### 做什么
给每个窗口判定「它像什么」⇒ ⇒ 决定**哪些通道会来看它**。

| 层            | 判据           | 例子（形态级）                                                      |
| ------------ | ------------ | ------------------------------------------------------------ |
| **第一层：内容形态** | 看**排版结构**    | 三列以上的表格 / 缩进条目 / `ABNF规则 = …` / `字段: 说明` 列表                  |
| **第二层：标题形态** | 看**标题文本的构词** | 首字母大写的驼峰词（像字段名）/ 全大写词（像方法名）/ 小写带连字符（像选项名）                    |
| **第三层：散文句式** | 看**句式模板**    | 「`XXX` MUST …」/「The `XXX` command …」/「`XXX` is defined as …」 |

### ★ 为什么排第一的是「形态」而不是「语义」
> 语义判据（"这段在讲方法"）依赖**英文措辞** ⇒ ⇒ 换协议 / 换作者就失效。
> ⇒ 形态判据（"这是三列表格"）是**排版事实** ⇒ ⇒ 跨协议稳定、跨作者稳定。

⇒ ★ 三层是**级联兜底**：第一层认不出 ⇒ 试第二层 ⇒ 再认不出 ⇒ 试第三层。

⇒ ★ **实测口径（2026-11-13 逐协议核查，务必照此表述）**：
> ★ 类型判定是**辅助分类**，**不是**通道的**准入条件**。
> 实测：判定命中率仅 **8~18%**（rtsp 17.6% / sip 14.4% / smtp 7.8% / DHCPv4 14.7%）
> ⇒ 但各通道的产出**远超**判定命中的数量
> ⇒ ⇒ **各通道各有独立的形态判据**，不共用这一套判定 ⇒ ⇒ 这是**判据冗余**（好事：单一判据失效不影响整体）。
> ⇒ ⇒ **不要**写成「判不出来 ⇒ 就交给 LLM 通道」的强因果。

⇒ ★ **实现落点**：三层判定集中在**独立的分类器模块**（与抽取器分离）⇒ ⇒ 判定规则可单独测试。

## 六、结构化通道抽取（10 条并行）

### 总原则
> **每条通道只负责一种形态**，互不重叠；通道之间**不共享判据**（避免判据分裂）。

| #   | 通道           | 形态                            | 抽什么            |
| --- | ------------ | ----------------------------- | -------------- |
| A0  | ABNF 方法枚举    | `Method = INVITEm / ACKm / …` | 方法集合           |
| A0b | ABNF 命令规则字面量 | `cmd = "AUTH"`                | 命令名            |
| A0c | 散文命令格式声明     | 「The `STARTTLS` command …」    | 命令名            |
| A0d | 消息清单表        | 「消息类型 / 方向 / 必填字段」表           | 消息清单           |
| A   | 缩进命令条目       | `CMD arg1 arg2`               | 方法 / 命令 + 参数   |
| B   | 缩进字段 / 类型条目  | `Field: type`                 | 字段名 + 类型       |
| C   | 缩进状态码表       | `250 OK`                      | 状态码            |
| D   | 字段取值样本       | 正文里出现的取值枚举                    | 字段的合法取值**样本集** |
| E   | ABNF 字段定义    | `Field = "a" / "b"`           | 字段 + 语法        |
| F   | 状态转移表        | 「从 / 消息 / 到」三列表               | 状态机边           |

### ★ 通道 F 的两个关键设计（最值得复用）

**① 按「列角色」解析，不按「列序号」**
> 状态机表的列顺序**因文档而异**（有的「发出的消息」在前、有的在后）
> ⇒ ⇒ 用**表头列名**判定每列的角色（谁表示「从」/ 谁表示「消息」/ 谁表示「到」）
> ⇒ ⇒ 好处：同一张表的**两种视角**（客户端视角表 / 服务端视角表）都能解析
> ⇒ ⇒ 一份规范产出一套**完整**状态机。

**② 支持「状态名继承」（留空 = 沿用上一行）**
> 规范里的状态机表常用**省略左侧列**的写法（后继行继承上一行的「从」状态）
> ⇒ ⇒ 解析时**必须按列位置**切（不能按内容切）⇒ ⇒ 用「上一行的状态名」补齐后继行
> ⇒ ⇒ 不丢边。
>
> ★ **实测口径**：状态机通道有**两个实现并存、合并去重**后使用
> ① 「三列定宽 + 状态名继承」的直读实现
> ② 「按形态切块 + 按表头列名判定列角色」的通用实现
> ⇒ 两者结果**等价**（同协议的转移集相同），② 额外提供「按形态定位 + 逐行溯源」
> ⇒ 且**不依赖章节树**（⇒ 附录里的表也能覆盖）。

### ★ 通道 D 的一条纪律
> 取值样本抽到的是「**规范里出现过的取值集合**」，**不是「封闭取值域」**。
> ⇒ ⇒ 这个区分在下游**直接决定**「取值合法性」这项检查能不能做
> ⇒ ⇒ 用成员判定去判**必然误报** ⇒ ⇒ 详见《种子校验层设计》。

## 七、LLM 通道（只补规则补不到的）

★ 定位都是「**规则补漏**」⇒ ⇒ **不产生新形态的知识**，只补**散文里的语义**。

| 通道 | 补什么 | 触发条件 | 粒度 |
|---|---|---|---|
| **状态机散文腿** | 表格抽不到的**散文状态机 / ASCII 状态图** | 规范**有**状态机但表格腿抽不到 | 文档 |
| **散文语义腿（按文档）** | **纯散文**文档里的语义 / 约束 | 该文档**没有任何结构化形态命中** | 文档 |
| **散文语义腿（按段落）＝通道 J** | ★ **混合结构文档**里未被规则覆盖的散文义务 | 该**段落**命中候选信号 | ★ **段落** |

### ★ 散文语义腿的四个设计

| 设计 | 内容 | 理由 |
|---|---|---|
| **触发粒度** | ★ 按文档（零命中）或 ★ **按段落**（候选信号） | ⇒ 混合结构文档里的散文义务**不再因为「同篇有表格命中」而整体跳过** |
| **候选信号 ≠ 证明** | 规范性关键词 / 条件句式 / 异常处理 / 跨节引用 ⇒ ★ **只是筛选信号** | ⇒ 「不含关键词」≠「不具规范性」（RFC 8174）⇒ ⇒ 缺口由**独立抽样检查**兜底 |
| **★ 反幻觉靠「可核对」不靠「白名单」** | 产出必须带**行号**，且**该行原文必须出现所声称的实体名** | 白名单会**挡掉通道的主要价值**（它恰是要抽「结构化没抽到」的新实体）；而「行号 + 该行原文」第三方**可核对** ⇒ 更强且不挡路 |
| **批量化 + 增量缓存 + 重试 + 运行保护** | 片段**合并成一次调用**；每批成功就**增量落缓存**；失败**重试一次**；超时/并发/熔断/重复调用检测 | 逐份调用 ⇒ 分钟级不可用；整批失败 ⇒ 全量重跑；LLM 偶发超时 ⇒ 重试通常就好；★ 影子模式**不是「零运行风险」** |

### ★ 结构：**切块 + 共享内核**（★ 2026-11-13 重构）

```
_extract_blocks(protocol, blocks, …)   ← 共享内核（缓存/批量化/LLM/运行保护/过滤/产 norm）
   ├─ extract_prose_norms(files)       ← 按**文档**切块
   └─ extract_window_norms(files)      ← 按**段落**切块（通道 J）
```
⇒ ⇒ 两个入口**只在切块粒度上不同** ⇒ ⇒ 缓存 / 批处理 / 运行保护**完全同源**。

### ★ 一个必须记住的坑：推理模型的「思考 token」

> **推理模型**的「思考 token」会**先**吃掉输出预算
> ⇒ 表现是「正式输出为空」⇒ 看起来像「LLM 没返回」
> ⇒ 实际是 `finish_reason=length`（输出被截断在思考阶段）
> ⇒ ⇒ 用推理模型时**输出预算必须给足**（实测 4000 不够、16000 正常）。
> ⇒ ⇒ 且**客户端超时必须给足**（实测单次 27.5s ⇒ 60s 会**偶发**超时 ⇒ 默认 300s）。

### 可复现性
两条 LLM 通道都带**磁盘缓存**（★ 缓存键**版本化**，见 §十二）
⇒ ⇒ **命中即不调 LLM** ⇒ ⇒ 产物**逐字节可复现**
⇒ ⇒ 缓存**入库**（否则「别人 clone 后跑不出同样结果」⇒ 复现性只是名义上的）
⇒ ⇒ ★ 缓存带 `complete` 标志 ⇒ **未跑完的不算命中** ⇒ 失败不会永久掩盖缺口。

## 八、质量闸（fail-closed）→ 映射为事实

### ★ 抽取结果的三类（★ 不进 fact 空间的另两类）

| 类别        | 定义                                | 去向                       |
| --------- | --------------------------------- | ------------------------ |
| **已证实事实** | 证据支持**全部**关键语义字段，且通过**当前版本**的自动校验 | ✔ **进 fact 空间**          |
| **待审候选**  | 有一定证据，但关键语义未确认（强度/极性/条件/例外任一不确定）  | ★ **不进 fact 空间** ⇒ 写候选台账 |
| **拒收结果**  | ★ **抽取错误**（声明与原文证据不一致）            | ★ 只留**诊断记录**             |

⇒ ⇒ ★ **两类问题必须分开判断**
· **抽取错误** ⇒ 拒收 / 待审
· **规范声明冲突**（两条声明**均有证据支持**但可比较作用域内要求不一致）
  ⇒ ⇒ ★ **保留两条声明**，标记冲突 / 待消解 ⇒ ⇒ **不得**因来源冲突直接拒收

⇒ ⇒ ★ **禁止**「因否定/条件未落在跨度内 ⇒ 丢掉极性 ⇒ 保留正面陈述」
⇒ ⇒ 证据不足只能**拒收或待审**。


### 质量闸的三项判据

| 判据 | 查什么 | 失败意味着 |
|---|---|---|
| **结构合法性** | 每条事实的标识 / 主体 / 维度 / 条件是否符合契约 | 产出物不合规 ⇒ **下游会崩** |
| **重复事实标识** | 同一个标识被产出多次 | **归一时会被覆盖** ⇒ ⇒ 知识丢失 ⇒ ⇒ 必须为 0 |
| **目录残留** | 抽出来的知识是否**来自目录行**（字段名 `toc_sourced_outcomes` / `toc_lines_removed`） | 目录里的名字被当成真知识 ⇒ ⇒ 纯度污染 |

⇒ ★ **闸不通过 ⇒ 中止构建**，且**中止发生在「清理旧产物」之后**
⇒ ⇒ **构建失败不会破坏已有知识库**。

### 映射：中间表示 → 事实

| 中间表示的字段 | → 事实的字段 |
|---|---|
| 协议 + 版本 + 主体 + 维度 + 条件 | **统一标识** |
| 抽取到的内容 | **值**（按值的形态包装：文本 / 模式 / 标量 / 集合 / 结构） |
| 值的类型标记 | **证据强度**（规范强制 / 规范未指定 / …） |
| **原始行号 + 文档名** | **证据位置**（可回溯到原文那一行） |
| 来源通道 / 权威级别 | **声明归属** |

⇒ ★ **这一步的关键**：**统一标识**是后面所有「对齐 / 消解 / 查重 / 纯净度」的地基 ⇒ ⇒ 它必须**早定义、严定义**。

## 九、覆盖台账（两本 + 两项覆盖率）

★ 对应：**「结构化命中 ≠ 知识覆盖完整」**
⇒ 「某窗口的字段表解析成功」**不能**证明「该窗口里的条件性散文义务已被抽出」。

| 台账 | 回答的问题 | 记录内容 |
|---|---|---|
| **文本覆盖** | 原文是否**到达**了抽取输入？ | 三段映射：**原始输入** →（清洗/TOC 隔离，含排除原因）→ **清洗后正文** →（窗口归属）→ **抽取窗口** |
| **抽取覆盖** | 哪些知识**尝试抽过**、哪些**仍有候选**？ | 各通道产出 / LLM 触发原因 / **拒收原因** / 未处理候选 / 独立抽样漏检检查 |

⇒ ⇒ ★ **两项覆盖率**（★ 不用单一分母）

| 指标 | 分母 | 回答 |
|---|---|---|
| **原始输入核算率** | **原始输入全部行** | 每个原文区间都有**明确去向**（保留/合理排除/待检查）⇒ ⇒ 清洗误删会**暴露** |
| **有效正文窗口覆盖率** | **已确认属于抽取范围的正文** | 有效正文是否都进入了抽取窗口 |

⇒ ⇒ ★ 台账落**元数据**（`derived/per_source/<协议>/<源>/coverage.json`）
⇒ ⇒ **不进 fact 空间** ⇒ ⇒ **中枢零影响 / 契约零变化**。

## 十、规范规则契约（Rule Slot / Assertion）

★ 目标：让「**行为义务与禁止性约束**」有载体 ⇒ ⇒ **不新增 aspect**（仍是 21 个）。

### ★ 为什么必须把「行为位置」与「规范内容」分开

| 问题 | 说明 |
|---|---|
| **身份碰撞** | 事实身份由「协议+版本+主体+维度+条件」决定 ⇒ ⇒ 同主体同条件下的**多条行为规则**（`MUST send ACK` 与 `MUST update timer`）**撞成同一身份** ⇒ ⇒ 质量闸判重复 ⇒ ⇒ **只能留一条 ⇒ 义务丢失** |
| **冲突不可见** | 若把强度/极性也放进身份 ⇒ ⇒ 同一行为位置的**相反要求**（`MUST send ACK` 与 `MUST NOT send ACK`）**分成两个身份** ⇒ ⇒ **永不进同一槽位** ⇒ ⇒ **永不触发冲突处理** ⇒ ⇒ **冲突不可见** |

⇒ ⇒ **解法**

| | 组成 | 去处 |
|---|---|---|
| **Rule Slot（规则槽位）** | 协议+版本+主体+**kind**+动作+对象+条件+作用域 | ★ **进事实身份**（`subject.qualifiers` + `condition`） |
| **Assertion（规范声明）** | 强度 + 极性 + 条件 + 例外 + 作用域 | ★ **进声明的值**（规范化 JSON 文本 `[RULE:v1] {…}`） |

⇒ ⇒ ★ **相反极性声明 ⇒ 同一槽位** ⇒ ⇒ 现成的「多声明共存 + 冲突标记保留」机制**直接生效**
⇒ ⇒ ★ **不新增冲突机制**。

### ★ 三类数据必须分开（★ 决定「什么算冲突」）

| 类别 | 字段 | 参与语义比较 |
|---|---|---|
| **规范语义值** | 强度/极性/条件/例外/作用域/动作/对象 | ✔ |
| **原文/证据/校验元信息** | 原文措辞 / 证据引用 / 来源 / 校验器版本 | ✘（★ 差异**不得**造成伪冲突） |

⇒ ⇒ ★ **写入前预归一化**（键名排序、无空白、紧凑分隔符）
⇒ ⇒ **语义相同的声明 ⇒ 文本必然相同** ⇒ ⇒ 不伪冲突
⇒ ⇒ ★ 原文措辞 ⇒ 落 claim 的**证据记录**（不进 value）。

### ★ 三级校验

| 层级 | 机制 | 结果 |
|---|---|---|
| **L1** | 确定性检查（区间存在 / 关键词与原文一致 / 否定词须在证据里 / 字段完整性 / 三态合法 / 非语义字段未混入） | 不通过 ⇒ 拒收或待审 |
| **L2** | **独立**语义核验（独立 prompt + 独立上下文；输出逐字段判定 + 证据区间 + 依据） | 支持 / 不支持 / 不确定 |
| **L3** | **人工确认**的关键语义回归样本 | 衡量 L1/L2 可靠性 |

⇒ ⇒ ★ 「独立」的三层含义要分开：**独立调用 / 独立判断过程 / 独立事实证据**
⇒ ⇒ ★ 「独立上下文」≠「验证器必须看不同原文」⇒ ⇒ 应给「候选事实 + 能支持或反驳它的完整证据」
⇒ ⇒ ★ 「模型说是」**不构成证明**。

⇒ ⇒ ★ **确定性前置**（★ 不依赖 LLM ⇒ 可复现、可离线测）
| 机制 | 作用 |
|---|---|
| 跨行条件/例外抽取 | 从**跨行原文**抽条件/例外（不是手工填） |
| 跨节引用抽取 + **章节定位器** | 引用**真定位**（能定位 ⇒ `resolved`；不能 ⇒ `unresolved` ⇒ 待审） |
| **确定性语义支持检查** | 原文是否支持所声称的动作/对象/等级 ⇒ ★ **验证器自己**识别不受支持的结论（不靠 LLM 自证） |
| 条件**归一化**（带开关） | 未确认 ⇒ **不强制合并**；可靠确认 ⇒ **允许**合并 |
| **发布闸** | 主体可解析 + 强度已知 + 校验已证实 ⇒ 才进正式事实；否则**隔离** |

⇒ ⇒ ★ **主体归属（P0-1）**：★ `entity` 只是**原文提及的实体**，**不等于**义务承担者
⇒ ⇒ ★ 中间字段（★ **不扩展正式 fact 契约**）：`mentioned_entity` / `normative_subject` /
　 `subject_status` / `subject_span`
⇒ ⇒ ★ 主体须在**证据跨度内可核对** ⇒ 否则 `unresolved` ⇒ **不产 Rule Slot** ⇒ 归待审
⇒ ⇒ ★ **禁止**为获得稳定 FactID 而**猜测主体**

⇒ ⇒ ★ **L1 / L2 真实接入（P0-2）**：★ 流程 =
　 **LLM 抽取 → 规范化映射 → L1 → L2 → 最终状态 → 影子产物**
⇒ ⇒ ★ L2 **只对 L1 通过且字段齐备**的候选跑（成本控制）⇒ 独立 prompt + 独立上下文
⇒ ⇒ ★ 影子产物落 `derived/per_source/<协议>/<源>/verify.jsonl` ⇒ ★ **不进 fact 空间**
⇒ ⇒ ★ 最终状态：确认 / 待审 / 拒收（★ 影子模式下**不入正式事实**）

⇒ ⇒ ★ **条件/例外的角色（P0-3）**：condition / exception / purpose / qualifier /
　 alternative / concession / explanatory ⇒ ⇒ **让步（even if）/ 目的（in order to）/
　 替代（or contain）** ⇒ **不是**条件/例外 ⇒ ⇒ 未获证据支持的**不得**留在确认规则里

⇒ ⇒ ★ **三态严格区分**（★ 不得混用）
| 状态 | 含义 |
|---|---|
| **语义签字** | 业务预期**已人工认可** |
| **断言覆盖** | 测试输入与断言**真覆盖**该行为（不是只比 hash/字符串） |
| **实现验收** | ★ **在真实链路上跑通并被验收** |

⇒ ⇒ ★ 「语义签字 + 断言覆盖」**不等于**「实现正确」。

### ★ 规范关键词归一化（RFC 2119 / 8174）

| 原文关键词 | 强度 | 极性 |
|---|---|---|
| `MUST` / `REQUIRED` / `SHALL` | `MUST` | positive |
| `MUST NOT` / `SHALL NOT` | `MUST` | negative |
| `SHOULD` / `RECOMMENDED` | `SHOULD` | positive |
| `SHOULD NOT` / `NOT RECOMMENDED` | `SHOULD` | negative |
| `MAY` / `OPTIONAL` | `MAY` | positive |

⇒ ⇒ ★ **强度只表等级、极性只表极性** ⇒ ⇒ 避免双重否定。
⇒ ⇒ ★ **缺失值三态**：`stated` / `absent` / `unknown`
⇒ ⇒ ★ **「仅仅没抽到」⇒ 默认 `unknown`**（★ **不得**默认 `absent`）
⇒ ⇒ ★ **「不含关键词」≠「不具规范性」** ⇒ ⇒ 无关键词时**不得凭推测赋强度**。

## 十一、文档级登记（只标记，不拦截）

| 项 | 内容 |
|---|---|
| 登记内容 | 编号 / 标题 / **文档自述状态**（Category）/ 日期 / `Updates` / `Obsoletes` / `Also see` / 规范性引用 |
| ★ 标签语义限定 | ★ 只标「**该文档自身声明的信息**」⇒ 单篇旧 RFC 的头部**无法反映**后来其它 RFC 对它的更新或废弃 ⇒ ⇒ **不得**标「当前生效」 |
| **支持 `unknown`** | 抽不到的记 `unknown`（★ **不猜**） |
| **两级信息分开** | ① **文档类别** ② **单条 claim 的规范强度** ⇒ ⇒ 二者**不可混用** |
| **不门禁** | ★ **不因状态是 Informational 或已被 Obsoletes 就拒抽** ⇒ ⇒ 只**标记** ⇒ ⇒ 避免误伤 |
| **产物去向** | `derived/per_source/<协议>/<源>/documents.json` ⇒ ★ **元数据** ⇒ ⇒ **中枢零影响** |

⇒ ⇒ ★ **规范时效性风险仍未关闭**（跨文档效力核查未做）。

## 十二、缓存的版本化

| 项 | 内容 |
|---|---|
| **缓存键** | 提示版本 + **模型标识** + **推理配置**（温度/输出预算）+ **解析器版本** + **Schema 版本** + **校验器版本** + 输入指纹 |
| **模型快照** | ★ 记录供应商返回的**实际模型版本** ⇒ ⇒ 规避「模型别名指向的底层版本变化」 |
| **增量落缓存** | 每批成功即写 ⇒ ⇒ 失败只重跑失败的批 |
| **`complete` 标志** | ★ 未跑完的缓存**不算命中** ⇒ ⇒ **失败不会永久掩盖缺口** |
| **可审计** | 缓存文件记 `key_manifest` |

⇒ ⇒ ★ **两条结论要分开写**
① **缓存命中时产物可复现**（可保证）
② **重新调用同一模型能否再次生成逐字节相同的结果**（**不一定成立**）
⇒ ⇒ 不得把①说成②。

## 十三、这套流程里最值得记住的 8 条

| # | 经验 | 不这么做的后果 |
|---|---|---|
| 1 | **形态判据优先于语义判据** | 换协议 / 换作者即失效 |
| 2 | **清洗与 TOC 隔离必须共用一条路径** | 目录污染（假知识进中枢） |
| 3 | **窗口合并必须有预算** | 上下文爆炸 ⇒ 成本失控 + LLM 输出漂移 |
| 4 | **LLM 通道必须带缓存 + 指纹** | 每次构建产物都变 ⇒ 验收基线必漂 ⇒ 整个验收体系失效 |
| 5 | **LLM 的产出必须「可核对」**（行号 + 原文含实体名） | 幻觉直接进中枢 ⇒ 后面所有结论失去可信度 |
| 6 | **规范语义要把「行为位置」与「规范内容」分开** | 混在一起 ⇒ ⇒ 要么**身份碰撞**（义务丢失）⇒ 要么**冲突不可见** |
| 7 | **证据不足只能拒收或待审，绝不简化** | 「丢掉极性保留正面陈述」会把**禁止变强制** ⇒ ⇒ 规范语义反向 |
| 8 | **失败必须可观测、且不缓存失败结果** | 静默失败与空缓存 ⇒ ⇒ 缺口被永久掩盖 ⇒ ⇒ 看起来像「本来就没有」 |

## 十四、与其它源的关系（接入新源的范式）

规范源是**五源里形态最规整**的一个 ⇒ 它的方法可作为**样板**：

| 步 | 规范源怎么做 | 其它源怎么套用 |
|---|---|---|
| 1 | 列清单（能填哪些知识桶） | 同 |
| 2 | 定形态判据（本文 §五、§六） | 换成该源的形态（如源码的「函数定义 / 分支 / 字段用法」） |
| 3 | 物化到统一事实空间（本文 §八） | 同 |
| 4 | 过纯净度闸（单源 ⇒ 其它源痕迹为零） | 同 |
| 5 | 端到端验收（抽取 → 对齐 → 图 → 种子 → 审查） | 同 |
| 6 | 增益归因（多源 vs 单源，只变一个变量） | 同 |

⇒ ★ **规范源已跑通的判据**：单源在多个协议上**逐条 100% 满足结构合法性检查**
⇒ ⇒ 其它源应达到同一标准才允许进入多源融合阶段。
