# 各源设计

> 五个知识来源的**分源设计**文档。⇒ 每源一个子目录；跨源设计在**本目录**。

## 五个来源

| 子目录 | 源 | 它提供什么 | 本目录文档数 |
|---|---|---|---:|
| [规范源/](规范源/README.md) | 规范源（spec / RFC 文本） | 规范给**约束**：协议长什么样、哪些行为被要求、哪些被禁止 | 1 |
| [源码源/](源码源/README.md) | 源码源（协议实现源码） | 源码给**实现**：这个实现**实际**怎么发、怎么收 | 3 |
| [流量源/](流量源/README.md) | 流量源（真实抓包语料） | 抓包给**观测**：这套实现**真的**在发什么报文序列 | 5 |
| [专家注记源/](专家注记源/README.md) | 专家注记源（人工逆向与判断） | 专家注记给**判断**：人工逆向出的结构与启发 | 1 |
| [漏洞源/](漏洞源/README.md) | 漏洞源（历史漏洞库） | 漏洞给**历史**：这个协议**曾经**怎么被攻破 | 5 |

## 阅读顺序建议

1. 先读跨源框架（**各源的能力边界**）⇒ ⇒ 知道每源能补什么
2. 再按源读本目录 ⇒ ⇒ 理解该源的形态判据与规则集
3. 接入新源时照《规范源》的**8 步流程**做 ⇒ ⇒ 它是**最规整**的样板
