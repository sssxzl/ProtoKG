# 值形态与比较语义

> ★ **定位**：中枢里每条 claim 都带一个 `value`（`{"type": …, "data": …}`）。
> 本文档定义**这些值形态的归一目标形态与相等判定语义**——
> 即「两条 claim 的值什么时候算同一个」。
>
> ★ **它替代什么**：旧契约层（`property_registry.json` / `comparison_policy.json` /
> `phase_a.py`）曾声明「9 种 normalizer + 9 种 comparator」，但**零实现**；
> 该契约层已随重构移除 ⇒ 那份声明的**载体不存在了**。
> ⇒ 本文档是它的**现代等价物**：不按「property」组织，而按**值形态**组织
> （值形态才是比较语义真正取决于的东西）。
>
> ★ **为什么现在需要它**：结构化 value **已经落地**（实测中枢 `struct` 278 条 +
> `set` 117 条 = 全部 claim 的 25%）⇒ 旧 backlog 警告的
> 「**结构化 value 一旦落地，比较语义可能不完整**」**已实际发生**：
> 实测发现 **1 个 fact_key** 的两条 struct claim 仅**字段顺序**不同却被判为不等
> ⇒ 会误判「多源不一致」。

## 一、值形态总表（实测中枢的分布）

| `value.type` | 条数（claim 级） | 典型 aspect | `data` 形态 | 顺序语义 |
|---|---:|---|---|---|
| `text` | 998 | `definition` | 字符串 | 无（精确匹配） |
| **`struct`** | **278** | `message_instance` / `vuln_pattern` / `required_headers` / `legal_boundary` | dict | **按字段分**（见 §三） |
| `pattern` | 122 | `syntax` | 字符串 | 无 |
| **`set`** | **117** | `value_enum_spec` / `value_enum_observed` | list | **无序** |
| `scalar` | 60 | `existence` | bool / 数值 | 无 |

> ⇒ 简单形态（text/pattern/scalar）占 74% ⇒ 精确匹配即可；
> **需要语义判断的只有 struct 与 set 两种**（共 395 条 = 25%）。

## 二、归一目标形态

`_normalize_value(value)`（`core/fused/downstream/resolver.py`）：

| `value.type` | 归一目标 |
|---|---|
| `set`（或 `data` 是 list/set/tuple） | **排序后的字符串列表**（⇒ 无序比较） |
| `struct` | 逐字段：`UNORDERED_STRUCT_FIELDS` 内的**排序后的字符串列表**；其余**原样** |
| `text` / `pattern` / `scalar` | `data` 原样 |
| 未知 / 非 dict | 原样返回（**不猜、不丢**） |

## 三、struct 的四种形态与顺序语义（★ 关键）

| # | `data` 的键 | 语义 | 顺序 | 条数 |
|---|---|---|---|---:|
| ① | `fields: [{name, value}]` | 消息实例的**字段集合** | **无序** | 170 |
| ② | `headers: [...]` | 必填头清单 | **无序** | 23 |
| ③ | `action` / `trigger_sequence` / `trigger_field` / `streams` / … | 漏洞触发**序列** | **有序** | 65 |
| ④ | `target_field` / `operator` / `operand` / `operand_ref` / `precondition` / … | 语义算子（约束） | 逐字段定（`operand` 随 `operator` 变） | 20 |

### ★ 为什么**不能**对 struct 一刀切无序化

- ③ 的 `trigger_sequence` 是**序列**（`["SETUP","PLAY"]` ≠ `["PLAY","SETUP"]`）
  ⇒ 若无序化 ⇒ **触发语义被破坏** ⇒ 漏洞边界候选会误判
- ④ 的 `operand` 随 `operator` 变（`present`/`absent` 是集合语义，`eq`/`ne` 是标量）
  ⇒ 无序化会改写算子语义

⇒ ⇒ **只对明确无序的 `fields` / `headers` 无序化**（清单见
`resolver.UNORDERED_STRUCT_FIELDS`，**显式且最小**）。

## 四、相等判定契约

`_value_eq(a, b)`（两个 **claim**）：

| 情形 | 结果 |
|---|---|
| 任一侧 `value` 缺失 | `va == vb`（原样） |
| `set` / list，元素**顺序不同** | ✅ **相等** |
| `struct.fields` 字段**顺序不同** | ✅ **相等**（归一后） |
| `struct` **少一个字段** | ❌ **不等**（不按「包含关系」判等） |
| `struct.trigger_sequence` **顺序不同** | ❌ **不等**（序列语义） |
| `text` / `pattern` / `scalar` | 精确相等 |

## 五、消解语义（跨 claim 层）

值的**形态**决定「两个 claim 是否等价」；claim 之间的**裁决**由
`resolver._ASPECT_SEMANTICS` 决定（按 aspect）：

| 消解语义 | 适用 aspect | 行为 |
|---|---|---|
| `union` | `value_enum` / `value_enum_spec` / `value_enum_observed` / `occurrence` | **取值池**：多源并集，保留全部 claim 为 basis |
| `precedence` | `existence` / `target_state` / `state_changing` / `case_sensitivity` / `value_type` | **单值判定**：按认识论优先级取最高 |
| `consensus`（默认） | 其余 | 等价性判定 + 优先级裁决 |

> ⇒ **`union` 就是 set 形态的比较语义**（并集）；
> ⇒ **`consensus` 依赖 `_value_eq`** ⇒ struct 的归一化直接影响它。
