## 〇、为什么改：诊断结论（全部实测）

| # | 问题 | 实测证据 |
|---|---|---|
| **P1** | **纯度自证失败**：中枢自称 `source_set=['rfc']`，但大量事实来自 `profile` | smtp **81.8%**、rtsp/sip **~51%**、dhcpv4 **27.8%** 是纯骨架 fact |
| **P1b** | 纯度闸**形同虚设** | `rag_seedgen.py:1241` 无条件 `_allowed.add(SKELETON_AUTHORITY)` |
| **P2** | **中枢没有「实体」概念**，实体藏在 `fact_key.subject.name` | rtsp 88 实体中 **61 个跨 aspect 重复** |
| **P3** | **图与中枢不是同一套实体命名** | rtsp 图 12 个节点对不上中枢；dhcpv4 多 17 个 |
| **P4** | **语义知识与 fact 层两套体系** | 语义四库在 `rfc/semantic/rules.jsonl`，独立 id |
| **P5** | **16 桶填充率极不均衡** | dhcpv4 有 6 桶为 0；smtp `method_sequence` 226 条 vs `required_headers` 0 条 |
| **P6** | **冲突消解从未触发** | 四协议多 claim 数 = 0、`resolution` 数 = 0 |
| **P7** | **目录语义冲突** | `per_source/`（按源分）下面装着**跨源**的中枢 |

★ P7 的细节：`paths.py` 的注释自己承认了矛盾 ——
「源退化为事实内部的一个字段（`all_claims[].authority`），**不再作为目录层级**」——
**但目录位置没跟着改**（阶段 1.6 遗留）。

## 一、目标与不变式

### 不变式（设计的判据，任何改动不得违反）

| # | 不变式 |
|---|---|
| **I1** | **分类是第一维，源是第二维** —— 存放位置由知识性质决定，不由来源决定 |
| **I2** | **同一槽位可有多源 claim** —— 规范证据与观测证据是同一知识点的不同证据 |
| **I3** | **源只作 provenance，不作特例** —— 中枢没有「某源恒允许/恒禁止」的概念 |
| **I4** | **中枢是派生物** —— 可随时重建；原始语料在 `kb/`，不在中枢 |
| **I5** | **实体主键统一** —— 事实/关系/规则/图全部引用同一 `entity_id` |

### 语义定位（用户口径）

> 「中枢**针对目标协议的知识分类**进行存储；多个异构知识源抽出关于协议的知识，**存入对应的位置**。」

## 二、中枢的最终结构

```
derived/
├── hub/                          ← ★★ 结构化知识中枢（独立角色，本次的家）
│   └── <协议>/
│       ├── index/
│       │   ├── entities.jsonl    ← 实体主表（跨分类的唯一索引）
│       │   └── slots.json        ← 槽位填充统计（诊断用）
│       ├── A_structure/structure.jsonl        ← 有什么
│       ├── B_interaction/interaction.jsonl    ← 怎么连
│       ├── C_constraints/constraints.jsonl    ← 必须/不许怎样
│       ├── D_construction/construction.jsonl  ← 怎么写出来
│       ├── E_observation/observation.jsonl    ← 实际什么样
│       ├── F_security/security.jsonl          ← 哪里可能出错
│       ├── state_machines.json                ← 候选（各源并存，未消解）
│       ├── transition_quality_gate.json       ← 抽取闸的统计（审计）
│       └── sources.json                       ← 构建台账（见 §五）
│
├── per_source/<协议>/            ← ★ 回归本义：只放**各源的中间产物**
│   ├── rfc/facts/rfc.jsonl
│   ├── rfc/semantic/rules.jsonl
│   ├── traffic/facts/…
│   ├── expert_note/facts/…
│   ├── profile/facts/…            ← 骨架源（阶段 6 消解后删除）
│   └── vuln/facts/…
│
├── protocol_kind/<协议>.json     ← 协议类型判定（独立角色）
├── seeds/<协议>/…                ← 种子
└── …（analysis / exp_* / spec / graph …）
```

★ `derived/` 从此**按角色分层**：中枢 / 各源中间产物 / 协议判定 / 种子 / 实验。

## 三、知识分类与槽位

| 分类 | 目录 | 回答什么 | 槽位 | 现有 aspect |
|---|---|---|---|---|
| **A 结构** | `A_structure/` | **有什么** | `methods` `headers` `statuses` `states` `timers` `roles` | `definition`(method/header/status) `existence` |
| **B 交互** | `B_interaction/` | **怎么连** | `transitions` `sequences` `instances` `relations` | `target_state` `method_sequence` `message_instance` `relation_to_other` |
| **C 约束** | `C_constraints/` | **必须/不许怎样** | `required_headers` `value_constraints` `preconditions` `session_semantics` `url_templates` `response_expectations` | `required_header_global` `required_header_by_method` `required_headers` `legal_boundary` `precondition` `session_header` `url_template` `response_expectation` |

      {"role": "target", "entity_id": "sip:state:registered"}
    ]
  },
  "condition": {"type": "always"},
  "claims": [
    {"claim_id": "c_8519af82",
     "owner": "rfc",
     "value": {"type": "text", "data": "Registered"},
     "epistemic": "normative",
     "evidence": [{"owner":"rfc","file":"rfc3261.txt","line":9019,"span":"..."}],
     "confidence": "high",
     "extracted_at": "2026-11-08T16:23:39Z"}
  ],
  "resolution": {"strategy":"consensus","decided":"2026-11-08T16:23:39Z",
                 "winners":{"value":"c_8519af82"},"reason":"only claim"}
}
```

**与现状的差异（4 处）**：

| 现状 | v2 | 作用 |
|---|---|---|
| `subject` 内嵌名字 + `qualifiers` 装关系 | `entity.entity_id` + `entity.participants[]` | 统一主键、关系结构化 |
| 无 `epistemic` 区分 | `epistemic`: normative/informative/observed/inferred | **「信息 vs 知识」的判据** |
| `resolution` 恒 null | **必填**（即使单 claim） | 裁决可审计 |
| `authority` 在 claim 内 | 同上 + `ledger` 逐类统计 | 纯度可自证 |

## 十、执行顺序总览

```
阶段 A（零风险）      A1 契约 → A2 校验器 → A3 实体主表 → A4 矩阵诊断
