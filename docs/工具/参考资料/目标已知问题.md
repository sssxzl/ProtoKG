## Issue 1：live555 SETUP 后第二个 SETUP 忙等

**发现时间**：2026-10-07（VM 侧测试期间）

### 现象

SETUP 建立 session 后，任何**第二个** SETUP 请求
使 target 进入**不可恢复忙等**（高 CPU、TCP 无响应），需 `kill -9` 重启。

### 触发条件

**任何第二个 SETUP**。

- 与 CSeq 取值**无关**
- 与 Authorization 是否存在**无关**（隔离测试已证明）
- 与是否同一 TCP 连接**无关**

### 影响

fuzzing 序列中若含双 SETUP ⟹ target 挂死，fuzz run 的有效时长被压缩。

本项目受影响的种子（`batch-hub-20261007_183308`）：

| 文件 | methods | 证据等级 |
|---|---|---|
| `23_Init→SETUP+SETUP.raw` | SETUP, SETUP | **有 VM 证据** |
| `23_Init→SETUP+SETUP[sec].raw` | SETUP, SETUP | **有 VM 证据** |

⟹ 已由 `scripts/seedgen_from_hub.py` 自动写入该批次的 `known_issues.txt`。

### ⚠ 同构但**未验证**的形态

下列种子的**结构**与上面相同（同一 method 连发两次），
但重复的 method 不是 SETUP，**VM 侧从未测试过** ⟹ **不断言**它们同样会挂死：

| 文件 | methods |
|---|---|
| `06_Init→DESCRIBE+DESCRIBE.raw` | DESCRIBE, DESCRIBE |
| `12_Init→OPTIONS+OPTIONS.raw` | OPTIONS, OPTIONS |
| `30_Init→TEARDOWN+TEARDOWN.raw` | TEARDOWN, TEARDOWN |
| `36_Init→REDIRECT+REDIRECT.raw` | REDIRECT, REDIRECT |

这些来自 state_machine 的 wildcard 边（`* --METHOD--> $current`），
BFS 枚举时自然产生。若 VM 侧补测这些形态，结论可上移。

### 来源

VM 侧测试报告：[来源：用户转述 VM 侧 agent，2026-10-07]
  `~/d62_precision_report.txt`
  `~/vm_test_report.txt`

⚠ Windows 端**无 VM 访问权限**，以上现象均为转述，未独立复核。

### 处理

**不阻塞 D62 通道。**

本项目侧处置：受影响种子在批次 `known_issues.txt` 中标记，
建议进 fuzzing 前剔除，或依赖 AFLNet timeout 兜底。

### 上游报告

**候选，未裁定。** 属 live555 自身缺陷，是否向上游提 issue 待定。
