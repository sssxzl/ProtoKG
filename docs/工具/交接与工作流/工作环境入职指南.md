## 四、硬约束（不可违反）

1. **`kb/` 默认只读**。任何写 `kb/` 必须先停、汇报、等授权
2. **失败即停**。任一步失败不继续、不自行修
3. **不自行假设**。契约未写、语义不明、两方案都合理 → 停
4. **每步写 audit**（`guard/audit/step_<N>/audit.txt`，四项固定内容）
5. **每步备份**到 `guard/backup/step_<N>/before/`
6. **pytest 一律 `pytest -n auto`**
7. **不改冻结文档**（`docs/设计/顶层设计/` 下六份 `fused_*`）
8. **源隔离**：调一源（rfc / expert_note / vuln / traffic / source）不动他源
9. **量具自证**：探针/核查脚本首次运行前先自证（路径归一化、类型归一化、已知答案样本）
10. **报告实测不引用历史数字**——除非是基线，且基线与实测在同一步对比

## 五、工作流（每次开工按序做）

1. 读本文件（`工具/交接与工作流/工作环境入职指南.md`）
2. 读 `docs/工具/验收与规范/agent长期工作约束.md`
3. 读 `docs/实施/路线与里程碑/全局/后续路线.md`——找到「当前步骤」
4. 读 `guard/backup/` 下最近一个 `step_*/audit.txt`——了解上次停在哪
5. 判断：
   - **可自决** → 执行（见 agent_rules「自主执行协议」章节）
   - **需裁定** → 停下，写清「待裁定项 + 选项 + 推荐 + 理由」，等用户
6. 执行 → 写 audit + 汇报（≤60 行）
7. 更新 `docs/实施/路线与里程碑/全局/后续路线.md`——勾销完成项，写入下一项

## 六、汇报格式（固定）

```
本步目标：一句话
动作汇总：每步 PASS / FAIL
关键数值：实测值（不引用历史）
未决项：待裁定 / 待观察
下一步建议：一句话
```

≤60 行；过长时写详细到 `guard/backup/step_<N>/detail.txt`，汇报只给摘要。
