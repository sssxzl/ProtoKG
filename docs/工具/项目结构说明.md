```

                            ↓

│  形态分类 rfc_forms · 内容判据 rfc_classifier · 协议类型 kinds/  │
└───────────────────────────┬───────────────────────────────────┘
                            ↓
┌─ ③ 中枢层 core/fused/ + scripts/build_hub.py ─────────────────┐

│  Phase A 确定性抽图 → 投影/分层/度量 → 社区检测 → 社区报告       │

                            ↓
┌─ ⑤ 消费层 core/fused/downstream/ + scripts/seedgen.py ────────┐
```

## 附录 · 中枢视图层（阶段 D1，2026-11-09）

### 为什么有这一层

改造前 `assemble_bundle` 住在**消费层**（`core/fused/downstream/rag_seedgen.py`），却是**事实上的中枢门面** ⇒ 出现了「物理上在消费层、概念上属中枢层」的错位，并导致 **GraphRAG 整理层反向依赖消费层**。

### 分层依赖（调整后，单向）

```
⑥ 护栏层
   ↓
⑤ 消费层 ────┐
             ├→ ③' 中枢视图层 → ③ 中枢层 → ② 抽取层 → ① 知识源层
④ GraphRAG ─┘
```

### 各层的职责与落盘

| 层 | 代码 | 职责 | 落盘 |
|---|---|---|---|
| ① 知识源层 | `kb/` | 规范/源码/流量/注记/漏洞 | 只读 |
| ② 抽取层 | `core/fused/rfc_extractor.py` 等 | 五源抽取 → fact | `derived/per_source/` |
| ③ 中枢层 | `core/fused/{models,canonical,knowledge_slots,hub_entities,hub_layout}.py` | 汇聚 → 落位 → 契约 | `derived/hub/` |
| **③' 中枢视图层** | **`core/fused/hub/hub_view.py`** | **读中枢 ⇒ 组装视图**（16 桶 + 分类视图 + 实体视图） | **不落盘**（内存） |
| ④ GraphRAG 整理层 | `core/fused/graph_*.py` | 投影 → 图 → 社区 → 检索 | `derived/graph/` |
| ⑤ 消费层 | `core/fused/downstream/` `scripts/seedgen.py` | 五层种子 → LLM → `.raw` | `derived/seeds/` |

★ **视图层不落盘**：它是运行时组装的（bundle 从来不落盘）⇒ 落盘等于把中枢复制一遍 ⇒ 引入「两份不一致」的风险。
★ 另有 `core/fused/state_graph.py`（中枢层）：「哪个状态是初始状态」是状态图通用性质 ⇒ 消费层与整理层共用 ⇒ 避免倒置。
